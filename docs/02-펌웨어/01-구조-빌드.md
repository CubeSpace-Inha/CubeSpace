# 펌웨어 구조와 빌드

이 문서로 답하는 것: 무엇으로 빌드하고(코어·재빌드·FQBN·금지 API·변형 플래그), 소스를 어떻게 나누나(순수 로직과 하드웨어 층).

관련: [02-큐브](02-큐브.md) · [03-패드-프레임-광학](03-패드-프레임-광학.md) · [04-패드-BLE-USB-LED](04-패드-BLE-USB-LED.md) · [05-선개발-시험](05-선개발-시험.md) · [BLE 규격](../03-인터페이스/01-BLE.md) · [USB 규격](../03-인터페이스/02-USB.md) · [시험 벡터](../03-인터페이스/04-시험-벡터.md)

## 1. 빌드 환경

### 1.1 코어와 재빌드 라이브러리 [권장안 U-06]

| 항목 | 값 |
|---|---|
| 코어 | Arduino-ESP32 **3.3.12 고정**(ESP-IDF v5.5.5 기반). 보드 매니저 업데이트 금지 |
| 빌드 도구 | arduino-cli(1.6). PlatformIO(pioarduino)로 바꿀지 [미정 F8] |
| 라이브러리 | `<Arduino15>/packages/esp32/tools/esp32s3-libs/3.3.12/`을 재빌드본으로 바꿔 끼운다(`<Arduino15>` = Windows `%LOCALAPPDATA%\Arduino15`, macOS `~/Library/Arduino15`, Linux `~/.arduino15`). 큐브·패드가 같은 폴더를 쓴다. 팀은 같은 zip 하나를 쓴다 |
| 재빌드 네 값 | `CONFIG_BT_NIMBLE_MAX_CONNECTIONS=6`, `CONFIG_BT_CTRL_BLE_MAX_ACT=7`, `CONFIG_BT_NIMBLE_ENABLE_CONN_REATTEMPT=n`, `CONFIG_GPTIMER_CTRL_FUNC_IN_IRAM=y`. 필요하면 `CONFIG_RMT_TX_ISR_CACHE_SAFE=y`를 더한다(v5.5에서 `RMT_ISR_IRAM_SAFE`는 폐기 표시) |
| 재빌드 고정값 | espressif/esp32-arduino-lib-builder 커밋 `6671d0b`, `-t esp32s3 -i b774170ff46`(ESP-IDF v5.5.5 커밋), arduino 컴포넌트 = espressif/arduino-esp32 커밋 `e7c1e8cd4`(수동 체크아웃 + `-s`), `-e`, 툴체인 esp-x32 2601. lib-builder는 macOS·Linux(Windows는 Docker 또는 WSL2). 결과 zip은 호스트 OS와 상관없으니 한 번 만들어 팀 공유 폴더로 나눈다 |
| 예비안 | X1-V0가 1일 안에 안 되면 ESP-IDF v5.5.5 + arduino-esp32 3.3.12 컴포넌트. `sdkconfig.defaults`에 네 값 + `CONFIG_FREERTOS_HZ=1000`. 스케치는 `main/`으로 옮기기만 한다. 순수 ESP-IDF로 옮기지 않는다 |
| 왜 재빌드 | 사전 빌드는 연결 3·제어기 활동 6이라 스케치로 바꿀 수 없다. 패드는 링크 6 + 스캔 1 = 활동 7이 필요하다 |

### 1.2 빌드 검사 헤더

- `x1_build_check.h`(`#ifdef ESP_PLATFORM`로 감쌈, 스케치만 include):
  - `#include "esp32-hal-alloc-ble-mem.h"`. 이 헤더의 생성자가 `_bleLibraryInUse = true`를 세워 `initArduino()`가 BLE 제어기 메모리를 풀지 않게 한다. NimBLE C API만 쓰면 스스로 넣어야 한다.
  - 순정 라이브러리면 컴파일을 멈춘다:

```c
#if CONFIG_BT_NIMBLE_MAX_CONNECTIONS < 6 || CONFIG_BT_CTRL_BLE_MAX_ACT < 7 \
    || defined(CONFIG_BT_NIMBLE_ENABLE_CONN_REATTEMPT) || !defined(CONFIG_GPTIMER_CTRL_FUNC_IN_IRAM)
#error "CUBE SPACE: esp32s3-libs가 재빌드본이 아니다 (X1-V0)"
#endif
```

- `x1_proto.h`와 다른 순수 헤더는 이 헤더를 include하지 않는다(PC g++에서 컴파일).

### 1.3 FQBN

| 대상 | FQBN | 비고 |
|---|---|---|
| 패드(ESP32-S3-Zero) | `esp32:esp32:waveshare_esp32_s3_zero:USBMode=hwcdc,CDCOnBoot=default,DebugLevel=none` | 이 보드에서 `CDCOnBoot=default`가 Enabled, `cdc`는 Disabled다. `proto.h`의 `#error`가 최종 판정 |
| 큐브(ESP32-S3-Matrix) | `esp32:esp32:esp32s3:CDCOnBoot=cdc` | 일반 esp32s3에서는 `cdc`가 Enabled. Serial은 배터리 없는 예비 A1의 시험 빌드에서만 쓴다 |

### 1.4 로그 끄기

- `esp_log_level_set("*", ESP_LOG_NONE)`를 `nimble_port_init()`보다 먼저 부른다. 패드는 `usbInit` 직후, 큐브는 `setup()` 첫머리.
- 이 설정은 실행 중 ERROR 로그만 막는다. ROM 부팅 로그와 패닉 출력은 나간다. PC 게이트웨이가 SLIP 재동기로 버린다([USB 1](../03-인터페이스/02-USB.md)).

### 1.5 금지 API·규칙

| 금지 | 대신 | 쪽 |
|---|---|---|
| Arduino `BLEDevice`·`BLEServer`·`BLEClient`·`BLEScan` | NimBLE C API(`nimble_port_init`, `ble_gap_*`, `ble_gattc_*`, `ble_gatts_notify_custom`) | 양쪽 |
| `ESP_LOG*`, `Serial.print*`, `printf` | 없음(시험 빌드의 예비 A1만 예외) | 양쪽 |
| `analogSetPinAttenuation` | 첫 읽기 전 전역 `analogSetAttenuation(ADC_6db)`. 0 mV는 측정 실패 | 양쪽 |
| Adafruit_NeoPixel, GPIO21 `rgbLedWrite`·`neopixelWrite` | `rmtInit` + `rmtWrite`/`rmtWriteAsync` | 양쪽 |
| `HWCDCSerial.onEvent()`, `Serial.flush()`, print 계열 | `availableForWrite()` 검사 뒤 `write(buf, len)` 한 번 | 패드 |
| 프레임 루프에서 NimBLE 함수 직접 호출 | `cmdQ`로 `bleCtl`에 넘김 | 패드 |
| Arduino Wi-Fi·Network·BLE 라이브러리 링크, 코어 1에 다른 태스크 고정 | 없음 | 패드 |
| `gpio_hold`(부팅 때 `gpio_hold_dis(6)` 한 줄만 둠) | 리셋 원인 판정 | 큐브 |
| loop 안 `delay()` > 1 ms, `setup()` 안 긴 대기 | loop 1 ms 상태기계 | 큐브 |
| IR 에지에 `esp_timer` 콜백·`digitalWrite` | GPTimer ISR + 레지스터 쓰기 | 큐브 |
| SYNC를 FreeRTOS 틱·프레임 배수 시각에 맞춰 보내기, `ble_npl_callout` | `esp_timer` one-shot 난수 간격 | 패드 |
| 송신 출력 21 dBm | 큐브 ≤ +9 dBm 명시 설정, 패드 기본 +9(손잡이 +15) | 양쪽 |
| BLE OTA, 본딩 | USB 갱신만 [권장안 U-74] | 양쪽 |

### 1.6 컴파일 명령과 빌드 변형

```
arduino-cli compile --fqbn <1.3 FQBN> --libraries firmware/libraries \
  [--build-property "compiler.cpp.extra_flags=-DCS_FW=0x<git 앞 8자리> -D<변형 플래그>"] \
  firmware/<cube_fw|pad_fw>
make -C firmware/host_test        # 순수 로직 PC 시험(g++)
```

- Windows: PowerShell·cmd는 `\` 줄 이음을 모르니 `arduino-cli compile`을 한 줄로 친다. `make`는 MSYS2 UCRT64 셸 또는 WSL2에서([05-선개발 1.1](05-선개발-시험.md)). 저장소와 Arduino 데이터 폴더는 짧은 ASCII 경로에 둔다(예: `C:\dev\CubeSpace`, `arduino-cli config set directories.data C:\a15`). 긴 사용자 폴더 경로·한글 사용자 이름에서 툴체인 경로 한도 초과와 매번 다시 컴파일이 보고됐다.
- 패드 HELLO `fw`는 `CS_FW`(펌웨어를 빌드한 CubeSpace 커밋 앞 8자리)다. PC 커밋은 측정 기록에 따로 남는다([PC 내부 1](../03-인터페이스/03-PC-내부.md)). 큐브 HELLO 판은 `FW_MAJOR`·`FW_MINOR` 상수다. 형식은 [BLE 3](../03-인터페이스/01-BLE.md)·[USB 3](../03-인터페이스/02-USB.md).
- 시험 펌웨어는 새 스케치를 만들지 않고 본 펌웨어 + 플래그로 만든다.

| 빌드 | 플래그 | 하는 일 | 쓰는 시험 |
|---|---|---|---|
| cube_fw 본 | 없음 | 전부 | X1-B·X1-D, C 시험 |
| cube_fw 전원판 | `CS_PWR` + `#define` 셋(프로파일 P0~P4, V_OFF·V_BOOT_MIN 끄기, 지연 D) | 전원 기능, BLE 최소 서버(광고·CFG 저장·EVT BATT·BYE), 명령 쓰기 특성(이 판만), 자체 IR 점멸. 선택 `CS_TEST_MODE=1/2`(BLE 불필요) | C1·C2·C7·C9, 1호기 CT-4·CT-5 |
| cube_fw 시험 | `CS_TEST`, `CS_TEST_MODE=0/1/2` | 0: 누름 횟수 명령 + RAW_S1. 1: IR 1 s 켬/1 s 끔. 2: S1 확정마다 GPIO1 토글. 1·2는 IR 다섯 조건·무연결 꺼짐 끔(버튼 끄기는 그대로). HELLO 판 bit15 = 1 | X3-L, X1-D ④, C5, C12, CT-4·CT-5(2~6호기) |
| pad_fw 본 | 없음 | 전부 | G2~ |
| pad_fw X1J | `CS_TEST_X1J`, `CS_EDGE_MAP=X1J/CT5` | X1J: 에지마다 `err = 에지 − 계획 시각`을 10 µs 칸 막대그래프(±5 ms)에 쌓고, 10 s마다 LOG(수준 3)로 n·중앙값·p99.9·최대\|err\|·예열 시간·예열 직후 30 s 최대\|err\|. CT5: 핀마다 20 ms 넘게 안정된 뒤 첫 에지 시각을 LOG(수준 3, 핀·패드 시각 µs) | X1-J, CT-5 |
| pad_fw RSSI | `CS_TEST_RSSI`(선택 `CS_HANG_S=<s>`) | 링크별 RSSI(`ble_gap_conn_rssi()`) LOG 10 s, `bleCtl` 멈춤 | X1-B, F05-3, F05-6 |
| pad_fw T9 | `CS_TEST_T9`, `CS_LED_MODE=0/1/2` | PC 없이 체크무늬 1 s마다, LED 구동 A/B/C, BLE 대리 부하 | T9 |
| pad_fw 가짜 관측 | `CS_TEST_FAKEOBS`(대리 부하 켬/끔 상수) | 가짜 OBS | X2-U0~U4·U6 |

- 광학 CSV 시험 스케치 `pad_test`(BLE·이진 USB 없음)는 본 펌웨어와 따로 둔다. 사양은 [하드웨어 02](../01-하드웨어/02-패드.md) 10.3절.

## 2. 소스 구조

### 2.1 나누는 원칙

- **순수 로직**: 시각과 입력을 인자로 받는다. Arduino·NimBLE·레지스터를 부르지 않는다. PC g++와 Arduino 둘 다에서 컴파일된다. `firmware/libraries/CubeSpaceProto/`에 둔다.
- **하드웨어 층**: GPIO·ADC·먹스, RMT(LED·8×8), GPTimer ISR, NimBLE, HWCDC, NVS, 워치독. 얇게 두고 순수 로직을 부르기만 한다. 스케치 폴더에 둔다.
- 하드웨어가 와서 바뀌는 값은 상수 한 곳(`x1_proto.h` 상수표, `optics.h`, 빌드 플래그)에 모은다([05-선개발-시험 2](05-선개발-시험.md)).

### 2.2 파일

`firmware/`는 CubeSpace 저장소의 펌웨어 폴더다. 공용 시험 벡터는 `packages/protocol/vectors/`에 있다([아키텍처 8](../00-공통/01-아키텍처.md)).

```
firmware/
  libraries/CubeSpaceProto/          Arduino 라이브러리. 소스는 src/ 아래(아래 목록은 src/ 기준)
    x1_proto.h        UUID·구조체(CFG 20 B, EVT 14 B)·상수표. 순수(x1 = 큐브↔패드 BLE 규격)
    x1_build_check.h  ESP 전용(1.2). 스케치만 include
    proto.h/.cpp      USB 머리·메시지 부호화·해독, SLIP, CRC-32. 순수
    est.h             동기 추정기(정수 누설 나머지 누적). 순수
    frame.h           프레임 주기 P 공식, 슬롯 시각, IR 다음 에지 k. 순수
    tpad.h            t_pad32 만들기·복원. 순수
    cube_logic.h/.cpp 입력 확정, 버튼 분류, 전원 상태기계, EVT 대기열. 순수
    pad_link.h/.cpp   링크 상태기계, 설정 순서, 끊김 사유, 실패 무시. 순수
    optics.h          판정 상수(보정 도구가 생성, 손으로 안 고침)
    optics.cpp        배경 차분·발견·소실·창 위치·SAT·sync_fault·bad_map. 순수
    pad_pump.h/.cpp   펌프 순서, 보낼 자리 검사, 스냅샷, tx_drop. 순수
    led_map.h/.cpp    논리→물리 LED 순서, I_est 감광, 대기 패턴. 순수
  cube_fw/
    cube_fw.ino       initVariant·setup·loop(1 ms 상태기계)
    power.cpp/.h      ADC·전원 핀·딥슬립(cube_logic 호출)
    ble_periph.cpp/.h GATT 서버, 광고, CFG 대기, notify
    ir_sync.cpp/.h    SYNC 콜백 → est, GPTimer ISR
    display.cpp/.h    표시 합성, ledShow()(제한기, RMT 4블록)
  pad_fw/
    pad_fw.ino        initVariant(GPIO40 LOW)·setup·프레임 루프
    ble_central.cpp/.h bleCtl, GATT 쓰기 대기열, SYNC 타이머(pad_link 호출)
    scan.cpp/.h       먹스·ADC 읽기(optics 호출)
    led_out.cpp/.h    RMT A/B/C, LED 전원 상태기계(led_map 호출)
    usb_link.cpp/.h   HWCDC 초기화·읽기·쓰기(proto·pad_pump 호출)
  host_test/
    Makefile          g++ -I ../libraries/CubeSpaceProto, test_* 실행. 벡터는 ../../packages/protocol/vectors/proto_vectors.hex를 그대로 읽는다
    test_*.cpp        모듈마다 assert 실행 파일 1개. 시험 틀 없음
    sim_cube.cpp      가상 큐브 → EVT 열
    sim_pad.cpp       가상 패드 → USB SLIP 바이트 열(L0 파일)
```

### 2.3 모듈 표

| 모듈 | 종류 | 내용 | PC 시험 |
|---|---|---|---|
| `x1_proto.h`·`proto` | 순수 | CFG·EVT 구조체, USB 머리·메시지, SLIP, CRC-32 | 시험 벡터를 PC와 같이 씀 |
| `est.h` | 순수 | 동기 추정기 | 실수 모형과 대조 |
| `frame.h` | 순수 | 프레임 구간, 슬롯 시각, 다음 켜짐 k, 20 µs 미만 건너뜀 | 네 경우 |
| `tpad.h` | 순수 | 사건 시각 → `t_pad32`, 대칭 복원 | 음수 나이 |
| `cube_logic` | 순수 | 입력 확정, 버튼 분류, 전원 상태(켜기 하한·저전압·도크·자동 꺼짐·USB 호스트), EVT 대기열·순서 | 시나리오 표 |
| `pad_link` | 순수 | 링크 상태기계, 설정 순서, 끊김 사유, 3번 실패 → 10 s 무시, 옛 링크 0x11 | 가짜 BLE 사건 |
| `optics` | 순수 | 배경 차분, TH_ON·TH_OFF, 발견 청크 순서, 창 밀기, SAT, sync_fault, `bad_map` | 합성 센서 값 |
| `pad_pump` | 순수 | 펌프 순서, 보낼 자리(+512), 스냅샷, `tx_drop` | 바이트 열 |
| `led_map` | 순수 | 논리 → 물리 순서, `I_est`·감광, 대기 패턴 | 384행 대응표와 대조 |
| 하드웨어 층 | 하드웨어 | GPIO·ADC·RMT·GPTimer·NimBLE·HWCDC·NVS·워치독 | 컴파일만 |

- 순수 모듈 하나가 하는 일은 "입력(시각, 사건, 원시값) → 출력(새 상태, 보낼 것)"이다. 하드웨어 층이 실제 시각(`esp_timer_get_time()`)과 실제 입력을 넣는다.
