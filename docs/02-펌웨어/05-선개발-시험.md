# 하드웨어 전 선개발과 펌웨어 시험

이 문서로 답하는 것: 하드웨어 없이 무엇을 어떻게 만들고 확인하나, 하드웨어가 오면 어떤 값만 바꾸나, 펌웨어 시험의 합격 기준은 무엇이고 어떤 순서로 일하나.

## 1. 하드웨어 없이 개발

### 1.1 순수 모듈 시험 (`make -C firmware/host_test`)

- Windows는 MSYS2 UCRT64 셸(`pacman -S make mingw-w64-ucrt-x86_64-gcc`) 또는 WSL2 Ubuntu(`sudo apt install build-essential`)에서 실행한다. Makefile은 `$(CXX)`(g++)를 쓴다.

- 모듈마다 assert 실행 파일 하나. 시험 틀(프레임워크)은 넣지 않는다.

| 모듈 | 시험 항목 |
|---|---|
| `x1_proto.h`·`proto` | 구조체 CFG 20 B·EVT 14 B, 리틀 엔디언 바이트열, USB 메시지 부호화·해독, SLIP, CRC-32를 [시험 벡터](../03-인터페이스/04-시험-벡터.md)와 대조(PC Vitest와 같은 파일) |
| `est.h` | 정수 누설 나머지 누적이 실수 모형과 차 ≤ 1 µs(시계 차 ±20·±35 ppm, 예열 간격 5~15 ms) |
| `frame.h` | 기본값 → P 50 ms·슬롯 시각 표와 같음, 조건별 P(58.33·66.67·75·91.67), IR 다음 k 네 경우: 패드 시각 역행(재부팅), 전진, `est` 급변, slot 변경·`frame_us = 0`. 남은 시간 < 20 µs면 다음 k |
| `tpad.h` | `t_pad32` 만들기, 대칭 복원 음수 나이(−1·−1500 µs)·±2³¹ 부근 오차 0 |
| `cube_logic` | 시나리오 표 → 기대 EVT 열: 짧게(0.3·0.9 s)·길게(1.1 s, 끄기 시간 직전)·끄기·켜기 누름 무시·고착 10 s·도크·저전압(V_BOOT_MIN·V_OFF)·무연결 5분·S1 열림 5분·USB 호스트 중 안 꺼짐. EVT 대기열: 실패 → 재시도 → 성공 때만 `seq` +1, 스냅샷 순서, BTN 2칸 |
| `pad_link` | 가짜 BLE 사건 열 → 기대 LINK 열: 설정 실패 3번 → 10 s 무시, 옛 링크 0x11, BYE 즉시 `up=0`, 늦은 사건(다른 conn_handle) 버림, ENOMEM 재시도, 0x3E |
| `optics` | 합성 프레임: 발견 확정(CONTACT 에지 1프레임, 없으면 2프레임), 손 그림자 1프레임 거짓 발견 0, 소실 2프레임, OFF_PAD 12프레임, 창 밀기(네 모서리), SAT, sync_fault 3프레임과 배경 계단에서 0, `bad_map` 두 규칙 |
| `pad_pump` | 펌프 순서, 자리 모자라면 버림·`tx_drop`, OBS·LOG 512 B 예약, 스냅샷 순서 |
| `led_map` | 논리 → 물리 384행 대응표, 흰색 전체에서 `I_est` ≤ 4.0 A + 감광, `led_scale`, 대기 패턴 동적 ≤ 0.3 A |
| 큐브 제한기 | 전부 흰색 255 → `I_est` ≤ 40 mA + 0.5 mA |

### 1.2 가상 큐브·가상 패드 → L0 바이트 열

- **가상 큐브**(`sim_cube`): `cube_logic`에 시나리오(놓기·들기·버튼 짧게/길게/끄기·도크·전압 하강)를 시간순으로 넣으면 EVT 14 B 열이 나온다.
- **가상 패드**(`sim_pad`): 가상 큐브의 EVT와, 큐브 위치로 만든 합성 센서 값(빛 모형·정상 가정은 [시험 벡터](../03-인터페이스/04-시험-벡터.md) 가상 광학)을 받아 `optics`·`pad_link`·`pad_pump`를 돌린다. 출력은 USB SLIP 바이트 열 파일이다.
- 이 파일을 PC 재생의 L0(선로) 입력에 그대로 넣으면 PC `gateway`(`apps/pad-gateway`)부터 상태기계·묶기 규칙까지 한 번에 돈다. PC `--source=sim`과 달리 펌웨어 경로까지 시험한다.
- 합성 빛 모형 결과는 합격 근거가 아니다. 문턱값은 하드웨어 보정 뒤 다시 정한다.

### 1.3 맨 보드 단계 (보드만 있고 조립 전)

| 할 일 | 필요한 것 | 확인 |
|---|---|---|
| X1-V0 컴파일 | 재빌드 라이브러리 | 순정본 `#error`, 컴파일 성공 |
| BLE 링크·SYNC·CFG·EVT | A1 1~2 + Zero 1 | LINK `up=1`, HELLO·CONTACT·BTN(점퍼 선·택트 스위치)이 PC까지 |
| ICON → 8×8 | A1 내장 8×8 | `?`·✕·앱 아이콘이 보임 |
| USB → PC gateway | Zero + `CS_TEST_FAKEOBS` | 가짜 OBS로 PC 좌표·묶기 흐름 동작 |

- A1의 S1·버튼·도크는 점퍼 선이나 택트 스위치로 흉내 낸다.

## 3. 펌웨어 시험 (합격 기준)

- 시험 이름: C n = 큐브 시험 CT-n, T n = 패드 시험 PT-n([제작 시험](../01-하드웨어/05-제작-시험-실측값.md)). 이 표의 C5·C9·C12·T9는 펌웨어 쪽 확인이다. X1-*·X2-*·F05-*는 이 표가 정한다. 광학 측정(PT-*)·GAIN-CAL은 [06-광학-보정](06-광학-보정.md).

| 9 | 하드웨어 층 + 모든 빌드 변형 컴파일 | F05-5 | 재빌드 라이브러리 [권장안 U-06] |
| 10 | 맨 보드 | 1.3 표 | A1·Zero |
| 11 | 조립 뒤 시험 | 3절 순서: X1-V0 연결·T9·X2-U2(W7) → X1-J ①·X1-O·X1-B(W8) → X1-J ②③·F05-6·F05-3 1차(W9) → X1-D(W10~11) | 조립 큐브·패드 |

- 1~8은 하드웨어가 필요 없다. 9는 툴체인만, 10부터 보드가 필요하다.
