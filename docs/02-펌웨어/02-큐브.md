# 큐브 펌웨어 (cube_fw, ESP32-S3-Matrix)

이 문서로 답하는 것: 큐브는 무엇을 읽어 언제 IR을 켜고, 어떤 EVT를 언제 보내고, 버튼·전원·표시를 어떻게 처리하나.

관련: [01-구조-빌드](01-구조-빌드.md) · [05-선개발-시험](05-선개발-시험.md) · [BLE 규격](../03-인터페이스/01-BLE.md) · [큐브 하드웨어](../01-하드웨어/01-큐브.md)

큐브는 판정하지 않는다. 입력을 확정해 사건으로 보내고, 받은 아이콘을 그리고, 받은 시각에 맞춰 IR을 켠다.

## 1. 핀 표

| 신호 | GPIO | 방향 | 논리 | 확정·읽기 |
|---|---|---|---|---|
| IR_GATE | 1 | 출력 | HIGH = IR 켬(약 40 mA) | ISR이 레지스터로 씀. 부팅 첫 줄에서 LOW |
| CONTACT_N(S1) | 2 | 입력(외부 10 kΩ 풀업) | LOW = 놓임 | 5 ms 같은 값이면 확정 |
| VBAT_ADC | 4 | ADC1_CH3 | 1/3 분압(200 k/100 k) | 100 ms마다 `analogReadMilliVolts` 16회 평균 × 3 |
| DOCK_N | 5 | 입력(외부 10 kΩ 풀업) | LOW = 도크 위 | 50 ms 확정 |
| PWR_HOLD | 6 | 출력 | HIGH = 전원 유지, LOW = 해제 | 리셋 원인 판정 뒤 씀 |
| BTN_N(SW2) | 7 | 입력(내부 풀업) | LOW = 눌림 | 30 ms 확정, 고착 10 s |
| MATRIX_DATA | 14 | 출력(내장 8×8) | WS2812 | RMT 4블록 [실측 필요: 실물 실크 대조] |
| IMU SDA/SCL | 11/12 | 내장 | | 초기화하지 않음 [권장안 U-57] |

- GPIO3·부팅 설정 핀은 쓰지 않는다. 핀·회로의 정본은 [큐브 하드웨어](../01-하드웨어/01-큐브.md)다.

## 2. 실행 분담

태스크를 새로 만들지 않는다.

| 흐름 | 코어 | 주기·계기 | 하는 일 | 공유 |
|---|---|---|---|---|
| loop | 1 | 1 ms(`delay(1)`) | S1·BTN·DOCK 확정, EVT 보내기, `rearm`이면 IR 알람 걸기, 시간 상태기계(켜기 하한 1 s, 도크 막대, 끄기 순서, 해제 뒤 생존) | IR 허용 플래그(원자적) |
| loop | 1 | 100 ms | ADC 16회 평균 → 1 s 평균·10 s 이동 평균, `usb_serial_jtag_is_connected()` | |
| loop | 1 | 10 s | BATT EVT(링크·CFG 있을 때) | |
| loop | 1 | 사건 | HELLO 스냅샷, SYNC 상태 EVT, BYE, 자동 꺼짐 타이머, 표시 합성 → `ledShow()` | ICON 버퍼(호스트가 쓰고 플래그) |
| GPTimer ISR | 1 | IR 에지 | 다섯 조건 확인, GPIO1 쓰기, 다음 에지 알람 | `est`·`last_sync`·`n`·CFG(`portMUX` 스핀락 하나) |
| NimBLE 호스트 | 0 | BLE 사건 | SYNC(추정기 직접 갱신), CFG(검사·저장·예열 규칙·`rearm`), ICON(복사), CONNECT·DISCONNECT(광고), CFG 대기 5 s | 위와 같음 |
| BT 제어기 | 0 | | 손대지 않음 | |

- 호스트 콜백은 값을 저장하고 플래그만 세운다. 예외는 SYNC 콜백(추정기)뿐이다.
- EVT notify와 `seq` 증가는 loop 한 곳에서만 한다.
- CPU 80 MHz(`setCpuFrequencyMhz(80)`). BLE가 불안정하면 160 MHz.
- 송신 출력은 +9 dBm 이하로 명시 설정한다(`esp_ble_tx_power_set(ESP_BLE_PWR_TYPE_DEFAULT, ESP_PWR_LVL_P9)`).

## 3. 부팅 순서

| # | 할 일 |
|---:|---|
| 1 | `initVariant()` 첫 줄: `esp_reset_reason()`. POWERON·EXT·USB면 GPIO6 출력 HIGH. 그 밖(SW·PANIC·WDT·BROWNOUT·DEEPSLEEP 등)이면 GPIO6 출력 LOW, `boot_abnormal`. 원인과 관계없이 GPIO1 출력 LOW. 이어서 `gpio_hold_dis(GPIO_NUM_6)` |
| 2 | `setup()`: 로그 끄기, `setCpuFrequencyMhz(80)` |
| 3 | 핀: GPIO2·5 입력, GPIO7 입력 풀업, 전역 `analogSetAttenuation(ADC_6db)`. 8×8 `rmtInit(14, RMT_TX_MODE, RMT_MEM_NUM_BLOCKS_4, 10000000)`, 전부 끔 |
| 4 | `boot_abnormal`이면 5~8을 건너뛴다(BLE 없음). loop가 해제 뒤 생존 처리 |
| 5 | BTN_N이 LOW면 "뗄 때까지 무시"를 세운다 |
| 6 | DOCK_N 50 ms 확인(`setup()`의 유일한 대기). LOW면 `dock_boot`, 8을 건너뛴다 |
| 7 | `timerBegin(1000000)`, ISR 연결(코어 1). 알람은 걸지 않는다 |
| 8 | `nimble_port_init()`, GATT 서비스 등록, 호스트 시작. 호스트 동기 뒤 `cube_boot_id = esp_random()`(0이면 다시), 광고 시작 |
| 9 | `enableLoopWDT()`: `setup()` 마지막 줄(작업 워치독은 loop 반복에서만 먹으므로) |
| 10 | loop가 이어받음: 켜기 하한 1 s(LED 끔, 광고와 병행). `dock_boot`면 잔량 막대 3 s → 끄기. V_BOOT_MIN 미만이면 (연결돼 있으면 BYE 3) → 맨 아래 줄 빨강 1 s → 끄기. 이상이면 기본 아이콘 |

- CPU 리셋(패닉·워치독·`esp_restart()`)은 GPIO 출력을 되돌리지 않는다. 그래서 1번에서 비정상 리셋 = 꺼짐으로 처리하고, 발광 중 패닉이어도 IR을 끈다.
- 도크 부팅은 BLE를 켜지 않는다. DOCK_N 검사 전에 `nimble_port_init()`을 부르지 않는다.

## 4. 입력 확정과 내부 값

| 입력 | 규칙 | 내부 값 | 쓰는 곳 |
|---|---|---|---|
| S1 | 5 ms 같은 값 | `contact`, `n_close`(부팅 뒤 열림→닫힘 확정 수, u16 순환. 부팅 때 이미 닫힌 것은 안 셈), 확정 시각 | CONTACT EVT, IR 조건 |
| BTN | 30 ms 같은 값 | 확정 누름 시각, 누른 시간 | BTN EVT, 끄기, 고착 |
| DOCK_N | 50 ms 연속 LOW | `docked` | BYE 1 |
| 배터리 | 100 ms 16회 평균, 1 s 평균, 10 s 이동 평균. 보정 없음 | `v_1s`, `v_10s`(mV) | BATT, 저전압, 표시 |
| USB 호스트 | `usb_serial_jtag_is_connected()`(SOF 수신 판정, 전원 뱅크는 연결 아님) | `usb_host` | 자동 꺼짐 멈춤 |

- S1 열림이 확정되면 loop가 IR 허용 플래그를 먼저 내리고 곧바로 GPIO1을 LOW로 쓴다(같은 코어라 이 순서면 경합 없음).

## 5. IR 발광과 동기

### 5.1 추정기 (`est.h`, SYNC 콜백 첫 줄)

```c
int64_t now = esp_timer_get_time();           // 콜백 첫 줄
int64_t obs = now - pad_us;
if (n == 0) { est = obs; acc = 0; }
else {
  acc += (now - last) * LEAK_PPM;              // LEAK_PPM = 40
  int64_t q = acc / 1000000; acc -= q * 1000000;
  est = min(est + q, obs);
}
last = now; n++;
// 패드 시각 T → 큐브 로컬 = T + est - bias_us
```

- 누설을 그냥 int64 나눗셈으로 버리면 간격 25 ms 미만에서 0이 되어 실효 누설이 약 25 ppm이 된다. 나머지를 누적한다.
- `n`이 `WARM_N`(300)에 닿으면 동기 유효. SYNC EVT(유효)를 보낸다. SYNC 본문 길이 검사는 [BLE 2](../03-인터페이스/01-BLE.md).

### 5.2 CFG를 받을 때 (예열 규칙)

| 경우 | `n` |
|---|---|
| 새 연결의 첫 CFG, `pad_boot_id`가 저장값과 같고 마지막 SYNC가 `REJOIN_KEEP_MS`(5000) 안 | 유지(첫 SYNC부터 유효) |
| 새 연결의 첫 CFG, 그 밖 | 0 |
| 같은 연결의 두 번째 이후 CFG(sync_fault 재기록, 값 변경) | 늘 0, SYNC EVT(무효) 보냄 |

- CFG 값 검사·거부는 [BLE 2](../03-인터페이스/01-BLE.md). 받으면 저장하고 `rearm`을 세운다. 응답 뒤 HELLO 스냅샷(6절).
- 링크가 끊겨도 `est`를 버리지 않는다.

### 5.3 GPTimer ISR (코어 1)

- `rearm`이면 loop가 다음 틱에 스핀락 안에서 알람을 지금 + 100 µs로 건다(첫 CFG, 재기록, 새 `pad_boot_id` 모두 같다).
- 에지마다 k를 새로 계산한다(직전 k + 1 금지):

```
T_now = esp_timer_get_time() - est + bias_us          // 지금의 패드 시각
k     = floor((T_now - on_offset_us) / frame_us) + 1
T_on  = k * frame_us + on_offset_us ;  T_off = T_on + on_len_us
L     = T + est - bias_us                              // 로컬 목표
timerAlarm(t, timerRead(t) + (L - esp_timer_get_time()), false, 0)
```

- 남은 시간이 20 µs보다 작거나 음수면 그 켜짐을 건너뛰고 다음 k를 건다. 꺼짐 에지가 늦으면 곧바로 끈다.
- `frame_us == 0`이거나 `n < WARM_N`이면 켜지 않고 100 ms 검사 알람만 건다.
- 켜짐 에지에서 다섯 조건을 다시 본다. 하나라도 거짓이면 켜지 않는다.
- 출력은 `GPIO.out_w1ts = BIT(1)` / `GPIO.out_w1tc = BIT(1)`.

### 5.4 켜는 조건 (모두 참일 때만, 자기 슬롯 구간에서)

| # | 조건 |
|---:|---|
| 1 | 링크 연결 |
| 2 | CFG 받음 |
| 3 | `n ≥ WARM_N` |
| 4 | S1 닫힘(5 ms 확정) |
| 5 | `now − last_sync ≤ SYNC_STALE_MS`(1000) |

- 하나라도 깨지면 다음 에지를 기다리지 않고 끈다. 들린 큐브는 빛을 내지 않는다.
- 슬롯·구간은 CFG 값: `frame_us` 50000, `on_offset_us` = 14460 + 5460·slot, `on_len_us` 5460(패드가 정함, [03-패드-프레임-광학 4](03-패드-프레임-광학.md)).
- 손잡이: X1-J에서 예열 직후 30 s 최대 |err| > 0.975 ms면 `WARM_N` 400. 시계 차 |δ| > 20 ppm이면 `REJOIN_KEEP_MS` 2000.

## 6. EVT 보내기

- 종류·필드는 [BLE 3](../03-인터페이스/01-BLE.md), 순번·`t_pad32`·보내기 규칙의 정본은 [BLE 4](../03-인터페이스/01-BLE.md)다. 구현은 이렇다.
- 종류마다 미전송 칸을 둔다. 새 사건은 같은 종류의 미전송분을 덮어쓴다. **BTN만 2칸**(눌림 시작이 뗌에 덮이지 않게).
- loop가 1 ms마다 HELLO → RAW_S1 → CONTACT → BTN → SYNC → BATT → BYE 순으로 `ble_gatts_notify_custom`을 부른다. 하나가 실패하면 그 틱에서 멈춘다(스냅샷 순서 유지).
- `seq`는 notify가 0을 돌려줄 때만 +1. 구독(CCCD) 전에는 보내지 않는다.
- `t_pad32`는 사건 시각을 `tpad.h`로 바꾼다. 동기 무효면 무효값([BLE 4](../03-인터페이스/01-BLE.md)).
- 끊겨 잃은 것은 재연결 스냅샷이 되돌린다.

| 종류 | 보내는 때 |
|---|---|
| HELLO | CFG 응답 직후. 이어서 CONTACT(현재, `n_close`) → SYNC(현재) → BATT(마지막 1 s 평균) |
| CONTACT | S1 확정마다 |
| SYNC | 유효가 될 때, 무효가 될 때 |
| BATT | 10 s마다(`v_1s`) |
| BYE | 꺼지기 직전(연결돼 있을 때). 보낸 뒤 ≥ 300 ms에 PWR_HOLD LOW. 1 s 안에 못 보내면 포기하고 순서를 잇는다. 보낸 뒤 광고 안 함 |
| BTN | 8절 |
| RAW_S1 | `CS_TEST`만. 원시 레벨이 20 ms 안정된 뒤 첫 에지 시각을 적고, 다시 20 ms 안정되면 1개(튐당 1개) |

## 7. 연결·광고

- 광고는 전원이 켜지고 도크 검사를 통과했고 끄는 중이 아니고 연결이 없을 때만. 연결되면 제어기가 멈추고, 끊기면 곧바로 다시 한다. 광고 값은 [BLE 1](../03-인터페이스/01-BLE.md).
- CONNECT status ≠ 0이면 곧바로 다시 광고한다.
- CFG 대기: 연결 뒤 `CFG_WAIT_MS`(5000) 안에 CFG가 없으면 `ble_gap_terminate` 후 다시 광고한다. 타이머는 `ble_gap_conn_find()`가 성공하는 동안만 센다.
- 큐브는 파라미터 갱신을 요청하지 않는다. 평상시 플래시에 쓰지 않는다.

## 8. 버튼

| 누름 | 판정 | 동작 |
|---|---|---|
| 부팅 때 눌려 있던 누름 | 뗄 때까지 무시 | 없음. 그 뗌도 보내지 않음 |
| 부팅 때 누름이 10 s 넘음 | 고착 | 맨 아래 줄 빨강 1 s → PWR_HOLD LOW → 해제 뒤 생존 |
| 새 누름 확정(30 ms) | 눌림 시작 | BTN `v0 = 0` |
| 뗌, 누른 시간 < 1000 ms | 짧게 | BTN `v0 = 1`, `v1` = ms |
| 뗌, 1000 ≤ 누른 시간 < `OFF_HOLD_MS` | 길게 | BTN `v0 = 2`, `v1` = ms |
| 누른 채 `OFF_HOLD_MS` 도달 | 끄기 | 뗌 EVT 없이 BYE 2 → 끄기 순서 |

- BTN EVT(0x06)는 규격 v1에 있다. 형식은 [BLE 3](../03-인터페이스/01-BLE.md), PC 검사는 [USB 7](../03-인터페이스/02-USB.md).
- `OFF_HOLD_MS` = 4000(REQ-063, 10/11 확정). 길게 = 1~4 s.
- 누른 시간은 확정 누름 시각부터 확정 뗌 시각까지. `t_pad32`는 확정 시각.
- `CS_TEST` 모드 0: 1.5 s 안에 센 짧게 누름 횟수가 명령이다. 1번 = 링크 끊고 1.0 s 조용히(광고 안 함), 2번 = 2.5 s, 3번 = 8.0 s, 4번 = BYE 3 보내고 꺼짐. 받은 횟수를 맨 아래 줄 파랑 LED 개수로 1 s 보인다. 이 빌드에서 BTN EVT를 함께 보낼지 [미정 F7], 잠정 보내지 않음.

## 9. 전원·자동 꺼짐

| 상황 | 동작 | BYE | 표시 |
|---|---|---|---|
| 켬, 첫 1 s | LED 끈 채 `v_1s` 측정, 광고 병행 | | 끔 |
| 첫 1 s 평균 < `V_BOOT_MIN` | 끄기 | 3(연결돼 있으면) | 맨 아래 줄 빨강 1 s |
| 버튼 새로 `OFF_HOLD_MS` | 끄기 | 2 | 전부 끔 |
| 도크 감지(켜진 채) | 끄기 | 1 | 잔량 막대 3 s |
| `v_10s` < `V_OFF` | 끄기 | 3 | 맨 아래 줄 빨강 2 s |
| `v_10s` ≤ `V10` | 계속 동작 | | 맨 아래 줄 빨강 겹침 |
| S1 열림 5분 [권장안 U-57] | 끄기 | 2 | 끔 |
| 무연결 5분(링크 없을 때만 셈, 연결되면 0) | 끄기 | 없음 | 끔 |
| USB 호스트 연결 중 | 저전압·무연결·들린 채 꺼짐, 켜기 하한 판정, 딥슬립을 하지 않음 | | 규칙대로 |
| PWR_HOLD LOW 뒤 5 s 넘게 살아 있음 | LED 0 + 딥슬립(USB 호스트 연결 중이면 LED 0 대기) | | 끔 |
| 비정상 리셋 | 부팅 1번에서 꺼짐 | 없음 | 없음 |

- 끄기 순서(모두 같음): BYE(연결돼 있을 때) → 표시 → BYE 뒤 ≥ 300 ms(도크는 표시 3 s 뒤) → PWR_HOLD LOW. 링크가 먼저 끊겨도 순서를 잇는다.
- U-57이 기각되면 들린 채 조건은 "S1 열림 ∧ IMU 변화 없음 5분"이고 IMU 50 Hz 읽기를 loop에 더한다.

| 상수 | 값 |
|---|---|
| `V_OFF` | 3.60 V [실측 필요: C2·C9-h] |
| `V_BOOT_MIN` | V_OFF + 0.10 = 3.70 V |
| `V10` / `V30` | 3.70 V [권장안 U-96] / 임시 3.80 V [실측 필요: C7] |
| `NOLINK_OFF_S` / `LIFTED_OFF_S` | 300 / 300 |
| `BYE_HOLD_MS` | 300 |
| 해제 뒤 생존 | 5 s |

## 10. 표시

### 10.1 우선순위 (위가 이김)

| # | 표시 | 조건 |
|---:|---|---|
| 1 | LED 전부 끔 | 꺼지는 중(버튼). 도크·저전압 꺼짐은 2·3 표시 뒤 끔 |

- ICON 192 B는 호스트 콜백이 버퍼에 복사하고 플래그를 세운다. 바이트 순서는 [USB 4](../03-인터페이스/02-USB.md)·[BLE 2](../03-인터페이스/01-BLE.md).
- 밝기는 PC가 ICON 값에 반영한다 [권장안 U-57]. 큐브는 새 ICON의 켜진 칸(받은 값에서 세 채널 중 하나라도 0이 아닌 칸, 제한기 전)이 지금과 같고 평균 밝기만 낮으면 `DIM_FADE_MS`(500)에 걸쳐 선형으로 바꾼다. 그 밖(그림이 바뀜, 밝아짐)은 즉시 바꾼다.
- `?` 깜빡임은 PC가 두 ICON을 번갈아 보낸다. 그림이 바뀌므로 위 규칙대로 즉시 바뀐다(페이드가 깜빡임을 번지게 하지 않음).

### 10.2 `ledShow()` 제한기

- 모든 출력은 `ledShow()` 한 경로다. 제한기를 끄는 빌드는 만들지 않는다.
- `I_est = Σ(r + g + b)/255 × I_CH`. `I_est`가 상한을 넘으면 모든 값에 `상한 / I_est`를 곱한다. 부팅 첫 프레임은 전부 0.
- 상한 `LED_ADD_MAX_ACTIVE` 40 mA(큐브가 강제하는 유일한 상한). 어두운 밝기 15 mA는 PC가 보내는 ICON 값의 계약 상한이다 [권장안 U-57].
- `I_CH` 19 mA [실측 필요: C3-b].
- RMT 4블록(192심볼)이라 재충전 간격이 약 120 µs로 IR ISR과 덜 겹친다.
