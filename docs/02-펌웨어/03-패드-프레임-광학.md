# 패드 펌웨어: 프레임과 광학 (pad_fw, ESP32-S3-Zero)

이 문서로 답하는 것: 패드는 어떤 핀으로 무엇을 읽고, 코어·태스크·큐를 어떻게 나누고, 50 ms 프레임 한 번에 무엇을 하고, 광학 상태를 어떻게 정하나.

관련: [01-구조-빌드](01-구조-빌드.md) · [04-패드-BLE-USB-LED](04-패드-BLE-USB-LED.md) · [USB 규격](../03-인터페이스/02-USB.md) · [패드 하드웨어](../01-하드웨어/02-패드.md)

패드는 판정하지 않는다. 좌표·놓임·배정은 PC가 한다 [권장안 U-32]. 패드는 광학 원시 창과 큐브 사건에 시각을 붙여 올리고, PC가 준 그림과 아이콘을 내보낸다.

## 2. 코어·태스크·큐

| 흐름 | 코어 | 우선순위 | 하는 일 | 입력 → 출력 |
|---|---|---|---|---|
| 프레임 루프(`loop()`) | 1 | 1(손잡이 2) | `loop()` 한 번 = 프레임 하나: LED, 먹스·ADC, 광학, USB 펌프, LED 전원, 감광 | `evtQ`, USB RX, `sync_ok_ms`(읽기) → `cmdQ`, USB TX, RMT, GPIO40 |
| RMT ISR | 1 | 인터럽트 | 심볼 재충전(LED 창에서만) | |
| 시험 GPIO ISR(`CS_TEST_X1J`) | 1 | 인터럽트 | 에지 시각 기록 | → 링 버퍼 |
| NimBLE 호스트 | 0 | IDF 기본 | GAP·GATT 콜백 → `bleQ`에 넣기만 | |
| BT 제어기 | 0 | IDF 기본 | | |
| esp_timer 태스크 | 0 | IDF 기본 | 링크별 SYNC 쓰기 | 링크 구조체(읽기) → `sync_ok_ms` |
| `bleCtl`(새로) | 0 | 호스트보다 낮게 | 등록 표·링크 상태기계 단독 소유, 연결·설정·끊기, NVS, ICON·CFG 쓰기 | `bleQ`, `cmdQ` → `evtQ`, NimBLE |
| USB 인터럽트 | 0 | 인터럽트 | HWCDC 링 버퍼 | |

| 큐 | 칸 | 방향 | 가득 찼을 때 |
|---|---:|---|---|
| `bleQ` | 32 | NimBLE 콜백 → `bleCtl` | 광고 보고는 0 대기로 넣고 버림. 연결·GATT·EVT는 최대 10 ms 기다리고, 그래도 실패면 `lost_evt` +1. `bleCtl`은 `lost_evt` ≠ 0이면 슬롯마다 `ble_gap_conn_find`로 링크 표를 맞춘다(없는 링크 = DISCONNECT, 사유 0x10) |
| `evtQ` | 32 | `bleCtl` → 루프 | 버리고 `tx_drop` +1 |
| `cmdQ` | 16 | 루프 → `bleCtl` | 버리고 ACK를 보내지 않는다(PC가 1 s 뒤 다시 보냄) |

- 잠금은 없다. RMT 채널은 `setup()`(코어 1)에서 만들어 RMT 인터럽트를 코어 1에 둔다.
- 루프는 BLE 상태를 `evtQ`로만 안다. LINK·EVT를 받으면 슬롯별 사본(link, sync, contact, n_close, 마지막 HELLO·CONTACT·BATT)을 고친다. OBS `st`·읽기 조건·스냅샷은 이 사본으로 만든다.
- 사본의 예외 둘: ① `CFG_REWRITE`를 `cmdQ`에 넣는 순간 사본 sync를 WARMING으로 바꾼다. ② `sync_ok_ms[slot]`(SYNC 콜백만 쓰는 원자적 u32)이 800 ms 넘게 갱신되지 않으면 그 슬롯을 읽지 않는다.
- 코어 미고정 타이머 데몬(우선순위 1)이 루프와 시분할될 수 있다. X2-U2 읽기 창 편차가 200 µs를 넘으면 `setup()`에서 `vTaskPrioritySet(NULL, 2)`.

## 4. 프레임 시간표 (P = 50 ms)

- 패드 시각 = `esp_timer_get_time()`. `frame_no = floor(t / FRAME_US)`. 시각은 바쁜 대기로 지킨다.
- 슬롯 6 고정(등록 번호 0~5 = 발광 슬롯). 빈 슬롯 시간은 쉰다.

| 구간 | 패드 시각(ms) | 루프가 하는 일 | 큐브 IR |
|---|---|---|---|
| LED 창 | 0.00~3.20 | 대기 심볼 버퍼가 있으면 교체 → 4체인 송신 → 계산한 완료 시각까지 대기. 끝에서 **펌프 ①** | 모두 끔 |
| 배경 | 3.20~14.46 | 3.50까지 대기(데이터선 LOW ≥ 300 µs) → 11주소 × 7행 읽기(3.50~12.96) → sync_fault 검사 → **펌프 ②** → 14.46까지 대기 | 모두 끔 |
| 슬롯 i(0~5) | S_i = 14.46 + 5.46·i부터 5.46 | 링크가 있고 읽기 조건이면 S_i + 1.80까지 대기 → 추적 창 또는 발견 청크 읽기(~S_i + 3.96) → 배경 빼기 → 광학 상태 → OBS. 조건이 안 되면 NA OBS. 어느 쪽이든 **펌프 ③**. 링크가 없으면 펌프만 | 등록 번호 i만 |
| 여유 | 47.22~50.00 | **펌프 ④**, 500 ms마다 STATUS, LED 전원 상태기계, PC 생존 규칙, 다음 LED 프레임 부호화(교체는 다음 LED 창), `loop()` 반환 | 모두 끔 |

- 슬롯 읽기 조건: link UP ∧ sync VALID ∧ `sync_ok_ms` ≤ 800 ms 전 ∧ 늦음 ≤ `SLOT_LATE_SKIP_US`(200).
- 큐브에 주는 CFG 값: `frame_us` = `FRAME_US`, `on_offset_us` = 14460 + 5460·slot, `on_len_us` 5460, `bias_us` = `BIAS_US`(1000).
- 펌프 간격 상한은 ① → ② 약 11.3 ms다.

**넘침 규칙**(셋 다 `overrun` +1, 몰아서 따라잡지 않음):

| 경우 | 처리 |
|---|---|
| 프레임 시작이 `FRAME_LATE_SKIP_US`(1000) 넘게 늦음 | 그 프레임 건너뜀(다음 경계에서, `frame_no`는 시각대로 늚) |
| 배경 읽기 시작이 `BG_START_MAX_US`(3500) 넘음 | 배경 갱신·sync_fault 검사 건너뜀 |
| 슬롯 읽기 창 시작이 200 µs 넘게 늦음 | 그 슬롯 안 읽음, NA OBS + `st` "이번 프레임 읽지 않음" 비트 |

**프레임 공식**(`frame.h`, 측정값이 바뀌면 여기만 고침):

```
R_bg   = 11 × (a + 7·c·READS)
R_slot = max(4 × (a + 3·c·READS), 2 × (a + 7·c·READS))
배경 구간 = t_s + R_bg + e ;  슬롯 L = e + t_s + R_slot + e
P ≥ G_LED + 배경 구간 + 6·L + 1(여유) → 25/3 ms 배수로 올림, FRAME_US는 정수 µs
기본값: a 0.3, c 0.08, READS 1, t_s 0.3, e 1.5, G_LED 3.2 [실측 필요] → P 50
```

| 조건 | P(`FRAME_US`) |
|---|---:|
| 기본 | 50000 |
| LED 1체인 순차(T9 B) | 58333 |
| READS 2 | 66667 |
| READS 4 | 91667 |
| e 3.0(X1-J 미달 1단계) | 75000 |
| e 4.5 [권장안 U-106] | 91667 |

## 5. 센서 읽기

- 배경: 주소마다 S0~S3 설정 → `a` 기다림 → 7개 SIG를 차례로 `analogReadMilliVolts`(READS 1). 11주소 × 7행 = 77값 `BG[r][c]`.
- 슬롯 창: 추적 창 3행 × 4열(주소 4개 × 3채널) 또는 발견 청크 2열 × 7행(주소 2개 × 7채널).
- 차분: `v′ = (슬롯 읽기 − 같은 센서 BG) × (1/g)`. 단위는 이득 중앙값 센서의 mV.
- 영점 ch15는 부팅 자가진단에서만 읽는다.
- 슬롯 값의 OBS 형식(창, 발견 OBS의 빈 열, `st` 비트)은 [USB 3](../03-인터페이스/02-USB.md).

## 6. 광학 판정 (`optics`)

### 6.1 상수 (`optics.h`, 보정 도구가 `cal-<serial>.json`에서 생성)

| 이름 | 정의 | 측정 전 임시값 |
|---|---|---|
| `INV_G[7][11]` | GAIN-CAL 이득 g(77개 중앙값 = 1)의 역수 | 1 |
| `TH_ABS` | 50 mV | 50 |
| `SIGMA_N` | IR 끔 차분 200프레임 표준편차 | 5 mV [실측 필요: PT-4a] |
| `TH_ON[6]` | max(TH_ABS, 10σ_n, k_on × r_slot × V_REF), k_on = 0.5·f_c | 100 mV |
| `TH_OFF` | 0.8 × TH_ON[slot] | 80 mV |
| `TH_SF` | max(10σ_n, 0.5 × TH_ON[slot]) | 50 mV |
| `SAT_MV` | min(1550, V_clip − 50) | 1550 [실측 필요: PT-1s] |

- 임시값으로는 합격 판정을 하지 않는다.

### 6.2 광학 상태 (슬롯마다)

| 상태 | 조건 |
|---|---|
| NA | link DOWN, sync WARMING, SYNC 800 ms 공백, 또는 신호 없음 ∧ contact UP |
| SEARCHING | 신호 없음 ∧ contact DOWN. contact가 DOWN으로 바뀌면 여기서 시작 |
| ON_PAD | 발견 확정(6.3) 뒤. 확정 뒤에는 contact 값과 관계없이 우선 |
| OFF_PAD | SEARCHING으로 12프레임(0.6 s) 신호 없음. 발견 청크는 계속 돈다 |

- link UP ∧ sync VALID이면 contact와 무관하게 자기 슬롯을 늘 읽는다.

### 6.3 발견·소실

| 사건 | 규칙 |
|---|---|
| 후보 | 발견 청크의 V′_max ≥ TH_ON |
| 확정(1프레임) | 최근 1 s 안에 그 큐브의 CONTACT DOWN 에지가 있음 |
| 확정(2프레임) | 다음 프레임 추적 창(후보 중심)에서도 V′_max ≥ TH_ON이고 최대 센서가 후보 ±1칸 안 |
| 소실 | ON_PAD에서 V′_max < TH_OFF가 2프레임 → 찾기. 발견 청크는 마지막 위치에 가까운 열부터 |

- 발견 청크 순서: 열 {0,2} → {4,6} → {8,10} → {1,3} → {5,7} → {9}, 6프레임 한 바퀴.

### 6.4 추적 창 위치

- 중심 = 직전 프레임 창 안 최대 센서 (r*, c*).
- 행: `r0 = clamp(r* − 1, 0, 4)`, 3행.
- 열: 오른쪽 이웃 ≥ 왼쪽 이웃이면 `c* − 1`, 아니면 `c* − 2`에서 시작, `clamp(…, 0, 7)`, 4열.
- 격자 끝에서 자르지 않고 안쪽으로 민다. 크기는 늘 3 × 4.
- ON_PAD가 아니면 창 크기 0으로 보낸다.

### 6.5 SAT·sync_fault

- SAT: 창 안 센서의 배경 원시값이나 슬롯 원시값 하나라도 ≥ SAT_MV면 OBS `st` SAT 비트.
- B_ema: 센서마다 배경 지수 평균, α = 1/20, **늘 갱신**. 이탈 후보인 큐브의 3 × 3만 최대 3프레임 멈춘다.
- sync_fault(배경 구간, ON_PAD 큐브만):

```
D[r][c] = (BG − B_ema) × INV_G
D_rel   = D(r*, c*) − 중앙값(둘레 8개 가운데 격자 안의 것)
D_rel ≥ TH_SF가 3프레임 → OBS st sync_fault 비트 + cmdQ에 CFG_REWRITE(slot) + 사본 sync = WARMING
```

- 큐브는 다시 받은 CFG로 재예열한다(약 3 s, IR 꺼짐).

### 6.6 부팅 자가진단 `bad_map`

| 규칙 | 불량 |
|---|---|
| ch15(GND) 영점 > 30 mV | 그 먹스의 11개 |
| 배경 원시값 ≥ SAT_MV이고 같은 행 90 % 이상이 SAT_MV/2 미만 | 그 센서 |

- 비트 = 행 × 11 + 열, HELLO에 싣는다([USB 3](../03-인터페이스/02-USB.md)). 단선·죽은 센서는 GAIN-CAL이 가린다.
