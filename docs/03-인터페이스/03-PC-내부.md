## 1. 게이트웨이 → 상태기계 내부 사건

함수 호출로 넘긴다. G1~G8은 [02-USB.md](02-USB.md) 6절 규칙이다. 패드 메시지에서 만든 모든 사건에 그 프레임 머리 `t_us`를 `t_pad_us`로 붙인다(`cube.evt`만 예외: [02-USB.md](02-USB.md) 5절 복원 시각). 모든 사건에 입력원 `src`를 붙인다. 시각 필드 `t_pc_us`는 PC 시각 µs.

| 사건 | 필드 | 만드는 때 |
|---|---|---|
| `pad.session` | `state: up\|lost\|rebooted, pad_boot_id, reset_reason, fw, frame_us, bad_map, t_pc_us, snapshot[{slot, link, reason, mac, cube_boot_id, fw, contact, n_close, batt_mv}]` | G1·G2·G7. `snapshot`은 `up`·`rebooted`만 |
| `obs` | `slot, frame_no, t_pad_us, t_pc_us(= t_pad_us + off), age_ms, optical, sync_valid, contact_down, sat, sync_fault, not_read, led_seq, window{r0, c0, h, w, v[]}, x, y, conf` | G4를 통과한 OBS마다. `x, y, conf`는 `estimate(window, cal)`로 채움, ON_PAD 아니면 비움 |
| `cube.evt` | `slot, cube_boot_id, seq, type, v0, v1, t_pad_us, t_valid, t_pc_us` | G5를 통과한 EVT(RAW_S1 제외) |
| `cube.rebooted` | `slot, cube_boot_id` | G5 |
| `cube.link` | `slot, up, reason: dock\|button\|low_batt\|timeout\|stale\|local, mac` | LINK(G6) |
| `cube.icon_failed` | `slot` | ICON 재시도 실패 |
| `reg.candidate` | `mac, rssi` | CAND |
| `pad.status` | STATUS 필드 전부 + `gap`, `obs_stale`, `bad`, `bad_field`, 슬롯별 동기 유효 비율(OBS `st` b2, 최근 10 s) | STATUS |
| `pad.proto_mismatch` | `pad, pc` | [02-USB.md](02-USB.md) 7절 |

- `estimate(obs, cal) -> {valid, x, y, conf, edge, vmax, sum}`, 상태 없는 순수 함수. 좌표 원점은 LED 영역, 단위 mm.
- 접촉과 광학의 앞뒤는 `cube.evt.t_pad_us`와 `obs.t_pad_us`로 가린다. 게이트웨이는 도착 순서대로 넘긴다.
- JSON Schema(`schemas/obs.v1.json` 등)는 개발판·Vitest에서만 검사. 배포판은 TS 타입과 [02-USB.md](02-USB.md) 7절 값 검사.

기록 JSONL(게이트웨이, 한 줄 한 객체, 재생은 같은 순수 모듈에 넣음):

| `d` | 줄 |
|---|---|
| `meta`(첫 줄) | `{"t": t_pc_us, "d": "meta", "proto": 1, "gw": "<git 8자리>", "pc_boot": <u32>, "src": "pad"\|"sim"\|"csv"\|"csvfile"}` |
| `meas` | `{"t", "d": "meas", "meas_id", "pc_git", "pc_dirty", "pad_fw", "cube_fw": {"<슬롯>": "<EVT HELLO v1>"}, "cal_sha256"}`. 패드 HELLO 뒤 1줄, `cube_fw`가 바뀔 때마다 1줄 |
| `rx` / `tx` | `{"t", "d": "rx"\|"tx", "b": "<복원 프레임 base64, CRC 포함>"}` |
| `bad` | `{"t", "d": "bad", "b": "<앞 256 B base64>"}` |
| `port` | `{"t", "d": "port", "e": "open"\|"close"\|"error"}` |

파일 이름 `pad-<pad_boot_id 16진>-<시작 시각>.jsonl`. 제목·경로·URL·프롬프트는 어떤 기록에도 넣지 않는다.

## 2. 서비스 ↔ 창 어댑터 (stdio NDJSON)

전송 틀:

| 항목 | 값 |
|---|---|
| 프로세스 | `cube-adapter.exe`(C#), main의 상주 자식. stdin/stdout |
| 틀 | JSON 객체 1개 + `\n`. UTF-8, BOM 없음, 들여쓰기 없음. C# `new UTF8Encoding(false)` 읽기·쓰기(`AutoFlush = true`), Node `setEncoding('utf8')` |
| 한 줄 상한 | 262144 B. 넘으면 다음 `\n`까지 버리고 `ipc_overlong`++. JSON 아니면 버리고 `ipc_bad`++. `\r`은 JSON 공백 |
| 흐름 | 창마다 "보낸 1 + 대기 1"(latest-wins). Node는 `stdin.write`가 `false`면 `drain`까지 창마다 마지막 `apply` 항목만 들고 있음. `enumerate`·`launch`·`ping`은 버리지 않음 |
| 감시 | `ping` 1 s, 무응답 3 s → 재시작 1·2·4 s, 60 s에 3회 상한. 재시작 때 미응답 명령은 Node가 `uncertain(adapter_restart)`로 닫음 |
| 종료 코드 | 0 정상(stdin EOF 포함), 2 DPI 인식 실패, 3 관리자 권한 실행, 4 기타 치명. 2·3은 재시작 안 하고 사유 표시(3이면 `elevated`: 창 제어·AI 시작 모두 막음) |
| 판 | `v:1`. 필드 추가는 `v` 유지(모르는 필드 무시), 뜻이 바뀌면 `v` + 1 |

공통 값: 창 참조 `win = {hwnd, pid, proc_start}`(모두 10진 문자열). 사각형 `rect = {x, y, w, h}` 물리 px 정수, 원점 = 주 모니터 왼쪽 위, 보이는 경계(`DWMWA_EXTENDED_FRAME_BOUNDS`). 시각 = QPC 기반 µs 정수(Node `process.hrtime.bigint() / 1000n`).

Node → C#:

| `t` | 필드 | 응답 |
|---|---|---|
| `hello` | `v:1, t_sent` | `ready` |
| `config` | `apps:[{app_id, exe_names:[…], exe_path}], exclude_pids:[…]` | 없음 |
| `enumerate` | `req, with_title:bool, t_sent` | `windows` |
| `apply` | `batch_id, t_sent, items:[{cmd_id, win, op:"place"\|"restore"\|"minimize", rect?}]` | 항목마다 `result` |
| `launch` | `req, app_id, kind:"folder"\|"file"\|"url", arg, t_sent`(url은 K4) | `launched` 또는 `launch_failed` |
| `ping` | `seq, t_sent` | `pong` |

C# → Node:

| `t` | 필드 | 보내는 때 |
|---|---|---|
| `ready` | `v:1, pid, dpi_awareness:"pmv2", work_area:rect, os_build, is_window_arranged:bool, anim:{min_animate, client_area}` | `hello` 뒤 |
| `windows` | `req, list:[{win, app_id, state, visible_rect, dpi, z, excluded?:"elevated"\|"access_denied"\|"other_monitor", title?}]` | `enumerate` 뒤. `title`은 `with_title:true`일 때만, 서비스는 저장·기록 안 함 |
| `result` | `cmd_id, batch_id, win, verdict, reason?, visible_rect, state, dpi, retries, revision, queued, t_sent, t_recv, t_issue, t_obs, t_done` | 명령마다 |
| `window_state` | `win, state:"normal"\|"max"\|"arranged"\|"min"\|"hidden", visible_rect, by:"user"` | 250 ms 폴링, 상태가 바뀜 |
| `window_closed` | `win` | 250 ms 폴링, 창 사라짐·식별 키 불일치 |
| `window_changed`(K3) | `win, cause:"user_drag"\|"other", state:"normal", visible_rect` | 보통 상태에서 8 px 넘는 변화가 두 번 이어짐 |
| `display_changed` | `work_area:rect` | 1 s 폴링, 작업 영역 변경 |
| `launched` / `launch_failed` | `req, win, ms` / `req, reason:"bad_arg"\|"bad_exe"\|"no_new_window"\|"ambiguous"\|"start_error", ms` | 실행 대기 중 250 ms 열거, 기한 15 s |
| `pong` | `seq, t_sent, t_recv` | `ping` 뒤 |
| `error` | `code:"dpi_awareness"\|"adapter_elevated"\|"fatal", detail` | 종료 직전 |

판정값(`result.verdict`):

| 값 | 뜻 | `reason` | 서비스 처리 |
|---|---|---|---|
| `ok` | normal, 오차 ≤ 8 px(최소화는 min 도달) | | 없음 |
| `deferred` | 최소화 유지, 복원 위치만 갱신 | `kept_minimized` | 없음 |
| `clamped` | 계획보다 8 px 넘게 큼 | `min_size` | 최소 크기 표 갱신, 재계획 |
| `mismatch` | 그 밖 불일치 | `size`, `position`, `state` | 재계획 1회, 같은 창 연속 2회면 한계 표시 |
| `uncertain` | 기한 1000 ms 안 변화 없음 | `timeout`, `adapter_restart` | "응답 없음", 자동 재시도 없음. 10 s 안 같은 `cmd_id`의 `result{revision:1, reason:"late_apply"}`가 오면 그 판정으로 |
| `superseded` | 새 명령에 밀려 안 보냄 | | 없음 |
| `rejected` | 안 보냄 | `stale_handle`, `user_moving`, `hidden`, `elevated`, `access_denied`, `other_monitor` | 사유별 |
| `preempted_by_user`(K3) | 판정 때 사용자가 끌고 있음 | | 뒤따르는 `window_changed`로 |

- 서비스는 창마다 마지막으로 보낸 `cmd_id`보다 오래된 형상 결과(`ok`·`clamped`·`mismatch`)를 버린다. `window_closed`·`window_state`·`rejected(stale_handle·elevated·access_denied)`는 늘 적용한다.
- 창을 활성화하거나 Z 순서를 바꾸지 않는다. 예외: 전경 창 최소화는 `SW_MINIMIZE`, 나머지 `SW_SHOWMINNOACTIVE`, 새로 실행한 창 [권장안 U-24].
- 등록 앱(`app_id`): `vscode`(`Code.exe`, 인자 [`--new-window`, 폴더]), `notepad`(`Notepad.exe`, 인자 [파일]), `edge`(`msedge.exe`, [`--new-window`, URL], K4). `exe_path`는 등록 화면에서 받아 `config`로 보낸다.

묶기 재설계가 요구하는 것(규격 미정, 필요한 내용만):

| 기능 | 필요한 내용 |
|---|---|
| 점 → 맨 위 창 찾기 | 입력: 모니터 점(물리 px). 출력: 그 점에서 보이는 맨 위 등록 창 `win`(항상 위 창 건너뜀). 없으면 없음. 안 묶인 창만 고르는 것은 서비스가 할지 어댑터가 할지 [미정 S3: 잠정 = 엔진 `pick`이 계산] |
| 창별 보고 | `windows` 항목에 `onTop`(항상 위 여부) 추가 필요. `minimized`는 `state:"min"`, `z`는 이미 있음. `home`(최소화 전 자리)은 최소화된 창의 복원 사각형 보고 또는 서비스 저장 중 하나 [미정 S3: 잠정 = 어댑터가 `onTop`, 서비스가 `home` 기억] |
| 지도 갱신 | 안 묶인 창의 새 창·이동·도킹·최소화를 따라가야 함. 잠정: 주기 `enumerate`로 지도만 갱신 [미정 C9] |
| 배치 밖 창 최소화 | 기존 `apply{op:"minimize"}`로 충분(항상 위·관리자 권한·사용자가 새로 연 창 제외) |
| 등록 앱 실행 | `launch`를 M2로 당김. 팝업에서 프로그램만 고를 때(폴더·파일 인자 없음) `arg` 형식 필요. 대상은 등록 앱만 [미정 C1] |

## 3. 렌더러 ↔ main IPC

| 방향 | 수단 |
|---|---|
| 렌더러 → main | `window.cube.invoke(ch, body)` → `ipcRenderer.invoke('cube:req', ch, body)` → `ipcMain.handle('cube:req')` 1개 |
| main → 렌더러 | `webContents.send('cube:state', {ver, s})` → `window.cube.onState(cb)`(해제 함수 반환) |
| 그 밖 | preload 노출은 위 두 함수뿐. `ipcMain.on` 0개. TCP·UDP 포트·WebSocket 없음 [권장안 U-22] |

`cube:state`의 `s`(렌더러가 읽는 후보 계약. 서비스가 필드를 확정하면 이 표를 고친다). 렌더러는 `ver`가 정수 ≥ 0이고 지금보다 클 때만 받고, `s`가 객체가 아니면 버린다. 모든 칸은 없을 수 있다.

| 칸 | 형 |
|---|---|
| `pad` | `{session: up\|lost\|rebooted, input: pad\|sim\|csv\|csvfile\|replay, fw?, bad_sensors?: number[]}` |
| `mode` | `screen\|ai` |
| `ai` | `{state: ready\|running\|waiting\|done\|failed\|stopped, step?}` |
| `notices` | `[{code, slot?}]`. 코드: `pad_lost`, `pad_rebooted`, `proto_mismatch`, `cube_proto_mismatch`, `port_busy`, `elevated`, `adapter_down`, `icon_failed`, `cli_version_mismatch`, `storage_error` |
| `cubes` | `[{slot, name, mac4, link: up\|down, down_reason?: link\|bye1\|bye2\|bye3, batt_pct: number\|null, batt_level: ok\|low30\|low10, state, xy: [x, y]\|null, owner: string\|null, protect?: {by: manual\|auto, absent?: lift\|link}, released_by_drop?}]`. `state`는 U·RUN·RUNp·LIFT·LIFTp·RECOG·RECOGp·HOLD·PABS·REM([소프트웨어 03](../04-소프트웨어/03-상태기계.md), p = 보호) |
| `windows` | `[{id, app, owner: string\|null, status: linked\|minimized\|relaunchable\|gone\|excluded\|no_response, reason?: elevated\|access_denied}]` |
| `last_error` | `{code, text}` |
| `saved` | `{cubes, windows, template: number\|null}` |

- 시안 견본에는 `profiles`·`layout`도 있다. 형은 AI 모드·배치 화면을 만들 때 정한다 [미정 S2와 함께].

main 검사 순서:
1. `event.senderFrame?.origin === APP_ORIGIN`(`app://cube` [실측 필요]) 아니면 `forbidden_sender`
2. `ch`가 허용 목록에 없으면 `forbidden_channel`
3. `JSON.stringify(body)`가 예외면 `bad_request`, UTF-8 바이트 > 65536이면 `too_large`
4. 채널 스키마(ajv, `additionalProperties: false`) 틀림 → `bad_request`
5. 특권 채널이면 main이 네이티브 확인 창
6. 서비스 호출. 서비스 응답 대기 10 s 넘으면 `timeout`

응답: `{ok: true, body}` 또는 `{ok: false, err, detail_id?}`. `err` 12개: `bad_request`, `forbidden_channel`, `forbidden_sender`, `too_large`, `busy`, `stale_view`, `not_waiting`, `not_found`, `no_free_slot`, `bad_arg`, `timeout`, `internal`. 진단 로그는 `ch`·결과 코드·처리 ms만(body 없음).

허용 채널 27개(배포판). 개발판만 `dev.*`(시뮬레이터 조작) 추가:

| 종류 | `ch` `{본문}` |
|---|---|
| 읽기 | `snapshot.get{}`, `history.list{limit ≤ 200, before?}`, `diag.get{}`, `ai.output.get{run_id, step_no, kind: "result"\|"diff"\|"test_log", offset}`(64 KiB씩) |
| 변경 | `mode.set{mode: "screen"\|"ai"}`, `layout.rearrange{}`(→ `{layout_ver}`), `assign.release{slot}`, `protect.set{slot, on}`, `window.relaunch{link_id}`(창이 있거나 실행 중이면 `busy`), `cube.register_scan{on}`(빈 슬롯 없으면 `no_free_slot`), `cube.register_commit{mac}`(최근 30 s CAND에 있어야 함), `cube.unregister{slot}`, `cube.rename{slot, name ≤ 32자}`, `cube.icon_set{slot, app_id}`, `profile.save{kind, id(UUID), fields}`, `profile.delete{id}`, `ai.start{request_id, view_ver}`, `ai.stop{run_id}`, `ai.answer{run_id, choice: "continue"\|"accept"\|"stop"}`, `ai.login{provider: "claude"\|"codex"}`, `clipboard.write{text ≤ 64 KiB}` |
| 특권 | `mcp.register_begin{name, args[], tools[]}`, `skill.register_begin{name}`, `workdir.register_begin{project_id}`, `tool.register_begin{tool}`, `project.test_begin{project_id, tool_id, args[], timeout_s, unisolated}`, `data.purge{}` |

- `ai.answer`의 `continue`는 대기 사유가 `tests_changed`·`config_file_changed`·`uncertain`이면 특권 처리.
- 중복: `ai.start`만 요청 ID. 같은 `request_id` → 첫 결과, 활성 실행 → `busy`, `view_ver` 다름 → `stale_view`, 아니면 새 `{run_id}`. 나머지 변경은 멱등. `ai.answer`는 대기 중이 아니면 `not_waiting`.
- 기한: 채널 응답 1 s 목표(오래 걸리는 일은 즉시 응답하고 진행은 상태로). 렌더러는 자동 재전송하지 않는다.
- 상태: `{ver, s}` 전체 스냅샷, 50 ms 모음(최대 20 Hz), 약 30 KB [실측 필요]. `ver`는 1씩 증가, 렌더러는 `ver ≤ 현재`면 버림. `did-finish-load` 때 main이 마지막 상태를 다시 보냄. 큰 텍스트·OBS 원자료는 넣지 않음. `s`의 필드는 상태기계·배치·어댑터·AI 문서가 정함.
- 알림 `s.notices[] = {code, slot?, text_id}`: `pad_lost`, `pad_rebooted`, `proto_mismatch`, `cube_proto_mismatch`, `port_busy`, `elevated`, `adapter_down`, `icon_failed`, `cli_version_mismatch`.
- 등록 흐름: `cube.register_scan{on: true}` → REG_SCAN on → 2500 ms 동안 CAND 주소가 정확히 1개면 MAC 끝 4자리·RSSI를 보이고(2개 이상이면 "하나만 켜세요", 30 s 없으면 "찾지 못함") → `cube.register_commit{mac}` → 빈 슬롯 중 가장 작은 번호로 REG → LINK `up=1` → ICON.

코드 저장소의 지금 코드(`pc/src/main/ipc-check.ts`, `main.ts`, `preload/preload.ts`)와 대조:

| 항목 | 설계 | 코드 |
|---|---|---|
| 채널 이름·수 | 27개 | 같음(`CHANNELS`) |

## 4. 서비스 → AI CLI 호출

자식 실행 규칙(CLI·판정 테스트·어댑터 모두):

| 규칙 | 내용 |
|---|---|
| R1 셸 없음 | `spawn(file, args, { shell: false, windowsHide: true })`. `exec`·`shell: true` 금지 |
| R2 `.exe`만 | `file`은 등록 표의 절대 경로, 확장자 `.exe`. `.cmd`·`.bat`·`.ps1`·`.vbs`·`.js`는 등록에서 거부 |
| R3 사용자 글 | 프롬프트는 stdin으로만. 작업 폴더는 `cwd`. MCP·설정은 실행 폴더에 만든 파일 경로 |
| R4 저장값 인자 | Claude 세션 ID `^[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}$`, Codex `thread_id` `^[0-9A-Za-z-]{8,64}$` [실측 필요], 모델 = 코드 상수 목록의 전체 이름 |
| R5 환경 | 부모 환경을 물려주지 않고 허용 목록으로 새로 만듦. API 키는 `auth = api_key`일 때만 그 CLI 자식에만(`ANTHROPIC_API_KEY` 또는 `CODEX_API_KEY`) |
| R6 종료 | 중지·시간 초과·설정 불일치는 `taskkill /PID <pid> /T /F` 즉시. `interrupt`·SIGINT·SIGTERM 안 씀. 끝낸 세션은 `tainted` |
| R7 출력 상한 | stdout + stderr 단계당 16 MiB, 넘으면 R6 + `output_limit` |
| R8 작업 개체 | `detached: false`. 앱이 비정상 종료하면 직계 자식(`claude.exe`·`codex.exe`·어댑터)은 함께 끝나지만, libuv 작업 개체에 `SILENT_BREAKAWAY_OK`가 있어 손자(MCP 서버·셸·판정 테스트)는 남을 수 있다. 손자까지 끝내는 길은 R6 `taskkill /T`다 |
| 판 고정 | 실행마다 `--version`을 읽어 고정값과 다르면 시작 거부(`cli_version_mismatch`) |

Claude(`claude.exe`, `cwd` = 작업 폴더):

| 인자 | 값 |
|---|---|
| `-p` | 고정 문자열 `"표준 입력의 CUBE SPACE 지시를 따른다"` |
| `--output-format stream-json --verbose` | |
| `--setting-sources user`, `--settings <run>\claude\settings.json` | |
| `--strict-mcp-config --mcp-config <run>\claude\mcp.json` | 서버가 없으면 `{"mcpServers":{}}` |
| `--tools` | R `Read,Grep,Glob` / W `Read,Grep,Glob,Edit,Write` / 순서 추천 `""` |
| `--permission-mode` | R·순서 추천 `dontAsk` / W `acceptEdits` |
| `--permission-prompts none`, `--disable-slash-commands`, `--system-prompt-snapshot off` | |
| `--allowedTools` | `mcp__<서버>__<도구>,…`(허용 MCP 도구가 있을 때만) |
| `--model` | 전체 이름(별칭 금지) |
| `--max-turns` | 계획 30, 구현 60, 검토 30, 수정 40, 순서 추천 3 |
| `--session-id <UUID>` 또는 `--resume <UUID>` | 함께 쓰는 것은 `--resume <id> --fork-session --session-id <새 UUID>`뿐 |
| `--json-schema` | 단계 스키마(한 줄 JSON) |
| `--max-budget-usd 1.00` | API 키 모드만 |

- 환경: `SystemRoot`·`SystemDrive`·`windir`·`TEMP`·`TMP`·`USERPROFILE`·`HOMEDRIVE`·`HOMEPATH`·`APPDATA`·`LOCALAPPDATA` 복사, `PATH=%SystemRoot%\System32;<claude.exe 폴더>`, `CLAUDE_CONFIG_DIR=%LOCALAPPDATA%\CubeSpace\claude-home`, `CLAUDE_CODE_DISABLE_AUTO_MEMORY=1`, `ENABLE_CLAUDEAI_MCP_SERVERS=false`, `DISABLE_AUTOUPDATER=1`, `DISABLE_UPDATES=1`, `CLAUDE_CODE_USE_POWERSHELL_TOOL=0`, `CLAUDE_CODE_SUBPROCESS_ENV_SCRUB=1`.
- 환경 값의 `%이름%`은 표기다. 서비스가 부모 `process.env`로 펼친 실제 경로를 넣는다.
- stdin: 조립한 UTF-8 텍스트(≤ 1 MB, CLI 상한 10 MB)를 쓰고 바로 닫는다. 제어 요청 없음.
- stdout에서 쓰는 사건: `system/init`, `rate_limit_event`, `system/api_retry`, `assistant`(도구 이름만), `result`(`subtype`·`is_error`·`terminal_reason`·`usage`·`modelUsage`·`total_cost_usd`·`num_turns`·`permission_denials`·`structured_output`).

Codex는 독립 실행 `codex.exe` 경로를 등록한다. npm 판(`@openai/codex`)은 실행 파일이 `bin/codex.js`라 Windows에서 `.cmd`로 깔려 R2에 걸린다.

Codex(`codex.exe`, `cwd` = 작업 폴더, `CODEX_HOME=%LOCALAPPDATA%\CubeSpace\codex-home`, `config.toml`은 단계마다 새로 씀):

```
codex.exe exec --json --sandbox <read-only|workspace-write> -c sandbox_mode="<같은 값>"
  --model <전체 이름> --cd <작업 폴더> --ignore-rules
  --output-schema <run>\schema\<단계 종류>.json -o <run>\steps\<step_id>\last.json
  [--skip-git-repo-check]
  -
```

- 환경: Claude 복사분 + `PATHEXT`·`ComSpec`·`ProgramFiles`·`ProgramData`, `PATH=%SystemRoot%\System32;<codex.exe 폴더>;<등록 도구 폴더>`.
- stdout에서 쓰는 사건: `thread.started`(`thread_id` 즉시 저장), `turn.completed`(`usage`), `turn.failed`·`error`, `item.completed`의 `command_execution`·`file_change`·`mcp_tool_call`.
- 판정 테스트: `codex.exe sandbox -- <test.argv…>`, 같은 환경에서 API 키 뺌, 300 s 뒤 트리 종료.

단계 출력 스키마(모두 `additionalProperties: false`, 모든 속성 `required`, 선택 값은 `null` 합집합, 길이 제약 넣지 않음. 서비스가 받은 뒤 문자열 4000자·배열 20개로 자르고 `truncated` 표시):

| 단계 | 필드 |
|---|---|
| plan | `summary`, `steps[]`, `files_to_change[]`, `tests_to_add[]`, `risks[]` |
| implement, fix | `summary`, `changed_files[]`, `notes` |
| review | `verdict: "approve"\|"changes"`, `issues[{file, line: integer\|null, problem, fix}]` |
| order_recommend | `order[]`(prompt profile_id), `reason` |

- Claude `result.subtype = error_max_structured_output_retries`, 또는 `success`인데 `structured_output` 없음 → `bad_output`.
- 단계 벽시계 상한: 계획 10분, 구현 20분, 검토 10분, 수정 15분, 순서 추천 60 s.
