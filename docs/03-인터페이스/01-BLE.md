# 큐브 ↔ 패드 BLE 규격

이 문서로 답하는 것: 큐브와 패드가 BLE로 무엇을, 어떤 바이트로, 언제 주고받나?

> 표시: `[권장안 U-nn]` 확정 전 값, 이 값으로 구현. `[미정 …]` 값 없음(번호는 [03-미정-결정](../00-공통/03-미정-결정.md)), 잠정이 있으면 함께 적음. `[실측 필요]` 시작값, 시험으로 고정.
> 기준일 2026-10-11. 묶기 재설계(10/8 확정)를 반영했다. 큐브·패드가 보내는 값과 바이트 형식은 규격 v1로 확정(10/11, 판 규칙은 [USB 7](02-USB.md)).
> 공통: 모든 정수는 리틀 엔디언, 구조체에 빈 바이트 없음. 값은 한 곳에만 둔다: 펌웨어 `proto.h`(BLE는 `x1_proto.h`), PC `proto.ts`.
> 같은 묶음: [01-BLE](01-BLE.md) · [02-USB](02-USB.md) · [03-PC-내부](03-PC-내부.md) · [04-시험-벡터](04-시험-벡터.md)

## 1. 연결 값

| 항목 | 값 |
|---|---|
| 역할 | 패드 = 중앙(광고 안 함), 큐브 = 주변(GATT 서버) |
| 연결 수 | 켜진 등록 큐브 전부, 최대 6(링크 6 + 스캔 1 = 제어기 활동 7). 재빌드 `MAX_CONNECTIONS=6` 전제, 사전 빌드면 3 [권장안 U-06] |
| 큐브 광고 | 연결 가능·비지향 레거시, 간격 80(50 ms), 채널 37·38·39, 공개 주소. AD = Flags `0x06`(3 B) + 128비트 서비스 UUID(18 B) = 21 B. 이름·스캔 응답 없음 |
| 광고하는 때 | 켜져 도크 검사를 통과했고, 끄는 중이 아니고, 연결이 없을 때. 끊기면 바로 다시. BYE를 보낸 뒤에는 안 함 |
| 패드 스캔(평상시) | 수동, `itvl 0x0061`(60.625 ms), `window 0x0018`(15 ms), `filter_duplicates 0`, 무기한, `filter_policy 1`(허용 목록 = 등록 MAC). 등록 표가 바뀌면 스캔 멈춤 → `ble_gap_wl_set()` → 재시작 |
| 패드 스캔(등록 모드) | 위와 같고 `filter_policy 0`. REG_SCAN on 뒤 30 s에 스스로 끔 |
| 연결 개시 | 한 번에 1개. `ble_gap_connect` 제한 2000 ms, 개시 스캔 `16/16`(10 ms). 개시·설정 동안 스캔 멈춤. 재빌드 `CONN_REATTEMPT=n` |
| 연결 파라미터 | `itvl_min = itvl_max = 24`(30 ms), latency 0, supervision 200(2.0 s), `ce_len 0/0`. 큐브는 갱신 요청 안 함 |
| PHY·MTU | 1M. MTU 선호 256, 연결 직후 1회 교환 |
| 송신 출력 | 큐브는 +9 dBm 이하로 명시 설정. 패드는 +9 dBm에서 시작, 조정 손잡이 +15 dBm(21 dBm 금지) |
| 설정 순서 | 연결 → MTU → 서비스 탐색(UUID) → 특성 전부 → EVT 설명자 → CCCD `0x0001` 쓰기 → CFG 쓰기(응답) → USB LINK `up=1` → 스캔 재개 → SYNC 타이머(예열 간격). 전체 제한 3000 ms |
| 설정 실패 | 연결 실패·설정 중 끊김·3 s 초과·원격 GATT 오류. 같은 MAC 연속 3번이면 10 s 무시. 실패마다 USB LOG 수준 2(슬롯·단계·NimBLE 오류 코드) |
| 큐브 CFG 대기 | 연결 뒤 5000 ms 안에 CFG가 없으면 큐브가 끊음(`ble_gap_conn_find` 성공 동안만 셈). CONNECT status ≠ 0이면 곧바로 다시 광고 |
| 패드 사건 거름 | GAP·GATT 사건은 conn_handle이 그 슬롯의 현재 값과 같을 때만 처리. CLOSING에서 `terminate`가 `BLE_HS_ENOTCONN`이면 바로 DOWN |
| 옛 링크 | 링크가 있는 MAC의 광고를 보면 끊지 않고 사유 `0x11`만 예약. supervision 만료 DISCONNECT에 그 사유를 붙여 알리고 다시 연결 |
| GATT 쓰기 동시 수 | ICON·CFG 재기록은 패드 전체에서 1개(CFG 먼저, 슬롯 번호 순) + 설정 절차 1개. `BLE_HS_ENOMEM`은 실패로 치지 않고 50 ms 뒤 다시 |
| 보안 | 본딩·암호화 없음, BLE OTA 없음 [권장안 U-74]. 연결은 등록 MAC만(등록 모드 제외) |

## 2. GATT 특성

| 이름 | UUID | 방향·속성 | 형식(B) |
|---|---|---|---|
| 서비스 | `92707afe-9ddd-4585-8e49-0b307dcd400e` | 기본 서비스 | |
| SYNC | `79532248-5f32-4b11-a3be-8af7e558bc3a` | 패드→큐브 Write Without Response | `i64 pad_us`(8) |
| CFG | `40d2c3b6-2a89-4611-a088-412719dd8c08` | 패드→큐브 Write(응답) | 아래(20) |
| EVT | `5df28f48-7cb1-46e7-9f86-85c031b2488c` | 큐브→패드 Notify(CCCD) | 아래(14) |
| ICON | `a8243c3b-780f-46e0-8283-f8630da1e8b6` | 패드→큐브 Write(응답) | `u8 rgb[192]`, 8×8 행 우선, 칸마다 R·G·B |

특성 순서는 위 표 순서로 고정한다. 패드는 연결마다 탐색한다.

CFG 20 B:

| 오프셋 | 필드 | 형 | 값 |
|---:|---|---|---|
| 0 | `ver` | u8 | 1 |
| 1 | `slot` | u8 | 0~5(등록 번호 = 발광 슬롯) |
| 2 | `pad_boot_id` | u32 | 패드 부팅 ID |
| 6 | `frame_us` | u32 | 기본 50000. 늘릴 때 25/3 ms 배수(58333·75000·91667) |
| 10 | `on_offset_us` | u32 | 14460 + 5460·slot |
| 14 | `on_len_us` | u32 | 5460 |
| 18 | `bias_us` | i16 | 1000 [실측 필요] |

EVT 14 B:

| 오프셋 | 필드 | 형 | 뜻 |
|---:|---|---|---|
| 0 | `cube_boot_id` | u32 | 큐브 부팅 ID |
| 4 | `seq` | u16 | 큐브 EVT 순번 |
| 6 | `type` | u8 | 3절 |
| 7 | `v0` | u8 | 3절 |
| 8 | `v1` | u16 | 3절 |
| 10 | `t_pad32` | u32 | 사건 시각(패드 시각 하위 32비트), 동기 무효면 `0xFFFFFFFF` |

| 특성 | 보내는 때 | 큐브 처리 |
|---|---|---|
| SYNC | 링크마다 one-shot 타이머, 다음 간격 µs 균등 난수: 예열(EVT SYNC=1 전) 5000~15000, 유효 뒤 20000~40000. 보내기 직전 `pad_us = esp_timer_get_time()`. 틱·프레임 배수에 맞추지 않는다 | 콜백 첫 줄 시각으로 추정기 갱신. 길이 ≠ 8이면 무시 |
| CFG | 설정 단계 끝, sync_fault 뒤, 값이 바뀔 때 | 길이 ≠ 20, `ver ≠ 1`, `slot > 5`면 ATT 오류 `0x80`. 응답 뒤 HELLO 스냅샷(4절) |
| EVT | 3절 | 구독 전에는 보내지 않음 |
| ICON | 그 슬롯 LINK `up=1` 뒤마다, 아이콘·밝기가 바뀔 때. 밝기는 PC가 값에 반영 [권장안 U-57] | 길이 ≠ 192면 거부. 버퍼 복사 뒤 응답, 표시는 loop |

- CFG 원격 오류 → 링크를 끊고 다시 연결(설정 실패 1회). ICON 실패 → USB ACK `code 4`.
- ICON 192 B는 MTU 256의 Write 최대 253 B에 한 번에 든다. ICON은 MTU 교환 뒤에만 보낸다.

## 3. EVT 종류

| type | 이름 | v0 | v1 | t_pad32 | 보내는 때 |
|---|---|---|---|---|---|
| 0x01 | CONTACT | 1 놓임(S1 닫힘), 0 들림 | `n_close`: 부팅 뒤 열림→닫힘 확정 수(부팅 때 닫힘은 안 셈), u16 순환 | S1 5 ms 확정 시각 | 확정마다, 스냅샷 |
| 0x02 | SYNC | 1 유효, 0 무효 | 0 | 보낸 시각 | `n ≥ 300`이 될 때, 무효가 될 때, 스냅샷 |
| 0x03 | BATT | 0 | V_A1 mV(보고 직전 1 s 평균) | 보낸 시각 | 10 s마다, 스냅샷 |
| 0x04 | BYE | 1 도크, 2 버튼 끄기·들린 채 자동 꺼짐, 3 저전압 | 0 | 보낸 시각 | 꺼지기 직전(연결돼 있을 때) |
| 0x05 | HELLO | 프로토콜 판 1(`CUBE_PROTO`) | 펌웨어 판 `(주 << 8) \| 부`, 시험 빌드는 bit15 = 1 | 보낸 시각 | CFG 응답 직후 |
| 0x06 | BTN | 0 눌림 시작, 1 짧게 뗌(< 1 s), 2 길게 뗌(1 s 이상, 끄기 시간 미만) | v0 = 0이면 0, 1·2면 누른 ms(30 ms 확정 기준) | 확정 시각 | 누름·뗌 확정 때 |
| 0x10 | RAW_S1 | 튐이 끝난 뒤 S1 원시 레벨(1 = 닫힘) | 그 튐의 에지 수 | 첫 원시 에지 시각 | `CS_TEST` 빌드만. 20 ms 안정 → 첫 에지 → 다시 20 ms 안정 때 1개 |
| 0x07~0x0F, 0x11~0xFF | 예약 | | | | 보내지 않음 |

- BYE: 보낸 뒤 ≥ 300 ms(도크 3000 ms)에 PWR_HOLD 해제. 1 s 안에 못 보내면 포기하고 끈다.
- 끄기 누름 시간 `OFF_HOLD_MS`는 큐브 펌웨어 상수다([펌웨어 02 8절](../02-펌웨어/02-큐브.md)). 규격은 이 값에 기대지 않는다: 길게 = 1 s 이상, 끄기 시간에 닿으면 BTN 뗌 없이 BYE 2만.
- BTN 규칙: 켜기 누름과 켜진 직후 첫 뗌은 보내지 않음.

## 4. 순번·시각·보내기 규칙

| 값 | 규칙 |
|---|---|
| `cube_boot_id` | `nimble_port_init()` 뒤 `esp_random()`, 0이면 다시 |
| `seq` | 부팅 때 0. `ble_gatts_notify_custom`이 0을 돌려줄 때만 +1(보내지 못한 EVT는 번호를 쓰지 않음) |
| `t_pad32` | 큐브 로컬 사건 시각 `t`를 `T = t − est + bias_us`로 바꾼 하위 32비트. 동기 무효면 `0xFFFFFFFF` |
| 동기 추정 | SYNC 콜백: `obs = now − pad_us`; `n == 0`이면 `est = obs`, 아니면 `est = min(est + Δt × 40 / 10⁶, obs)`(정수 누설: `acc += Δt × 40; q = acc / 10⁶; acc −= q × 10⁶`). 유효 = `n ≥ 300` |
| 새 연결 첫 CFG | `pad_boot_id`가 저장값과 같고 마지막 SYNC가 5000 ms 안이면 `n` 유지(바로 유효), 아니면 `n = 0` |
| 같은 연결 두 번째 이후 CFG | 늘 `n = 0` + EVT SYNC(0) |
| HELLO 스냅샷 | CFG 응답 뒤 HELLO → CONTACT(현재 상태·`n_close`·확정 시각) → SYNC(현재) → BATT(마지막 1 s 평균). 첫 CFG에서 `n = 0`이면 이 CONTACT의 `t_pad32 = 0xFFFFFFFF`. 그래서 스냅샷의 놓임·들림 에지는 `n_close` 변화로만 판정 |

보내기 큐: 종류마다 "미전송 최신 1개"(새 사건이 같은 종류 미전송분을 덮음). BTN만 미전송 2칸. 1 ms마다 HELLO → RAW_S1 → CONTACT → BTN → SYNC → BATT → BYE 순으로 보내고, 하나가 실패하면 그 틱에서 멈춘다.

큐브 IR 발광: 링크 연결 ∧ CFG 받음 ∧ 동기 유효 ∧ S1 닫힘(5 ms 확정) ∧ 마지막 SYNC 뒤 1000 ms 이내일 때만 자기 구간 `[k·frame_us + on_offset_us, + on_len_us)`에 켠다. 하나라도 깨지면 바로 끈다.

## 5. 끊김 사유

패드가 USB LINK `up=0`의 `reason`에 붙인다.

| 코드 | 뜻 | 붙이는 조건 |
|---|---|---|
| 1·2·3 | BYE 사유 | 끊기기 전에 BYE를 받음. 받으면 끊김을 기다리지 않고 바로 LINK `up=0` |
| `0x10` | 시간 초과 | HCI `0x208`, 그 밖 모든 사유 |
| `0x11` | 옛 링크(재부팅한 큐브) | 0x11을 예약한 링크의 끊김(1절 옛 링크) |
| `0x12` | 패드가 끊음 | HCI `0x216`(REG에서 빠진 슬롯 등) |

LINK `up=1`을 보낸 적 없는 연결의 끊김은 알리지 않는다.
