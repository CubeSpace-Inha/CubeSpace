# 배치 엔진(engine)

이 문서로 답하는 것: 묶인 창을 화면에 어떻게 나누고, 큐브를 밀면 경계가 어떻게 움직이며, 놓은 점의 대상 창과 패드 지도는 어떻게 계산하나.

관련: [03 상태기계](03-상태기계.md) · [05 표시](05-표시.md) · [06 창 어댑터](06-창-어댑터.md) · [PC 내부 2 어댑터 메시지](../03-인터페이스/03-PC-내부.md)

## 1. 역할과 입구

- 순수 함수 묶음이다(`@cube-space/engine`, 기댈 패키지 없음). cube-events가 `step` 안에서 부르고, 결과 적용 묶음은 커밋 뒤 어댑터로 간다.
- 맡지 않는 것: 배정·판정 시점(상태기계), 좌표 필터·`motion` 생성(상태기계), 창 호출·판정(어댑터), LED 그리기(표시 렌더러).

| 입구 | 하는 일 |
|---|---|
| `pick(P, wins)` | 점의 대상(5절) |
| `region_at(tree, xy)` / `candidate(tree, xy)` | 영역 찾기, 깊이 ≥ 8.33 mm 후보 |
| `relayout(bound_on, cube_xy)` | 배치 다시(4절) |
| `fold(tree, w)` | 접힘(7절) |
| `on_motion` / `on_push_end` | 밀기(6절) |
| `rearrange()` | 재정렬 버튼 |
| `restore_saved()` / `reconcile()` | 모드 복귀, 서비스 시작 대조 |
| `on_adapter(result \| window_state \| windows \| display_changed)` | 결과 반응, 외부 변경, 지도 갱신 |
| `replan()` | 최소 크기 회복 |
| `pad_map(wins, bound)` | 패드 지도 칸 색(10절) |

- 출력 명령: 어댑터 `apply{batch_id, items:[{cmd_id, win, op, rect}]}`, `op ∈ {place, restore, minimize}`(올리기 없음). 묶음마다 `layout_ver`, 항목마다 원인 `motion.src` 또는 `null`. 형식은 [PC 내부 2](../03-인터페이스/03-PC-내부.md).

## 2. 좌표

| 항목 | 규약 |
|---|---|
| 패드 좌표 | mm, LED 영역 왼쪽 위 원점, x 0~200 오른쪽, y 0~133.33 아래 |
| 선 위치 `pos` | 작업 영역 기준 정규화 절대 좌표 0~1(float64). 부모 기준 비율이 아니다 |
| 정규화 → mm | `x_mm = u × 200`, `y_mm = v × 133.33` |
| 정규화 → px | `x_px = wa.x + round(u × wa.w)`, `y_px = wa.y + round(v × wa.h)`. 선마다 한 번 반올림해 인접 창이 같은 정수 경계를 쓴다 |
| 패드 점 → 화면 점 P | `P = (wa.x + round(x_mm/200 × wa.w), wa.y + round(y_mm/133.33 × wa.h))`. 축마다 따로 줄인다(1920 × 1032면 가로 9.60, 세로 7.74 px/mm) |
| 출력 사각형 | 물리 px 정수, 보이는 경계 `{x, y, w, h}`, 허용 오차 8 px |
| 패드에 그리는 선 | 가장 가까운 LED 칸 경계(피치 8.33 mm, 최대 ±4.17 mm) |
| 작업 영역 `wa` | 어댑터 `ready.work_area`(물리 px). Electron `screen`(DIP)은 쓰지 않는다 |

- 작업 영역이 바뀌면 `pos`는 그대로, px만 다시 계산한다. 최소 크기를 어기면 `replan`.

## 3. 분할 트리

- 노드 = `Leaf(win)` 또는 `Split(d, pos, a, b)`. `V` 세로선(a 왼쪽), `H` 가로선(a 위). 잎 ≤ 4. 창 id는 저장소 `window.id`(HWND 아님).
- 정규화 `canon(tree) = rebuild(layout(tree))`: 구조 변경(접힘·배치 다시·재정렬·모드 복귀·대조·재계획) 끝마다. 세로선 먼저, 작은 좌표 먼저. 선이 어긋나지 않은 2×2의 뿌리는 세로선이다. 선 이동(밀기)은 정규화하지 않는다.
- 저장: `layout{mode:'screen', tree_json, layout_ver, saved_at}`. `tree_json` = `{"d":"V"|"H","pos":float,"a":…,"b":…}` / `{"w":window_id}` / `null`, 저장 전 정규화.
- 창별 `window.layout ∈ {tiled, untiled, out}`. tiled = 영역 있음, untiled = 관리 중이나 영역 없음(창 끔, 사용자가 옮긴 창), out = 관리 밖.
- `layout_ver`(u32): 구조 변경 +1, 밀기는 선이 처음 움직일 때와 커밋 때 +1.

## 4. 배치 다시

| 항목 | 규칙 |
|---|---|
| 배치에 드는 창 | 묶이고 켜진 창(최대 4). `?` 큐브·창 끈 큐브의 창은 빠진다 |
| 언제 | 큐브를 놓아 묶음, 팝업에서 고름, 창 켜기, 모양 모드 실행. 내림·해제·닫힘·창 끄기는 접힘(7절)으로 남은 창이 채운다 |
| 모양 | 창 수 템플릿(REQ-006 ①). 1 = 전체, 2 = `V(0.5, 왼, 오)`, 3 = `V(0.5, 왼, H(0.5, 오른위, 오른아래))`, 4 = `V(0.5, H(0.5, 왼위, 왼아래), H(0.5, 오른위, 오른아래))`. 칸은 읽기 순서 [미정 C4: 잠정 = 요구 원문의 템플릿(REQ-006)] |
| 밀어 둔 선 | 묶인 창 수가 바뀌어 배치를 다시 하면 템플릿으로 되돌린다 [미정 C11: 잠정 = 템플릿] |
| 칸 배정 | 담당 큐브가 관측되는 창은 Z 순서대로 그 큐브 중심이 든 칸에 먼저(비어 있을 때). 나머지는 빈 칸을 읽기 순서로(REQ-006 ④) |
| 명령 | 최소화 창은 `restore`, 나머지 `place`. 활성화 안 함 [권장안 U-24]. 숨김 창은 보일 때 `place` 1회 |
| 배치 밖 등록 창 | `minimize`하고 `home` 기록. 제외: 항상 위 창, 관리자 권한 창(`excluded`), 큐브가 놓인 뒤 사용자가 연 새 창(다음 배치 때까지) |
| 최소 크기 실패 | Z 순서 가장 아래 창부터 `untiled`(REQ-006 ⑤) |

- 화면 제어 모드 첫 진입(저장 트리 없음)은 창을 옮기지 않고 패드 지도만 켠다.
- 재정렬 버튼(`layout.rearrange`): 배정 불변, 묶이고 켜진 창을 템플릿으로 다시 놓는다 [권장안 U-39].
- 모드 복귀: 떠날 때 트리 저장, 돌아오면 `restore_saved`. 그사이 닫힌 창은 접고, 새 창은 `out`, 옮겨진 `tiled` 창은 저장 영역으로 `place`(최대화 제외). 합격 ≤ 8 px, 배정 변화 0(REQ-035) [권장안 U-43].
- 서비스 시작: 저장 트리 + 상태기계 대조([03](03-상태기계.md) 15절). 창이 없는 잎은 접는다.

## 5. 점 판정 `pick(P)`

착지 판정과 패드 지도가 같은 함수를 쓴다.

| 순서 | 규칙 | 결과 |
|---|---|---|
| 1 | 점 P를 덮는 보이는 등록 창을 `z` 작은 것(맨 위)부터 본다. 항상 위 창은 건너뛴다 | 첫 창 W |
| 2 | W가 안 묶인 창 | `float(W)` |
| 3 | W가 없거나 묶인 창 | 최소화된 안 묶인 창 가운데 `home`이 P를 덮는 것. 여럿이면 마지막에 최소화된 창 → `home(W′)` |
| 4 | 그것도 없음 | `empty`(팝업) |

- 경계 띠: 큐브 중심 ±8.33 mm 네 점(가로·세로)과 중심의 `pick` 결과가 모두 같지 않으면 띠로 본다 [권장안 U-69] [미정 S4].
- 보호 창 이관은 영역 기준이다: `candidate(tree, xy)`가 보호 창 영역을 주면(중심 깊이 ≥ 8.33 mm) 이관.
- 깊이 = 안쪽 경계선까지 최단 거리(mm). 패드 바깥 변은 경계선이 아니다. 후보가 없으면 직전 후보 유지, 전환에 16.67 mm.

## 6. 밀기(REQ-007)

| 항목 | 규칙 |
|---|---|
| 밀 수 있는 큐브 | 놓임 ∧ 가동 ∧ 창 `tiled` ∧ 중심이 자기 영역 안. 남의 영역 위 큐브는 밀지 않는다 |
| 입력 | 상태기계의 `motion{cube, still\|moving, rest_xy, xy3}`·`push_end{cube, cause}`만. 엔진 자체 필터·문턱 없음 |
| 시작 | moving 시작 ∧ `rest_xy`가 자기 영역 안쪽 경계선에서 19.5 mm 안 ∧ `rest_xy → xy3`의 경계 법선 성분 ≥ 3 mm ∧ 중심이 자기 영역 안. 그 선을 잠그고 `link_ver`를 기록 |
| 구석 | 두 선이 모두 맞으면 `rest_xy`에서 10 mm 움직이는 동안 더 많이 움직인 축의 선 하나. 정하기 전엔 선을 움직이지 않는다 |
| 경쟁 | 같은 선에 세션이 있으면 시작 안 함(먼저 민 큐브 우선, 뒤 큐브는 막는 큐브). 다른 선 동시 밀기는 프레임마다 작은 슬롯부터 계산 |
| 선 위치 | `L = clamp(max(L0, 앞면), 범위, 막힘)`, 앞면 = `xy3` + 17.5 mm(미는 방향). 몸체 앞면이 선을 넘을 때만 움직인다 |
| 범위 | 그 선에 닿은 잎 모두가 최소 크기를 지키는 구간(`feasible`) |
| 막힘 | 미는 방향 앞, 선 길이(양 끝 ±17.5 mm) 안 다른 놓임 큐브의 중심 − CLEAR 17.5 mm [권장안 U-71]. 막는 큐브 = 놓임 큐브 전부(배정 무관). 재인식 대기·끊김 큐브는 위치를 몰라 못 막는다 |
| 한계 표시 | 앞면이 선을 2 mm 넘게 지나 있는 동안 이음매 빨강 점멸. 막힘이면 막은 큐브 둘레도 빨강 점멸 [실측 필요] X8-P |
| 끝 | `push_end`(still·CONTACT UP·광학 소실·link_down·모드 전환·세션 끊김), `link_ver` 변화, 다른 구조 변경 커밋, 중심이 선을 넘음(남의 영역 위, 연결 유지) 중 먼저. 선을 커밋하고 확정 적용 1회. 다시 인식돼도 이어 가지 않는다 |
| 갱신 | 프레임마다 그 선에 닿은 창만 한 묶음. 최대화 이웃 창엔 안 보내고 보통으로 돌아올 때 1회 |
| 당기기 | 없음 [권장안 U-68]. 줄이는 길: 이웃의 반대 밀기, 마우스로 가장자리 끌기, 재정렬. 바깥 변 쪽 밀기는 무반응 |
| 반응 | 관측 수신 → 명령 발행 p95 ≤ 20 ms, 멈춘 순간 → 창 경계 최종 위치 p95 ≤ 200 ms(REQ-050) [권장안 U-44] |

```text
on_motion(m):
  if 세션 없음: 시작 조건이면 선 잠금, s = {L0, link_ver, moved:false}; 아니면 return
  if link_ver != s.link_ver or 다른 구조 변경 커밋: 세션 끝
  front = (m.xy3 + 17.5) / S                      # S = 그 축 패드 길이(mm)
  blk   = min((o.c − CLEAR)/S for o in 놓임 큐브 if o가 선 앞 and o 수직 좌표 ∈ [선 시작 − 17.5, 선 끝 + 17.5])
  new   = max(s.L0, min(front, feasible(node).hi, blk))
  if new != node.pos and not s.moved: layout_ver += 1; s.moved = true
  node.pos = new
  limit = (front − node.pos) × S > 2
  if m.xy3 / S > node.pos: 세션 끝(남의 영역 위)
```

## 7. 접힘

- 잎을 빼고 형제 부분 트리가 부모 사각형을 차지한다. 빠진 선에 닿은 잎만 넓어진다. 끝나면 정규화.

| 사건 | 창 | 트리·관리 |
|---|---|---|
| 내림, 배정 해제, 창 끄기 | 최소화, `home` 기록 | 접힘, `untiled` |
| 창 닫힘 | 없음 | 접힘, 관리에서 삭제 |
| 끊김 미배정 | 그대로 | 그대로, 다음 배치 때 빠짐 [미정 C10] |
| 보호 부재, 사용자 최소화·최대화·숨김 | 그대로 | 그대로 |

- 창 1개가 접히면 트리가 빈다(테두리 꺼짐). 접힌 영역 위 다른 큐브는 넓어진 이웃 위가 된다.

## 8. 최소 크기와 재계획

- 영역 최소 폭·높이 = max(앱 최소 px, A_mm). A_mm = 큐브 한 변 + 2 × e95 = 35 + 2 × 5 = 45 mm(1920 × 1032에서 432 × 348 px) [실측 필요] e95.
- 앱 최소 초기값: VS Code 400 × 270 DIP × 배율(세로 패널이면 폭 600 DIP). Edge·메모장은 같은 값 잠정 [실측 필요] W-T6. 잠정값만으로 템플릿을 거부하지 않는다.
- 최소 크기 표 `minsize{app_id, dpi, w_px, h_px, source: init|measured|learned}`. `clamped`면 max(기존, 실제)로 갱신.
- `replan()`: 모든 선을 `feasible` 안으로 뿌리부터 최대 4번 조인다. 그래도 어기면 `z`가 가장 큰(맨 아래) 창을 `untiled`로.
- 모니터 1대, 해상도·배율 한 쌍 고정(1080p면 100 %) [권장안 U-26].

## 9. 어댑터 결과와 외부 변경

| 판정값 | 반응 |
|---|---|
| `ok`·`deferred`·`superseded` | 없음 |
| `clamped` | 최소 크기 표 갱신 → `replan` |
| `mismatch` | `replan` 1회. 같은 창 연속 2회면 한계 표시, 다음 구조 변경까지 그 창에 안 보냄 |
| `uncertain` | 재시도 없음, "응답 없음" 알림, `late_apply`로 해제 |
| `rejected(stale_handle·elevated·access_denied)` | 창 닫힘과 같게(상태기계가 처리) |

- 버리는 옛 결과는 형상 결과뿐이다(창마다 마지막 `cmd_id`보다 오래된 것). 사실 보고는 버전과 무관하다.
- 최대화 창엔 선 이동·접힘·재계획 명령을 보내지 않는다. 배치 다시·재정렬은 `place`로 푼다.
- 외부 변경(REQ-031, K3). 원인이 아니라 새 상태·이전 상태·8 px 넘게 바뀐 변으로 판단. state normal이고 새 사각형이 마지막 계획과 8 px 안이면 늦은 자기 명령으로 무시.

| 변화 | 반응 |
|---|---|
| 바뀐 변이 모두 트리 선 위(가장자리 끌기) | 선을 새 위치로, 최소 크기로만 조임(큐브를 지나가도 됨). `layout_ver` +1 |
| 바깥 변 변경, 이동, 스냅 | 배치에서 뺌: 접힘, `untiled`, 배정 유지 [권장안 U-41] |
| 최대화 / 해제 | 영역 유지 / 지금 영역과 8 px 넘게 다르면 `place` 1회 |
| 사용자 최소화·복원·숨김 | 영역 유지 |

- K3를 끄면(`k3: false`) 엔진은 외부 변경을 모르고 다음 명령이 되돌린다.
- AI 모드 동안에는 닫힘·열림만 반영하고 돌아올 때 맞춘다.

## 10. 패드 지도

안 묶인 창을 모니터 위치 그대로 패드 칸에 앱 대표색으로 칠한다.

| 항목 | 규칙 |
|---|---|
| 칸 | LED 24 × 16, 칸 중심 `(8.33 × (i + 0.5), 8.33 × (k + 0.5))` mm를 2절 식으로 점 P로 바꿈 |
| 칸 색 | `pick(P)`가 `float(W)`면 W의 앱 대표색 × 알파 0.25, `home(W′)`면 W′의 대표색 × 알파 0.10, `empty`면 끔 |
| 그리지 않음 | 묶인 창(창 테두리·큐브 표시가 대신 함), 항상 위 창, 관리자 권한 창 |
| 켜는 때 | 안 묶인 창이 하나라도 있으면 늘 |
| 다시 계산 | 창 목록이 바뀔 때(새 창·이동·도킹·최소화·닫힘·묶기). 배정은 바꾸지 않는다 |
| 출력 | 칸마다 `{rgb, alpha}`. 층 합성과 우선순위는 [05 표시](05-표시.md) 2절 |

- 새 창·이동을 따라가려고 어댑터 `enumerate`를 주기적으로 부른다 [미정 C9: 잠정 = 주기 열거로 지도만 갱신]. 주기는 상태 폴링과 같은 250 ms로 둔다.
- 앱 대표색 값과 알파의 코드값 환산은 정해지지 않았다 [미정 C7]. 이 문서 안: 등록 앱마다 대표색 1개를 등록 표에 두고, 칸 값 = 대표색 × 알파(코드값 0~255).
- 모니터는 1대다. 모니터 전환 기능은 없다.
