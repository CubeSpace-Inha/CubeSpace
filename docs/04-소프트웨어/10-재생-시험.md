# 재생·시뮬레이터와 시험

이 문서로 답하는 것: 하드웨어 없이 어떻게 입력을 만들고 기록을 다시 돌리나, 모듈마다 무엇을 어떻게 시험하고 무엇이 통과면 구현이 끝났다고 보나.

관련: [01 구성](01-구성.md) · [02 게이트웨이·좌표](02-게이트웨이-좌표.md) · [03 상태기계](03-상태기계.md) · [04 배치 엔진](04-배치-엔진.md) · [시험 벡터](../03-인터페이스/04-시험-벡터.md)

## 1. 입력원

| 항목 | 규칙 |
|---|---|
| 선택 | 시작 인자 `--source=pad\|sim\|csv:<포트>\|csvfile:<파일>`. 사건 기록에 `src`를 남긴다 |
| 시뮬레이터(`sim`) | 좌표가 아니라 OBS 광학 원시 창(`obs.window`)을 만든다. 실물과 같은 게이트웨이·estimate 경로를 탄다. 빛 모형·`cal-sim.json`·정상 가정은 [시험 벡터](../03-인터페이스/04-시험-벡터.md) 가상 광학 |
| 장면 시나리오 파일 | 놓기·밀기·들기·버튼·끊김을 시간순 사건으로 적은 파일. 시뮬레이터가 읽는다. 형식은 [미정: 시뮬레이터를 만들 때 정한다] |
| CSV | 패드 시험 펌웨어 CSV(77센서)를 5 × 5 창으로 바꿔 넣는다. 새 USB 메시지 없음 |
| 모의 표시 | 모의 입력을 하나라도 섞으면 동반 앱 상단에 [모의]. 모의 통과는 지표·실물 시험 합격 근거가 아니다(REQ-055) |
| 시연 대체 | 패드 무반응이면 `--source=sim`(DB 유지)로 다시 시작, 남은 장면 15 s 안 [권장안 U-93] |

## 2. 기록 재생

| 층 | 다시 넣는 것 | 쓰임 |
|---|---|---|
| L0 선로 | USB 바이트(`records\` `rx`) | 게이트웨이 시험 |
| L1 프레임 | 디코드한 프레임 | 세션·순번 규칙 |
| L2 광학 창 | OBS 원시 창. 좌표는 재생 때 estimate가 다시 계산 [권장안 U-32] | 추정기 바꾼 뒤 비교 |
| L3 사건 | 상태기계 입력 사건 JSONL | 상태기계·엔진 결정론 |

- 시계: 게이트웨이는 `onFrame(buf, t_pc_us)`의 `t_pc_us`만, `step`은 사건의 `t`만 쓴다. 재생은 원래 시각 또는 가상 시계로 돌린다.
- `cube-replay`는 실물과 같은 순수 모듈(`src/core`)을 쓰고 Electron 없이 Node에서 돈다.
- 공개(K7): `cube-events`·`cube-replay`와 합성 기록만 MIT로 공개한다(REQ-060).

## 3. 장애 주입(F01~F16)

Vitest에서 시나리오로 넣고 기대 결과와 비교한다. 층은 2절(L0~L3). F06~F10 입력 창은 시뮬레이터가 만든 기록이나 실물 기록을 변조한 것이라 둘 다 [모의]다.

| ID | 주입 | 기대 |
|---|---|---|
| F01 | L0: 바이트 변조 0.1 %, ROM 부팅 문구 끼우기 | 틀린 프레임 수용 0, 다음 프레임부터 정상 |
| F02 | L1: 프레임 1·5 % 버림, 중복, 50 ms 안 순서 바꿈 | 틈 수 = 버린 수, 옛 것 버림 |
| F03 | L1: 2 s 멈춘 뒤 몰아 보내기(`t_pc_rx`를 2 s 밂) | 나이 100 ms 넘은 OBS가 상태기계로 안 감 |
| F04·F05 | L1: 패드 재부팅, USB 끊김 | 판정 동결, 유예 뒤 재평가, 배정 변화 0 |
| F06 | L2: 센서 포화 | 확정 판정 0 |
| F07 | L2: 신뢰도 저하(창 잡음 σ 20 mV, 이득 ±30 %) | `conf` 낮음 → 확정 판정 0, 재인식 안내 |
| F08 | L3: 다섯 번째 큐브 | 흰 점멸, 기존 배정 불변 |
| F09·F10 | L2: 큐브 ID 교환, 한 프레임 30 mm 넘는 이동 | 관측 버림, 잘못된 배정 0 |
| F11 | L3: 접촉 DOWN + 광학 없음 | 가장자리 띠 밖이면 재인식 대기, 최소화 0 |
| F12 | L3: S1 사건 유실 | 광학 소실만으로 재인식 대기, 내림 판정은 규칙표대로 |
| F13 | L3: 모드 전환 중 제거 | 최소화 0 |
| F14 | L1: 큐브 재부팅(LINK down 0x11 → up, 새 `cube_boot_id`) | `cube.rebooted` 1번, ICON 다시 보냄, 배정은 [03 상태기계](03-상태기계.md)의 새 boot 규칙대로 |
| F15 | L1: 연결 한도(등록 6 + 미등록 광고 1, 합성 CAND) | 미등록 연결 0, 등록 모드 밖 후보 알림 0 |
| F16 | L3: AI 실행 중 명세 큐브 제거 | 실행 계속, 회색 점멸 |

## 4. 모듈별 시험 방법

시험 러너는 Vitest 하나다. 순수 함수는 직접, 컴포넌트는 Testing Library(jsdom)로 본다. 난수는 씨앗 PRNG(mulberry32). CubeSpace-Client에서는 `pnpm check`(lint · typecheck · test)로 한 번에 돌린다.

| 모듈 | 방법 | 합격 |
|---|---|---|
| estimate | [시험 벡터](../03-인터페이스/04-시험-벡터.md), 시험 벡터 부록의 `estimate()`와 같은 창·같은 표로 비교(가장자리·모서리 포함) | 좌표 차 ≤ 0.01 mm |
| gateway | 시험 벡터(정상·잘린 프레임·순번 역행·boot 바뀜·나이 초과·판 불일치) | 사건 열 일치 |
| cube-events | X3-S: 전이표 모든 칸, 시나리오(아래 5절), fuzz(씨앗 고정 10,000 × 60 조작) | 불변식 I1~I10 위반 0, 기대 명령 일치 |
| engine | X8-S: 속성 시험 10,000 × 60, 입구 JSON Schema, SQLite 왕복. X8-G: 비율 반례, 접힘, 템플릿 1~4, 경계 깊이, 정지 떨림(σ 1 mm 60 s → 선 이동 ≤ 1 mm), 정규화 이력, 숨김 창, 점 판정·지도 | E1~E9 위반 0, 기대 트리·명령 일치, 왕복 바이트 같음, `k3 = false`도 |
| 서비스 셸 | 07-T2: 10분 기록 두 번 재생, 커밋 실패 주입 10회 | 명령 목록 바이트 동일, 실패 때 명령 0 |
| 표시 렌더러 | 우선순위, ≤ 20 fps, 정상 둘레 점등 0, 지도(묶인 창·항상 위 창 제외, 두 알파), 흐름 사건당 1번, 패드 밖 표시 0, 잔량 3단계, 아이콘 규칙(`?`·✕ 포함), 10 s 뒤 어두운 ICON 1번 | 기대 프레임·ICON 일치 |
| 어댑터 순수부 | `judge` 판정표 모든 줄, `uncertain(timeout)` 경로, 키 비교 | 일치 |
| AI 조정 | 모의 실행기 시나리오(정상 30, 오류 15), 중복·복구·대기·한도, 금지 인자 대조 | 30/30, 15/15, 중복 0, 자동 재실행 0, 금지 인자 0 |
| IPC·보안 | `ipc-check`(다른 origin, 목록 밖, 64 KiB 초과, BigInt·순환, 스키마 밖 필드), `resolveAppPath`(`..`, `%2e%2e`, 빈 경로, 절대 경로, 잘못된 인코딩), 금지 문자열 grep | 모두 거부, 정상 200 |
| 렌더러 화면 | 상태 함수 단위 시험, Playwright 스모크 UI-S1~S4 | 기대 표시 |

- 결정론: 같은 입력 열을 두 번 넣으면 `commands`가 바이트까지 같아야 한다(REQ-055).
- CI는 저장소마다 둔다: CubeSpace-Client는 push·pull_request마다 `pnpm check`, 창 어댑터(C#) 시험은 CubeSpace-Program-Win32, 펌웨어 호스트 시험은 CubeSpace-Firmware에서 돈다. Windows 전용 시험(W-T, AI-T, S-N1)은 CI 밖.

## 5. 묶기 재설계 확인 시나리오

X3-S·X8-G 시나리오로 넣는다.

| # | 입력 | 기대 |
|---|---|---|
| 1 | 창 4개가 떠 있을 때 큐브를 한 창 위에 놓음 | 그 창이 묶이고 나머지 3개는 최소화, `home` 남음 |
| 2 | 최소화 창의 `home` 자리에 두 번째 큐브를 놓음 | 그 창이 올라와 묶임, 화면 둘로 나뉨 |
| 3 | 빈 곳 또는 이미 묶인 창 자리에 놓음 | 팝업 열림. Esc면 큐브 `?`. 다른 창이 묶이지 않음 |
| 4 | `?` 큐브 버튼 짧게 | 팝업 맨 위 = `lastProgram`. 다시 짧게면 그것이 묶임 |
| 5 | 묶인 창을 닫음 | 큐브 `?`, 팝업 없음, 남은 창으로 다시 배치 |
| 6 | 큐브가 놓인 채 창을 열거나 도킹 | 배치 그대로, 지도 칸만 바뀜 |
| 7 | 큐브를 내림 | 그 창 최소화. T_lift 안에 다시 놓으면 최소화 없음 |
| 8 | 겹친 자리에 놓음 / 항상 위 창 위에 놓음 | `z` 가장 작은(맨 위) 창이 묶임 / 그 아래 창이 묶이고 항상 위 창은 지도에 없음 |
| 9 | 모양 모드 모양 완성 | 이미 떠 있는 프로그램은 다시 실행하지 않고, 지도대로 묶인 큐브는 모드 구성으로 바뀜 [미정 C2] |
| 10 | PC 다시 켜기 | 모양이면 모양 모드 프로그램이 열려 묶임. 설정을 끄거나 모양이 아니면 모든 큐브 `?` |
| 11 | 지도 두 창 경계에서 8.33 mm 안에 놓음 | 흰 점멸 1.5 s, 배정 없음 |
| 12 | 활성 4개일 때 다섯 번째 큐브를 빈 곳에 놓음 | 흰 점멸, 팝업 없음 [미정 C15] |
| 13 | 보호 창 위에 미배정 큐브를 놓음 | 팝업이 아니라 이관 |

## 7. 시험 ID 정의

- 이름: T n = 패드 시험 PT-n, C n = 큐브 시험 CT-n([하드웨어 05](../01-하드웨어/05-제작-시험-실측값.md)). X1·X2·F05-n은 펌웨어(장애 주입 F05와 다르다)([펌웨어 05](../02-펌웨어/05-선개발-시험.md) 3절), 광학 측정·보정은 [펌웨어 06](../02-펌웨어/06-광학-보정.md). F는 3절, 07-T는 4·6절이다.
- 아래는 소프트웨어 문서가 쓰는데 다른 곳에 정의가 없는 ID다. X3 = 상태기계, X8 = 배치 엔진, W-T = 창 어댑터, S = 통신·보안, AI-T = AI 실물, AI-M = AI 모의, UI-S = 화면 스모크.
- W-T1·W-T5·W-T6은 한 스크립트로 시연 배율 1개에서 한다. W-T·AI-T·S-E2는 Windows PC에서, CI 밖이다.

| ID | 조건 | 합격 | 미달이면 |
|---|---|---|---|
| X3-H | 사람 들기 시간. 팀원 3명 × (짧은 들기 10 + 영역 사이 60~120 mm 들어 옮기기 10 + 치우기 10) = 90회, 35 mm 모형 블록, 휴대폰 240 fps. 외부 참가자는 IRB 답 뒤 | 짧은 들기 30개의 최대(과소추정 가능) ≤ 0.40 s면 T_lift 0.5 s 유지 | 0.40~0.45 s면 짧은 들기 100회를 더 모아 3번째 큰 값으로 다시 판단. 0.45 s를 넘으면 T_lift 0.6 s [권장안 U-94] |
| X3-E | 가장자리·포화(실물). 네 변 밀어내기 각 5 + 끝에 닿아 정지한 자리에서 밀어내기 5. 띠 안(끝에서 20 mm) 정지 큐브에 가림·강한 빛·급락·무선 끊김 2.5 s·동기 이탈 각 5, 가운데 가림 10.
