# 게이트웨이와 좌표 추정

이 문서로 답하는 것: `gateway`는 USB 바이트를 어떤 규칙으로 사건으로 바꾸고 시각을 어떻게 맞추나, `estimate`는 광학 원시 창을 어떻게 mm 좌표로 바꾸고 언제 판정을 보류하나.

관련: [01 구성](01-구성.md) · [03 상태기계](03-상태기계.md) · [USB 인터페이스](../03-인터페이스/02-USB.md) · [PC 내부 인터페이스](../03-인터페이스/03-PC-내부.md) · [시험 벡터](../03-인터페이스/04-시험-벡터.md)

## 1. gateway 경계

- 순수 코어. 입력은 네 함수뿐이다: `onFrame(buf, t_pc_us)`, `onBad(...)`, `onPort(event, t_pc_us)`, `onTick(t_pc_us)`. 안에서 시계를 읽지 않는다. 출력은 내부 사건 목록과 송신할 프레임 목록이다.
- 포트 입출력은 main이 한다: `new SerialPort({ path, baudRate: 115200, hupcl: false, rtscts: false })`(DTR·RTS 0, 리셋 회피). 찾기는 VID 303A·PID 1001, 지난번 `serialNumber`부터, 1500 ms 안 패드 HELLO.
- 바이트 형식·메시지 목록은 [USB 2](../03-인터페이스/02-USB.md), 판 불일치·값 검사는 [USB 7](../03-인터페이스/02-USB.md)이다. 이 문서는 동작만 적는다.
- 패드 하나만 쓴다. 두 번째 패드가 붙으면 등록된 패드만 쓰고 "패드는 하나만 연결하세요"를 알린다(REQ-065).

## 2. 세션 규칙 요지

세부(스냅샷 순서, 재시도 간격)는 [USB 6](../03-인터페이스/02-USB.md).

| 규칙 | 동작 |
|---|---|
| G1 열기 | 동기 바이트 먼저, PC HELLO 500 ms마다, 패드 HELLO 전 프레임은 버림. HELLO~첫 STATUS 사이의 LINK·EVT는 `pad.session.snapshot`에 담는다 |
| G2 재부팅 | HELLO `boot`가 직전과 같으면 `up`, 다르면 `rebooted`. 마지막 `pad_boot_id`는 저장소에 둔다. 세션 중 머리 `boot`가 바뀌어도 `rebooted` → G1 |
| G3 순번 | 같은 `boot`에서 `seq ≤ 마지막`이면 버림. 건너뛴 수는 틈으로 센다 |
| G4 나이 | 4절 |
| G5 큐브 중복 | 슬롯마다 `(cube_boot_id, seq)`. boot가 다르면 `cube.rebooted`. 같으면 `(seq − 마지막) mod 65536`이 1~32767일 때만 받는다. 표는 패드 재부팅에도 유지, 게이트웨이 재시작 때 비움 |
| G6 끊김 사유 | 1 `dock`, 2 `button`, 3 `low_batt`, 0x10 `timeout`, 0x11 `stale`, 0x12 `local` |
| G7 부재 | 포트 `close`·`error` 또는 유효 패드 프레임 1500 ms 없음 → `lost`, 1000 ms마다 다시 찾음. 같은 boot에서 프레임 `t_us` 틈 > 1 s도 `lost` 다음 `up` |
| G8 다시 보냄 | 패드 HELLO 뒤 REG → 현재 LED. LINK `up=1`마다 그 슬롯 ICON |

- `lost` 동안 상태기계는 판정을 동결한다. 복귀 유예는 같은 boot 2 s, 다르거나 모르면 20 s [권장안 U-33]. 유예 처리는 [03 상태기계](03-상태기계.md) 15절.
- USB를 뽑으면 패드가 꺼지므로 늘 `lost` → `rebooted` 순서로 온다.
- 송신: LED는 대기 칸 1개를 덮어쓰고 `frame_us` 틱마다, 바뀌었고 `port.writableLength < 4096`일 때만 보낸다(≤ 20 fps). ICON은 슬롯마다 미결 1개.

## 3. 시각 변환

| 단계 | 규칙 |
|---|---|
| 32비트 패드 시각 복원 | [USB 5](../03-인터페이스/02-USB.md)의 대칭식. 무효값이면 머리 `t_us`를 쓰고 `t_valid = false` |
| 패드 → PC 오프셋 | 첫 표본 `off = t_pc_rx − t_us`. 이후 `off = min(off + (t_pc_rx − t_prev) × 100e-6, t_pc_rx − t_us)`. 새 `pad_boot_id`면 다시 시작 |
| "지금" | 마지막 패드 프레임 머리 `t_us`. 판정 시각은 모두 패드 시각이다. PC 시계는 표시·지연 측정에만 쓴다 |
| 사건 시각 | 패드에서 온 사건에 그 메시지 머리 `t_us`를 `t_pad_us`로, 모든 사건에 입력원 `src`를 붙인다. `cube.evt`는 복원한 사건 시각 |

- 접촉과 광학의 앞뒤는 `cube.evt.t_pad_us`와 `obs.t_pad_us`로 가린다. 게이트웨이는 도착 순서대로 넘긴다.

## 4. 나이 거르기와 값 검사

- `age = t_pc_rx − (t_us + off)`. `age > 100 ms`인 OBS는 상태기계로 보내지 않고 `obs_stale`을 1 올린다. 원시 기록에는 남긴다.
- EVT·LINK·STATUS·ACK·CAND는 나이와 무관하게 넘긴다.
- 버린 OBS는 상태기계의 연속 프레임 계수를 끊는다(`frame_no` 차로 셈).
- 값 검사([USB 7](../03-인터페이스/02-USB.md))에 어긋난 프레임은 버리고 `bad`로 기록한다. 예: OBS `h·w ≤ 21`, 가운데 열 밖 `|v| ≤ 3300 mV`.

## 5. estimate 함수

```text
estimate(obs, cal) -> { valid, x, y, conf, edge, vmax, sum }
  obs : { slot, frame_no, st, r0, c0, h, w, v[h*w] }   mV 차분, INT16_MIN = 값 없음
  cal : { gain[7][11], bad, curve{u[401], t[401], edge_u[401], edge_t[401]}, offset_mm, th_on_mv[6] }
  상태·필터 없음. 같은 입력이면 같은 출력
```

| 단계 | 규칙 |
|---|---|
| 1 | `h·w = 0`이거나 광학 상태 ≠ ON_PAD → `{valid: false, conf: 0}`. SAT면 좌표는 구하되 `conf = 0` |
| 2 | `v′ = v / g`. `bad` 센서는 같은 행 창 안 이웃 평균으로 채운다(없으면 0) |
| 3 | 발견 OBS(`h = 7`, [USB 3](../03-인터페이스/02-USB.md))면 `INT16_MIN` 칸을 뺀 최대 센서 좌표, `conf = 0.1`로 끝 |
| 4 | 창 안 최댓값 `(r*, c*)`. 축마다 쓸 줄을 고른다. 최댓값이 격자 끝 줄(행 0·6, 열 0·10)이면 있는 두 줄(끝 줄 + 안쪽 한 줄)만 쓰고 중심은 끝 줄이다(10/11 사용자 결정: 가장자리는 있는 센서로만). 아니면 중심을 창 안쪽으로 민 세 줄이다: `r_c = clamp(r*, r0 + 1, r0 + h − 2)`, `c_c = clamp(c*, c0 + 1, c0 + w − 2)`. 창 밖·격자 밖 칸은 0으로 채우지 않는다(창 밖을 0으로 채우면 100 mm/s에서 p95 4.8 mm [모형]). 고른 칸(3 × 3, 가장자리 2 × 3, 모서리 2 × 2)에서 음수는 0, `S` = 합. 세 줄 축 `u = (다음 줄 − 앞 줄)/S`(x는 오른쪽 − 왼쪽, y는 아래 − 위), 두 줄 축 `u = 안쪽 줄/S` |
| 5 | 세 줄 축 `t = interp(u, curve.u, curve.t)`, −1~1로 자름. 두 줄 축 `t = ±interp(u, curve.edge_u, curve.edge_t)`, 0~1로 자르고 부호는 안쪽(행·열 0이면 +, 6·10이면 −). 두 표 모두 x·y 공용 401점 단조. 기준 구현은 [시험 벡터 부록](../03-인터페이스/04-시험-벡터.md)의 `estimate()` |
| 6 | `x_p = SX[c_c] + (50/3)·t_x + dx`, `y_p = SY[r_c] + (50/3)·t_y + dy`. `SX = 33.67 + (50/3)c`, `SY = 33.5 + (50/3)r`. LED 영역 좌표 `x = x_p − 17.00`, `y = y_p − 16.83`, 0~200 × 0~133.33으로 자름 |
| 7 | `conf = clamp((V′max − TH_ON)/TH_ON, 0, 1)`. 상한: SAT 0, 채운 센서가 고른 칸 안이면 0.4, 발견 0.1. `edge = r* ∈ {0,6} ∨ c* ∈ {0,10}` |

- 출력 좌표: 패드 LED 영역 왼쪽 위 원점, x 오른쪽 0~200 mm, y 아래 0~133.33 mm, float, 큐브마다 20 Hz(REQ-003).
- 필터는 estimate에 없다. 3프레임 평균·정지 판정은 상태기계가 한다([03 상태기계](03-상태기계.md) 5.3절).
- 게이트웨이·시뮬레이터·재생·CSV 입력이 같은 함수를 쓴다.
- 좌표를 PC에서 계산한다 [권장안 U-32].

## 6. 보정 파일

- `cal-<패드 serialNumber>.json`(`ver` 2). estimate가 읽는 칸: `gain[7][11]`(이득, 77개 중앙값 = 1), `bad`, `curve{m, sigma, h, u[401], t[401], edge_u[401], edge_t[401]}`(두 표 모두 맞춘 (m, σ)의 모형에서 만든다: `curve()`·`curve_edge()`), `offset_mm`, `th_on_mv[6]`. 그 밖 칸(`fw`, `optics`, `adc`, `v_ref_mv`, `f_c`, `k_on`, `cube_gain[6]`, `k_cube`, `k_t`, `pos_cal`)은 기록·검사용.
- 파일 SHA-256을 측정 설정 해시 `meas_id`에 넣는다([10 재생·시험](10-재생-시험.md)).
- HELLO `fw` ≠ `cal.fw`면 동반 앱에 경고한다(REQ-003).
- 1점 확인: 교정 화면에서 확인점 오차 ≤ 1.0 mm. 넘으면 안착을 고쳐 1회 더, 또 넘으면 GAIN-CAL 77 + POS-CAL 26 + 재빌드를 안내한다 [권장안 U-23].
- 보정 무효: 센서·기둥·상판·테이프·RL·CF·R1 변경, 1점 재확인 불합격, `bad` 센서 교체. 큐브 LED 교체는 그 슬롯 `cube_gain`만 다시 잰다.

## 7. 판정 보류

| 조건 | 처리(REQ-021) |
|---|---|
| SAT | `conf = 0`. 배정·이관·내림 같은 확정 판정에 쓰지 않음 |
| `conf < 0.5` | 놓임 에지 판정·밀기에 쓰지 않음. 마지막 안정 상태 유지 |
| `sync_fault` | 패드가 CFG를 다시 쓰고 큐브가 재예열(약 3 s). PC는 재인식 대기, 판정 안 함 |
| 정지 중 광학 소실 | `edge_out`이 아니면 재인식 대기. 광학 소실만으로 내리지 않음 |
| 한 프레임 이동 > 30 mm | 그 관측을 버림(장애 주입 F10의 타당성 문턱) |

- `conf < 0.5` 관측은 연속 프레임 계수를 끊는 것으로만 다룬다. 그것만으로 상태를 바꾸지 않는다.
- `edge_out` = 소실 직전 4프레임 모두 `edge = 1` ∧ `vmax` 단조 감소.
