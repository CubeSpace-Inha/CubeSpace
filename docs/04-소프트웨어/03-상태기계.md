# 상태기계(cube-events)

이 문서로 답하는 것: 큐브 사건 하나를 받아 어떤 상태로 바꾸고 어떤 명령을 내나. 큐브를 놓으면 무엇을 묶고, 내리면·끊기면·버튼을 누르면 어떻게 되나(큐브↔창 묶기 재설계 기준).

관련: [01 구성](01-구성.md) · [02 게이트웨이·좌표](02-게이트웨이-좌표.md) · [04 배치 엔진](04-배치-엔진.md) · [05 표시](05-표시.md) · [06 창 어댑터](06-창-어댑터.md) · [PC 내부 1 내부 사건](../03-인터페이스/03-PC-내부.md)

## 1. 역할

- `step(state, event) → { state', commands[] }`. 순수 함수다. 벽시계·난수·파일·DB·IPC를 쓰지 않는다. 부수 효과는 모두 `commands`로 내고 서비스 셸이 실행한다.
- 맡는 것: 존재 사건 조합, 큐브 상태 전이, 놓임 에지 판정(묶을 대상 고르기), 선택 팝업 진행, 내림·배정 해제, 버튼, 끊김·BYE·새 boot, 교체 보호, 세션·모드 재평가, AI 후보, 창 사건 반영, 위치 필터·밀기 신호, 가장자리 경고.
- 맡지 않는 것: 좌표 추정(estimate), USB·세션 감지(gateway), 영역 기하·점 판정·지도·선 이동(engine), 창 호출(어댑터), AI 단계(AI 조정), LED 그리기(표시 렌더러).
- engine 함수는 `step` 안에서 부른다. engine 출력(적용 묶음)은 `commands`에 담겨 커밋 뒤 어댑터로 간다.
- 화면 제어 모드와 AI 모드의 상태를 큐브마다 따로 둔다.

## 2. 시계와 타이머

- 지금 = 마지막으로 처리한 패드 메시지 머리의 `t_pad_us`. `obs`·`contact`는 자기 `t_pad_us`(접촉 시각 무효면 머리 `t_us`).
- PC 쪽 사건(app·window)의 시각 = 적용 순간의 지금 + `pc_seq`(순서용).
- 패드 세션이 끊긴 동안 지금은 멈춘다.
- 타이머 = 상태 안의 마감 시각. 패드 메시지마다 마감 ≤ 지금인 것을 (마감, 슬롯) 순으로 발화한다. `setTimeout`·틱 메시지를 쓰지 않는다. 분해능 50 ms(링크가 0개면 STATUS 500 ms).
- 연속 프레임은 `frame_no` 차로 센다. 게이트웨이가 버린 OBS와 `conf < 0.5` 관측은 연속을 끊는다.

## 3. 서비스 셸과 트랜잭션

배정·보호·창 연결을 바꾸는 사건 하나 = SQLite 트랜잭션 하나(REQ-036).

| 순서 | 동작 |
|---|---|
| 1 | 사건을 JSONL에 남기고 `step(state, event)` → `state'`, `commands` |
| 2 | 첫째 명령 `db`를 `BEGIN … COMMIT`. DB 안에서 선행 조건을 다시 보지 않는다. `BEGIN IMMEDIATE` 안 씀 |
| 3 | 성공 → `state ← state'`, 나머지 명령(창·표시·알림) 실행 |
| 4 | 실패(SQLITE_BUSY·입출력) → `state'` 버림, 명령 0, 같은 사건 1회 재시도. 또 실패면 세션 끊김처럼 동결 + 저장 오류 알림. 복구는 서비스 재시작 |

- 창 명령이 실패해도 상태를 되돌리지 않는다.
- SQLite: WAL, `synchronous=NORMAL`, `busy_timeout=1000`. 쓰기 연결은 셸 하나, 동반 앱·로그는 읽기만.
- `link_ver`(u32)는 이 모듈이 배정·이관·미배정·보호 켜기·끄기마다 +1. `layout_ver`는 engine만 올린다.
- 어댑터 결과(`result`)는 `link_ver`를 싣지 않는다. 셸의 `cmd_id` 장부로 창·명령을 찾는다.

## 4. 용어

| 용어 | 뜻 |
|---|---|
| 연결 | link UP. 켜진 등록 큐브 전부, 최대 6. 발광 슬롯 = 등록 번호 [권장안 U-31] |
| 놓임(`placed`) | link UP ∧ 광학 ON_PAD ∧ 최신 CONTACT(t_pad 기준) DOWN. 다른 모듈은 다시 정의하지 않는다 |
| 놓임 에지 | `n_close`(부팅 뒤 S1 열림 → 닫힘 횟수, u16)가 그 boot에서 마지막으로 본 값과 달라짐. 접촉 사건과 스냅샷 가운데 먼저 온 것으로 무장 |
| 묶임 | 화면 제어 모드의 배정(큐브 → 창 1개). 창을 끈 배정 포함 |
| 활성 | 현재 모드의 배정 수. 최대 4(REQ-004) |
| 배치에 드는 창 | 묶이고 켜진 창(최대 4). 나머지 등록 창은 다음 배치 때 최소화 |
| 안 묶인 창 | 담당 큐브가 없는 등록 창. 떠 있음 / 최소화 둘 |
| `home` | 창이 최소화되기 직전의 보이는 사각형(화면 px). 창별로 저장 |
| `lastProgram` | 큐브에 마지막으로 묶였던 프로그램 `{app_id, arg?}`. 큐브별로 저장 |
| 내림 | 배정을 풀고 창을 최소화하고 `home`·`lastProgram`을 남기는 처리(10절) |
| 항상 위 창 | `onTop`. 묶기·배치·최소화·지도에서 모두 뺀다 |

## 5. 입력

### 5.1 사건 종류

형식은 [PC 내부 1](../03-인터페이스/03-PC-내부.md).

| 사건 | 쓰는 값 |
|---|---|
| `obs` | slot, frame_no, t_pad_us, optical, x, y, conf, edge, vmax. sync·sat·sync_fault는 기록만 |
| `contact` | v0 = 접촉 상태, v1 = `n_close`, t_pad_us. 이미 처리한 것보다 이른 옛 CONTACT는 버림 |
| `batt` | mV(직전 1 s 평균, 10 s마다) |
| `button` | 눌림 시작, 뗌(누른 시간 → 짧게 < 1 s, 길게 1 s~끄기 시간 미만)(REQ-063). 끄기 시간 4 s([펌웨어 02 8절](../02-펌웨어/02-큐브.md)) |
| `link_up` / `link_down` | mac, cube_boot_id, fw, 스냅샷 contact·n_close / reason 1 dock·2 button·3 low_batt·0x10 timeout·0x11 stale·0x12 local |
| `session_lost` / `session_resume` | 동결 / pad_boot_id, 슬롯별 link·reason·cube_boot_id·contact·n_close |
| `tick` | STATUS 시각만 |
| `app` | prot_on, prot_off, release, mode, rearrange, start_run, stop_run, unregister, popup_pick, popup_close |
| `window` | window_closed, window_state, windows(목록: minimized·onTop·z·rect), result, launched, launch_failed |

### 5.2 존재 사건 만들기

한 메시지 안 처리 순서: link → contact → optical → 에지 판정 → 타이머. 같은 시각은 슬롯 오름차순.

| link | 최신 contact | optical(이번 / 직전) | 추가 조건 | 사건 |
|---|---|---|---|---|
| UP | DOWN | ON_PAD | 놓임 거짓 → 참 | `placed` |
| UP | UP이 새로 옴 | 무엇이든 | | `contact_up` |
| UP | DOWN이 새로 옴 | 무엇이든 | 들림 대기면 T_find 한 번 | `contact_down` |
| UP | DOWN | 비ON_PAD / ON_PAD | 마지막 필터 중심이 LED 끝에서 E_edge 안 ∧ (소실 전 1 s 끝 쪽 이동 ≥ 3 mm ∨ `edge_out`) | `lost_band`(들림으로 침) |
| UP | DOWN | 비ON_PAD / ON_PAD | 그 밖 | `lost_mid`(재인식 대기) |
| DOWN | | | 사유 1·2·3 / 0x10~0x12 | `bye1`·`bye2`·`bye3` / `ld` |
| UP(다시) | 스냅샷 | | cube_boot_id 같음 / 다름 | `lu_same` / `lu_new` |

`lost_band`는 K3다. K3를 끄면(`k3: false`) 모든 광학 소실이 `lost_mid`다.

### 5.3 위치 필터·밀기 신호

| 항목 | 규칙 |
|---|---|
| 필터 | `xy3` = 최근 3프레임 평균, `rest_xy` = 마지막 still 구간 10프레임 평균, `pos` = still이면 `rest_xy` 아니면 `xy3` |
| moving / still | `|xy3 − rest_xy| ≥ 3 mm` / 10프레임 동안 이동 < 2 mm |
| `motion` 출력 | `{cube, still|moving, pos, rest_xy, xy3, src{pad_boot_id, frame_no, slot}}`. 밀기 세션 판단은 engine([04](04-배치-엔진.md) 6절) |
| 밀기 시작 후보 | 가동 ∧ 창 `tiled` ∧ 중심이 자기 영역 안 ∧ moving ∧ `rest_xy`가 안쪽 경계에서 19.5 mm 안 ∧ 경계 쪽 성분 ≥ 3 mm(REQ-007) |
| `push_end` | still, CONTACT UP, 광학 소실, link_down, 모드 전환, 세션 끊김 가운데 먼저 |
| 가장자리 경고 | 중심이 LED 끝에서 19 mm 이하 켬, 21 mm 이상 끔 [권장안 U-70] → `edge_warn{cube, side, on}`(REQ-022) |
| 버튼 중 멈춤 | 눌림 시작부터 뗀 뒤 0.3 s까지 그 큐브의 밀기 시작·내림 판정을 하지 않는다(REQ-063 ④) |

## 6. 큐브 상태(화면 제어 모드)

| 상태 | 배정 | 창 | 타이머 | 사용자에게 보이는 이름 |
|---|---|---|---|---|
| 미배정 U | 없음 | | | 트레이(패드 밖) / `?`(패드 위) / 고르는 중(팝업 열림) |
| 가동 RUN | 묶임 | 켬: `tiled`, 끔: 최소화·`untiled` | | 묶임 / 창 끔 |
| 가동·보호 RUNp | 묶임 | `tiled` | | 묶임(보호) |
| 들림 대기 LIFT | 묶임 | 그대로 | T_lift(T_find로 한 번 연장) | 묶임 |
| 들림 대기·보호 LIFTp | 묶임 | `tiled` | T_lift | 묶임(보호) |
| 재인식 대기 RECOG | 묶임 | 그대로 | 표시 0.3 s, 안내 10 s | 묶임 |
| 재인식 대기·보호 RECOGp | 묶임 | `tiled` | 같음 | 묶임(보호) |
| 끊김 보류 HOLD | 묶임 | 그대로 | T_drop | 묶임 |
| 보호 부재 PABS | 묶임 | `tiled` | | 묶임(보호) |

- 트레이 / `?` / 고르는 중은 미배정의 표시 구분이고 판정 상태가 아니다. 트레이 = 놓임이 아닌 상태가 T_lift 넘게 이어짐. 고르는 중 = 그 큐브의 선택 팝업이 열려 있음(메모리만).
- "창 끔"은 가동 계열 상태에 붙는 표지 `off`다. 배정은 두고 창을 최소화해 배치에서 뺀다 [미정 C10: 잠정 = 배정 + `off` 표지 + `untiled`].
- 옛 "제거됨" 상태는 없다.

## 7. 전이표

`=` 그대로, `·` 정상 세션에서 오지 않음. 결과 이름은 10절 표의 처리다.

| 상태 | contact_up / lost_band | lost_mid | placed | 타이머 | bye1 | bye2·3 | ld | prot_on / prot_off | w_closed | release |
|---|---|---|---|---|---|---|---|---|---|---|
| U | = | = | 에지면 착지 판정(8절) | · | = | = | = | 거부 / · | · | · |
| RUN | LIFT | RECOG | = | · | 내림 | 끊김 미배정 | HOLD | RUNp / · | 닫힘 미배정 | 해제 |
| RUNp | LIFTp | RECOGp | = | · | PABS(치움) | PABS(끊김) | PABS(끊김) | = / RUN | 닫힘 미배정 | 비활성 |
| LIFT | = | = | RUN | T_lift → 내림 | 내림 | 내림 | 내림 | LIFTp / · | 닫힘 미배정 | 해제 |
| LIFTp | = | = | RUNp | T_lift → PABS(치움) | PABS(치움) | PABS(치움) | PABS(치움) | = / LIFT | 닫힘 미배정 | 비활성 |
| RECOG | LIFT / = | = | RUN | · | 내림 | 끊김 미배정 | HOLD | RECOGp / · | 닫힘 미배정 | 해제 |
| RECOGp | LIFTp / = | = | RUNp | · | PABS(치움) | PABS(끊김) | PABS(끊김) | = / RECOG | 닫힘 미배정 | 비활성 |
| HOLD | · | · | · | T_drop → 끊김 미배정 | · | · | · | PABS(끊김) / · | 닫힘 미배정 | 해제 |
| PABS | = | = | RUNp | · | = | = | = | = / 원인대로 | 닫힘 미배정 | 비활성 |

- HOLD에서 `lu_same` → 스냅샷대로(놓임 → RUN, 접촉 UP → LIFT·T_lift 지금부터, 그 밖 → RECOG). `n_close`가 늘었으면 에지 무장. `lu_new` → 끊김 미배정.
- PABS의 prot_off: 원인 치움 → 내림, 끊김 → 끊김 미배정. PABS는 새 boot여도 다시 놓이면 RUNp.
- `unregister` → 어느 상태든 내림과 같다(배정 풂).
- contact_up·ld·bye는 에지 무장과 재실행 대기를 푼다.
- 짧은 들기(T_lift 안에 다시 놓임)는 아무것도 바꾸지 않는다. T_lift를 넘겨 내림된 뒤 같은 자리에 다시 놓으면 착지 판정의 `home` 규칙으로 같은 창이 다시 묶인다(REQ-008).
- 묶인 큐브를 T_lift 안에 다른 창 자리로 옮겨 놓으면 변화 없음(연결 유지) [미정 C12: 잠정 = 변화 없음]. 들지 않고 밀면 밀기다(REQ-007).

## 8. 착지 판정(미배정 큐브, 화면 제어 모드)

### 8.1 판정 조건

- 놓임 에지가 무장된 큐브가 놓임 T_stable 0.5 s(OBS 10개 연속) ∧ 이동 ≤ 4 mm(처음 3프레임 평균과 마지막 3프레임 평균의 거리)일 때 한 번 판정한다 [권장안 U-36].
- 무장 해제: 판정, CONTACT UP, link_down, BYE, 세션 끊김, 모드 전환.
- PC를 켤 때 이미 패드 위에 있던 큐브는 에지가 없으므로 판정하지 않는다(한 번 들었다 놓아야 한다).
- 같은 프레임에 둘 이상이면 작은 슬롯부터. 뒤 큐브는 앞 판정이 바꾼 상태로 본다.

### 8.2 대상 순서

판정 점 P = 큐브 중심(`pos`)을 화면 px로 옮긴 점([04](04-배치-엔진.md) 2절). 대상 찾기는 engine `pick(P)`다.

| # | 조건 | 결과 |
|---|---|---|
| 0 | 큐브 모양이 저장된 모양 모드와 같음 | 모양 모드 실행(19절) [미정 C2] |
| 1 | 경계 띠: P 둘레 ±8.33 mm(가로·세로 네 점)에서 `pick` 결과가 하나로 정해지지 않음 [권장안 U-69] [미정 S4] | 흰 점멸 1.5 s 한 번(`reject{boundary}`), 무장 해제. 다시 들었다 놓아야 판정 |
| 2 | 중심이 보호 중인 창의 영역 안(깊이 ≥ 8.33 mm) | 이관(REQ-016). 옛 담당 미배정, 보호 끝, 이관 흐름 1.0 s. 활성 4개여도 한다(REQ-004) |
| 3 | 활성이 이미 4개 | 흰 점멸(`reject{limit}`), 기존 배정 불변 [미정 C15: 잠정 = 팝업 대신 흰 점멸] |
| 4 | `pick(P)` = 떠 있는 안 묶인 창(항상 위 창 건너뜀, 겹치면 맨 위) | 그 창을 묶음 → 배치 다시 |
| 5 | `pick(P)` = 최소화된 안 묶인 창의 `home`(겹치면 마지막에 최소화된 창) | 그 창을 올려 묶음 → 배치 다시 |
| 6 | 그 밖(빈 곳, 묶인 창의 자리) | 그 자리에 선택 팝업, 큐브는 고르는 중(9절) |

- 4·5에서 묶인 뒤 "배치 다시" = 묶이고 켜진 창으로 템플릿을 다시 짜고, 배치 밖 등록 창을 최소화한다([04](04-배치-엔진.md) 4절).
- 사용자가 직접 연 새 창과 항상 위 창은 큐브가 놓일 때만 다룬다. 새 창은 다음 배치 때까지 그대로 둔다.

## 9. 선택 팝업

| 항목 | 규칙 |
|---|---|
| 여는 때 | 착지 판정 6, `?` 큐브 버튼 짧게. 활성 4개면 열지 않고 흰 점멸 [미정 C15] |
| 위치 | 큐브 자리에 해당하는 모니터 위치. 동반 앱 본창을 앞으로 부르지 않는다 [권장안 U-25] |
| 항목(위부터) | ① 이 큐브의 `lastProgram`(없으면 ②의 첫 항목) ② 안 묶인 열린 창: 떠 있는 창(z 순) → 최소화 창(최근 최소화 순) ③ 최근 프로그램 ④ 검색해서 실행 |
| 실행 대상 | ①③④의 프로그램은 등록 앱(REQ-005)만. main이 등록 경로로 실행하고 렌더러는 앱 ID만 보낸다 [미정 C1: 잠정 = 등록 앱만] |
| 고름 `popup_pick` | 떠 있는 창 → 묶음. 최소화 창 → 올려 묶음. 프로그램 → `launch{req, cube, app_id, arg}`, 대기표 `req → cube`. 그 뒤 배치 다시 |
| `launched{req, win}` | 대기가 살아 있고 그 큐브가 미배정·놓임이고 화면 제어 모드면 새 창을 묶고 배치 다시. 아니면 새 창은 사용자가 연 창처럼 둔다 |
| `launch_failed` | 큐브는 `?`, 흰 점멸 + 알림 |
| 닫음 `popup_close` | Esc·바깥 누름 → 큐브 `?` |
| 저절로 닫힘 | 큐브가 트레이가 됨, CONTACT UP, link_down, BYE, 세션 끊김, 모드 전환, 다른 길로 묶임 |
| 재실행 대기 취소 | CONTACT UP, link_down, BYE, 세션 끊김, 모드 전환 |

- 팝업 상태와 대기표는 저장하지 않는다. 어댑터는 실행을 15 s 안에 응답한다.
- 실행 창 대응 규칙은 [06 창 어댑터](06-창-어댑터.md) 8절.

## 10. 배정을 바꾸는 처리

| 처리 | 언제 | 배정 | 창 | 트리 | `home` | `lastProgram` |
|---|---|---|---|---|---|---|
| 내림 | T_lift 만료, BYE 1, 들림 대기 중 끊김·BYE, 재평가 3줄, PABS 해제(치움), 등록 해제 | 풂 | 최소화. 전경이면 `SW_MINIMIZE`, 아니면 `SW_SHOWMINNOACTIVE` [권장안 U-24] | 접힘, 남은 창이 채움 | 기록 | 기록 |
| 해제 | 동반 앱 '배정 해제'(REQ-025) | 즉시 풂 [권장안 U-61] | 최소화 | 접힘 | 기록 | 기록 |
| 닫힘 미배정 | `window_closed`, `rejected(stale_handle·elevated·access_denied)` | 풂, 묻지 않음 | 없음 | 접힘, 관리 집합에서 뺌 | 지움 | 기록 |
| 끊김 미배정 | T_drop 만료, BYE 2·3, 새 boot(REQ-033) | 풂 | 그대로 | 그대로, 다음 배치 때 최소화 [미정 C10: 잠정 = 다음 배치 때] | | 기록 |

- 큐브는 모든 경우 `?`(패드 위) 또는 트레이가 된다. 다음에 버튼을 누르면 팝업 맨 위가 `lastProgram`이다([10 재생·시험](10-재생-시험.md) 5절 4).
- 보호 4상태(RUNp·LIFTp·RECOGp·PABS)에서 '배정 해제'는 비활성이다.
- 내림·해제·창 끄기의 최소화는 "제거 확정 → 최소화 명령" p95 ≤ 800 ms(REQ-008)를 지킨다.

## 11. 버튼

입력은 BTN 사건([USB 2](../03-인터페이스/02-USB.md)). 끄기 누름은 큐브가 스스로 처리하고 BYE 2로 온다.

| 모드·상태 | 짧게(< 1 s) | 길게(1~4 s) |
|---|---|---|
| 화면 제어, 트레이 | 안내 알림 "패드에 올려 주세요" | 설정한 동작 |
| 화면 제어, `?` | 선택 팝업 열기 | 설정한 동작 |
| 화면 제어, 고르는 중 | 팝업 맨 위 항목 고름 | 설정한 동작 |
| 화면 제어, 묶임(RUN·LIFT·RECOG) | 창 켜기·끄기(12절) | 설정한 동작 |
| 화면 제어, 보호 중 | 거부: 흰 점멸 + 앱 문구(REQ-063 예외 ①) | 설정한 동작 |
| AI 모드 | 전환 가능 목록의 다음 프리셋(REQ-061). 목록이 비면 없음 | 설정한 동작 |

- 길게 지정할 수 있는 동작: 없음(기본), 프리셋 다음으로 바꾸기(AI 모드), 교체 보호 켜기·끄기, 배정 해제, 모드 전환, 재정렬(REQ-063 ②). AI 실행 시작·중지, OS 확인 창이 필요한 동작은 지정할 수 없다.
- 지정 동작이 그 상태에서 안 되면 하지 않고 흰 점멸 1.5 s + 앱 문구.
- 버튼 사건이 유실되면 아무것도 하지 않는다(재전송 없음).
- 누름 1번에 동작 1번. 판정 멈춤 0.3 s는 5.3절.

## 12. 창 끄기·켜기 [미정 C10]

- 끄기(묶임 + 짧게): `off = true`, 창 최소화, 트리 접힘, `home` 기록, 남은 창이 채움. 배정은 그대로이고 활성 수에 든다. 아이콘 ✕.
- 켜기(다시 짧게): `off = false`, 창 `restore`, 배치 다시(템플릿에 넣음).
- 켜려는데 창이 없으면 닫힘 미배정으로 처리한다.
- 보호 중인 배정은 끌 수 없다(보호 ⇒ 창 켬).

## 13. 끊김·BYE·새 boot

| 사건 | RUN·RECOG | LIFT | 보호 상태 |
|---|---|---|---|
| ld(0x10~0x12) | HOLD → T_drop 5 s 뒤 끊김 미배정 | 내림 | PABS(끊김). LIFTp는 PABS(치움) |
| 새 boot(`lu_new`, `cube.rebooted`) | 바로 끊김 미배정 | (ld가 먼저 옴) | PABS(끊김) |
| BYE 1(도크) | 바로 내림 | 내림 | PABS(치움) |
| BYE 2(버튼)·3(저전압) | 바로 끊김 미배정 [권장안 U-37] | 내림 | PABS(끊김) |

- 이 표는 큐브 사건에만 쓴다. 패드 재부팅·USB 끊김·서비스 재시작은 큐브 사건이 아니다(15절) [권장안 U-33].
- 우선순위: 들림 증거 > 끊김. 보호 > 끊김·방전 > 일반 내림.

## 14. 교체 보호(REQ-032)

| 항목 | 규칙 |
|---|---|
| 자동 켜기 | 마지막 BATT 3개 모두 ≤ V10 ∧ 무장 → 켜고 무장 해제. 재무장 = 3개 모두 ≥ V10 + 150 mV. 충전으로는 풀리지 않는다 |
| 수동 켜기 | 동반 앱 `protect.set` |

| 보호 중 들림·끊김·BYE·새 boot | PABS. 창·영역·배정 유지. 원인: LIFTp에서 온 것과 BYE 1 → 치움, 그 밖 → 끊김 |
| 끄는 길 | 이관(8.2의 2), 앱 해제(원인대로: 치움 → 내림, 끊김 → 끊김 미배정), 창 닫힘 |

## 15. 세션 동결·재개·서비스 재시작

- `session_lost`: 동결. 타이머·무장·재실행 대기를 버리고 팝업을 닫는다. 배정·창은 그대로, 창 명령 없음.
- `session_resume`: 스냅샷의 링크 필드 반영 → 유예 T_rec(재개 뒤 첫 메시지부터, 같은 pad_boot_id 2 s, 다르면 20 s) [권장안 U-33]. 유예 안 놓임은 바로 가동, 에지는 판정, BYE는 전이표. 나머지는 기록만 하고 유예 끝에 재평가(16절).
- 다시 연결된 뒤 패드 위 미배정 큐브는 그 자리에 창이 있어도 묶지 않고 `?`로 둔다. 새로 내려놓은 것만 판정한다 [미정 C13].
- 서비스 재시작 = 세션 끊김 + 창 대조. 어댑터 `ready` → 저장된 `win_key`마다 생존 확인(숨김도 생존) → 아래 표 → 유예 끝 재평가. 대조 전에는 창 명령을 보내지 않는다.

| 저장 상태 | 창 일치 | 창 없음·불일치 |
|---|---|---|
| 묶임 | 그대로 | 미배정 + `lastProgram` 유지 [미정 C10: 잠정] |
| 보호 | 그대로 | 보호 끝 → 미배정 + `lastProgram` |
| 안 묶인 창의 `home` | 그대로 | 지움 |

- 그다음 설정 `PC를 켤 때 모드 자동 실행`(기본 켜짐)이 켜져 있고 패드 위 큐브 모양이 저장된 모양 모드와 같으면 모양 모드를 실행한다. 아니면 모든 패드 위 큐브는 `?` [미정 C2]. 그 밖에는 시작 때 창을 실행하지 않는다(REQ-015 ⑥).
- 프로젝트 큐브(REQ-037)의 `lastProgram`은 그 프로젝트 폴더의 VS Code(`{vscode, 폴더}`)다. 창이 없을 때 놓으면 팝업 맨 위에서 다시 실행한다 [미정 C10: 잠정].

## 16. 모드 전환과 재평가

- 모드는 둘(화면 제어 / AI)이고 앱 버튼 `mode.set`(또는 길게 누름 설정)으로만 바꾼다(REQ-034). 탭 이동은 모드를 바꾸지 않는다.
- 늘 갱신: 링크, `n_close`, BATT, 보호 무장, 마지막 위치, 마지막 끊김 사유.
- 떠날 때: 타이머·무장·재실행 대기를 버리고, 밀기는 `push_end`, 팝업 닫음, 트리 저장. 전환 중 들림·제거로 창을 최소화하지 않는다.
- 들어올 때: 그 모드의 배정이 있는 큐브마다 아래 표에서 처음 맞는 줄 하나. 새 배정을 만들지 않는다. 창은 저장 트리로 복원 [권장안 U-43]. 저장 트리가 없는 첫 진입은 창을 옮기지 않고 패드 지도만 켠다. AI 실행은 계속된다.
- 같은 표를 세션 유예 끝과 서비스 시작에도 쓴다.

| 줄 | 보호 아님 | 보호 |
|---|---|---|
| 1 | 떠난 뒤 새 boot → 끊김 미배정 | 놓임 → RUNp |
| 2 | 놓임 → RUN | 새 boot·DOWN → PABS(이미 PABS면 원인 유지, 아니면 마지막 사유 BYE 1 → 치움, 그 밖 → 끊김) |
| 3 | DOWN·BYE 1 → 내림(유일한 즉시 최소화) | 이미 PABS → 그대로 |
| 4 | DOWN·BYE 2·3 → 끊김 미배정 | UP·접촉 UP → LIFTp, T_lift 지금부터 |
| 5 | DOWN·그 밖 → HOLD, T_drop 지금부터 | UP·접촉 DOWN·놓임 아님 → RECOGp |
| 6 | UP·접촉 UP → LIFT, T_lift 지금부터 | |
| 7 | UP·접촉 DOWN·놓임 아님 → RECOG(앱 안내만) | |

## 17. AI 모드 후보 [권장안 U-40]

- 큐브마다 `ai_since` 하나. 후보 ≤ 4, `ai_since` 순.
- AI 모드에서 놓임 에지 + T_stable 판정으로 들어온다. 4개면 `reject{limit}`. AI 역할이 없는 큐브는 `reject{no_role}` + "이 큐브에는 AI 역할이 없습니다"(REQ-034 예외 ④).
- 바로 빠짐: CONTACT UP, link_down, BYE, 새 boot, 등록 해제. 광학 소실로는 빠지지 않는다. AI 모드로 들어올 때 놓임이 아니거나 새 boot면 빠진다.
- 실행 명세 = 시작 순간 후보 ∩ 놓임(≤ 4)으로 고정. 그 뒤 물리 사건은 실행에 영향이 없다 [권장안 U-35]. 빠진 명세 큐브는 회색 점멸. 중지는 앱 버튼만(REQ-040).
- `ai_member{cube, add|drop, reason}`을 낸다. AI 조정이 구성 검증을 다시 한다.

## 18. 창 사건 반영

- 배정을 바꾸는 창 사건은 `window_closed`와 `result{rejected: stale_handle·elevated·access_denied}`뿐이다(닫힘 미배정). 버전과 무관하게 적용한다.
- 사용자 최소화·복원·숨김·이동·스냅 [권장안 U-41], 새 창, 형상 결과(`clamped`·`mismatch`), `uncertain`은 배정을 바꾸지 않는다. 형상 반영은 engine이 한다.
- 창 목록이 바뀌면(새 창, 이동, 도킹, 최소화, 닫힘) 상태는 그대로 두고 engine이 패드 지도만 다시 계산한다.
- 최소화된 안 묶인 창이 닫히면 그 `home`을 지운다. 패드 위 큐브가 없고 묶인 창도 없으면 지금 열린 창 기준으로 `home`을 다시 찍는다.

## 19. 모양 모드 [미정 C2: 잠정 = K8, REQ-064를 넓힘]

- 저장: 큐브 번호, 모양(큐브 쌍마다 8방향과 붙음), 그때 묶인 프로그램. 붙음 = 중심 거리 ≤ 35 mm + 틈 10 mm(동반 앱 시안 값).
- 모양이 맞는 순간: 저장 프로그램 가운데 떠 있거나 최소화된 것은 그 창을 쓰고 없는 것만 실행한다. 지도대로 묶였던 큐브도 모양 모드 구성으로 다시 묶는다. 모양 모드에 없는 창은 최소화한다.
- 화면 제어 M 범위를 먼저 만들고 이것은 나중에 만든다.
