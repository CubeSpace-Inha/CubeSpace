# Windows 창 어댑터(win-adapter)

이 문서로 답하는 것: C# 어댑터는 어떤 창을 보고, 창을 어떻게 옮기고 판정하며, 무엇을 감시하고, 앱을 어떻게 실행하나. 묶기 재설계로 새로 필요한 것은 무엇인가.

관련: [04 배치 엔진](04-배치-엔진.md) · [03 상태기계](03-상태기계.md) · [PC 내부 2 서비스 ↔ 창 어댑터](../03-인터페이스/03-PC-내부.md)

## 1. 실행 형태

| 항목 | 값 |
|---|---|
| 언어 | C#, Win32 `DllImport` 약 30개, NuGet 없음 |
| 배포 | .NET 10 자체 포함 단일 파일 win-x64, `app.manifest`에 `dpiAware true` + `dpiAwareness PerMonitorV2`. 게시는 Windows에서만 [권장안 U-78] |
| 프로세스 | `cube-adapter.exe`, main의 상주 자식. `spawn(exe, [], {stdio: ['pipe','pipe','pipe'], windowsHide: true})`. 로그인 세션 일반 권한, Windows 서비스 금지. 포장판은 Forge `extraResource`로 `resources\cube-adapter.exe`에 두고 `path.join(process.resourcesPath, 'cube-adapter.exe')`로 띄운다(asar 안 실행 파일은 `execFile`만 되고 `spawn`은 안 된다) |
| 구성 | 스레드 2개: stdin(받은 시각 `t_recv`를 찍어 큐에) / 주 루프(명령 처리 + 틱 폴링, 잠금 없음). 파일 `Program`·`Native`·`Windows`·`Apply`·`Launch`.cs |
| 순수 함수 | `judge`·키 비교·시각 변환은 Win32 없이. 단위 시험 1파일(판정표 모든 줄 + `uncertain(timeout)` 경로) |
| 통신 | stdio NDJSON v1, UTF-8(BOM 없음). `StreamReader/StreamWriter(…, new UTF8Encoding(false))` + `AutoFlush`. 한 줄 256 KiB. 메시지는 [PC 내부 2](../03-인터페이스/03-PC-내부.md) |
| 위치 | `pc/win-adapter/`. 클라이언트(spawn·ping·재시작)는 main 쪽 |

### 종료 코드와 재시작

| 상황 | 어댑터 | main 반응 |
|---|---|---|
| PMv2가 아님 | `error{dpi_awareness}` → 종료 2 | 다시 띄우지 않고 사유 표시 |
| 자기 토큰이 관리자 | `error{adapter_elevated}` → 종료 3 | 다시 띄우지 않음, 창 제어·AI 시작 막음 |
| 치명 오류 / `ping` 1 s에 `pong` 3 s 없음 | 종료 4 / 강제 종료 | 1·2·4 s 간격 재시작, 60 s에 3회 실패면 "창 제어 중지"(AI·설정은 계속) |
| 재시작 뒤 | | 미응답 명령은 `uncertain(adapter_restart)`로 닫고 `hello → ready → config → enumerate` |
| stdin EOF | 종료 0 | 앱 종료 순서의 한 단계 |

## 2. 좌표

- Per-Monitor V2, 물리 px 정수, 주 모니터 왼쪽 위 (0, 0).
- 계획·판정 사각형 = 보이는 경계 `DWMWA_EXTENDED_FRAME_BOUNDS`. `GetWindowRect`로 판정하지 않는다.
- 적용 사각형: 보통 상태면 목표 + 인셋(명령 직전 `GetWindowRect − EFB`, 캐시 없음). 그 밖은 인셋 0 + 보정 1회.
- `WINDOWPLACEMENT`는 작업 영역 좌표 = 화면 좌표 − 작업 영역 원점.
- 작업 영역 = `SPI_GETWORKAREA`(물리 px)를 어댑터가 보낸다.

## 3. 열거(`enumerate`)

| 순서 | 조건 | 결과 |
|---|---|---|
| 1~5 | 최상위(`EnumWindows`), 보임, 소유자 없음(`GW_OWNER`), `WS_EX_TOOLWINDOW` 아님, cloaked 아님(`DWMWA_CLOAKED`) | 후보 |
| 6 | 실행 파일 이름(`QueryFullProcessImageName`)이 등록 `exe_names`와 같음(대소문자 무시), `exclude_pids`(동반 앱·서비스·AI CLI) 뺌 | 등록 앱 창 |
| 7 | 무결성 수준이 어댑터보다 높음 / 확인 불가 | `excluded: "elevated"` / `"access_denied"` |
| 8 | 주 모니터가 아님 | `excluded: "other_monitor"` |

- `z`(0 = 맨 위): `GW_HWNDNEXT`로 내려가며 후보에만 번호, 상한 2,000회. 항상 위 창에서 일반 창으로 이어지는 순서는 문서가 보장하지 않으므로 W-T4에서 확인한다.
- 창마다 보고: `win`, `app_id`, `state`(normal·max·arranged·min·hidden), `visible_rect`, `dpi`, `z`, `onTop`, `home`(최소화 창만), `excluded?` [미정 S3]. 제목은 `with_title: true`일 때만.
- `onTop` = `GetWindowLongPtr(GWL_EXSTYLE) & WS_EX_TOPMOST`.
- `home` = 최소화 창의 `rcNormalPosition`을 화면 좌표로 바꾼 값. 서비스는 그 창이 최소화되기 전 마지막으로 본 `visible_rect`가 있으면 그것을 쓴다.
- `rcNormalPosition`은 작업 영역 좌표의 창 사각형이라 보이지 않는 크기 조절 테두리를 포함하고, `visible_rect`(EFB)보다 그만큼 크다. 어댑터는 그 창이 normal일 때 잰 인셋(`GetWindowRect` − EFB)을 기억해 `home`에서는 빼고, min 창 `place` 목표에는 더한다. 잰 적 없으면 인셋 0 [실측 필요] W-T5.
- 보조 창(Edge 분리 개발자 도구 등)이 사람 표시와 다르게 잡히면 "창 제목 있음" 조건을 더한다(REQ-005).
- 제외 표시 창에는 명령을 보내지 않는다(REQ-029).

## 4. 적용

### 4.1 활성화 규칙 [권장안 U-24]

- 배치·복원·비전경 최소화는 창을 활성화하지 않고 Z 순서도 바꾸지 않는다. 올리기(raise) 없음.
- 예외: 전경 창 최소화(`SW_MINIMIZE`, 다음 창이 활성화)와 앱 실행으로 생긴 새 창. 전경 판정은 보내기 직전 `GetForegroundWindow()`.
- 새 창이 앞으로 오는 것은 보장되지 않는다. 어댑터는 전경 프로세스도 마지막 입력을 받은 프로세스도 아니라 `SetForegroundWindow` 제한에 걸리고, Windows는 작업 표시줄 단추만 깜박일 수 있다. 판정·시험 기준에 넣지 않는다.
- `FLAGS = SWP_NOACTIVATE | SWP_NOZORDER | SWP_NOOWNERZORDER | SWP_ASYNCWINDOWPOS`. `WP(show)` = `GetWindowPlacement`로 읽고 `showCmd`·`rcNormalPosition`·`flags = WPF_ASYNCWINDOWPLACEMENT`만 바꿔 `SetWindowPlacement`.

| 연산 \ 상태 | normal | max·arranged | min |
|---|---|---|---|
| `place` | `SetWindowPos(h, NULL, rect, FLAGS)` | `WP(SW_SHOWNOACTIVATE)` | `WP(SW_SHOWMINNOACTIVE)` 뒤 곧바로 `deferred` |
| `restore` | `place`와 같음 | `WP(SW_SHOWNOACTIVATE)` | `WP(SW_SHOWNOACTIVATE)` |
| `minimize` | 전경이면 `ShowWindowAsync(SW_MINIMIZE)`, 아니면 `SW_SHOWMINNOACTIVE` | 같음 | 바로 `ok` |

- 상태 읽기: `IsIconic` → min, `IsZoomed` → max, `IsWindowArranged`(동적 로드, 없으면 거짓) → arranged, 나머지 normal.
- `SetWindowPlacement`가 최대화·스냅을 못 풀면 `SW_SHOWNOACTIVATE` → 판정 → `SetWindowPos` 두 단계 [실측 필요] W-T5. 스냅 상태에서 최소화한 창은 복원 때 다시 스냅될 수 있으므로(`IsWindowArranged` 문서) W-T5에 "스냅 → 최소화 → `restore`"를 넣는다.

### 4.2 보내기 전 검사·대기열·판정

- 보내기 전: 식별 키(→ `stale_handle`) → 제외 표시 → 숨김(→ `hidden`) → 사용자가 끄는 중 `GUI_INMOVESIZE`(→ `user_moving`). 이미 목표면 보내지 않고 `ok`.
- 창마다 보낸 명령 1 + 대기 1(latest-wins). 밀려난 것은 `superseded`.
- 대기 명령이 있으면 앞 명령의 첫 변화 틱에 판정하고 곧바로 보낸다. 없으면 같은 읽기가 N_STABLE(2)번 이어질 때 판정.
- 기한 D = 1,000 ms 안 변화가 없으면 `uncertain(timeout)`, 재시도 없음. 대기 명령이 없으면 L = 10 s 동안 감시해 바뀌면 같은 `cmd_id`로 `result{revision: 1, reason: "late_apply"}`.
- 보정: 대기 명령이 없을 때 명령당 1회.
- 경계 이동은 `apply` 한 묶음, 창마다 독립. `DeferWindowPos`는 쓰지 않는다. 모든 호출이 비동기라 멈춘 앱에 막히지 않는다 [실측 필요] W-T4b.
- 오차 `e = max(|Δleft|, |Δtop|, |Δright|, |Δbottom|)`(보이는 경계, 물리 px).

### 4.3 판정값

| 판정값 | 뜻 | 사유 |
|---|---|---|
| `ok` | normal ∧ e ≤ 8(최소화는 min) | |
| `deferred` | 최소화 유지, 복원 위치만 바꿈 | `kept_minimized` |
| `clamped` | 폭 또는 높이가 계획 + 8 px 초과 | `min_size` |
| `mismatch` | 작음·위치·상태 어긋남 | `size`·`position`·`state` |
| `uncertain` | 기한 안 변화 없음 | `timeout`·`adapter_restart` |
| `superseded` | 새 명령에 밀림 | |
| `rejected` | 보내지 않음 | `stale_handle`·`user_moving`·`hidden`·`elevated`·`access_denied`·`other_monitor` |
| `preempted_by_user`(K3) | 판정 때 사용자가 끄는 중 | |

엔진·상태기계 반응은 [04](04-배치-엔진.md) 9절. 성공률 지표: 앱 3 × 시작 상태 4 × 17 = 204회, `clamped`·`mismatch`·`uncertain`이 실패(REQ-028).

## 5. 감시(폴링)

대상: 마지막 `windows`의 창과 `launched`로 이은 창. 보낸 명령·늦은 적용 감시가 없는 창만 보고하고, 판정 때 `last_reported`를 바꿔 자기 명령을 다시 보고하지 않는다.

| 주기 | 조건 | 보고 |
|---|---|---|
| 250 ms | 창 사라짐(`IsWindow` 거짓 또는 키 불일치) | `window_closed`, 추적 끝 |
| 250 ms | 상태가 마지막 보고와 다름 | `window_state{…, by: "user"}` |
| 250 ms | normal 그대로 한 변이라도 8 px 넘게 바뀌고 같은 읽기 2번 | K3 `window_changed{cause: user_drag \| other}` |
| 1 s | 작업 영역 바뀜 | `display_changed` |

- 전이마다 1 s 안 1건, 자기 명령 뒤 0건(REQ-030). 숨김(cloaked)은 닫힘이 아니다.
- 새 창은 알리지 않는다. 서비스가 패드 지도 때문에 `enumerate`를 250 ms마다 부른다 [미정 C9]. 한 번 호출이 2 ms를 넘으면 주기를 늘린다 [실측 필요] W-T4.

## 6. 관리자 권한 창(REQ-029)

- 감지: `OpenProcess(PROCESS_QUERY_LIMITED_INFORMATION)` → `OpenProcessToken(TOKEN_QUERY)` → `GetTokenInformation(TokenIntegrityLevel)` RID를 어댑터와 비교. 높으면 `elevated`, 한 단계라도 실패하면 `access_denied`.
- 동반 앱 문구: "관리자 권한으로 실행된 창은 CUBE SPACE가 옮길 수 없습니다."
- 감지를 빠져나가 조용히 무시되면 `uncertain(timeout)`으로 남는다.

## 7. 창 식별과 복원 정보

| 항목 | `win_key` | 복원 정보 `launch` |
|---|---|---|
| 내용 | `{hwnd, pid, proc_start}`(10진 문자열, `proc_start` = `GetProcessTimes` 생성 시각) | `{app_id, kind: folder\|file\|url, arg}` |
| 대상 | 모든 관리 창 | CUBE SPACE가 인자와 함께 실행한 창만(`launch` 성공 때 기록) |
| 용도 | 명령마다 검증(캐시 없음), 서비스 재시작 대조 | 큐브를 다시 놓거나 팝업에서 고를 때 재실행 |

- 검증: `GetWindowThreadProcessId` PID와 생성 시각이 모두 같아야 한다. 다르면 `rejected(stale_handle)`. 창 제목은 키에 쓰지 않는다.
- 복원하지 않는 것: 창 안에서 옮긴 폴더·URL·탭, 사용자가 직접 연 창.

## 8. 앱 실행

| 항목 | 규칙 |
|---|---|
| 언제 | 선택 팝업에서 프로그램을 고름, 모양 모드에서 없는 프로그램, 프로젝트 큐브 재실행. 그 밖에는 실행하지 않는다(REQ-015 ⑥) |
| 대상 | 등록 앱(VS Code `Code.exe`, Edge `msedge.exe`, 메모장 `Notepad.exe`)만 [미정 C1] |
| 실행 파일 | 등록 때 main이 OS 파일 선택 창으로 받아 검사하고 OS 확인 창 뒤 저장. `config`로 한 번 보내고, 어댑터가 이름·존재를 다시 확인(아니면 `bad_exe`) |
| 호출 | `Process.Start`, `UseShellExecute = false` + `ArgumentList`. 셸·`.cmd`·`.bat` 금지, 환경 변수 안 바꿈. 예외면 `start_error`(로그에는 예외 종류만) |
| 인자 | VS Code `[--new-window, 폴더]`, 메모장 `[파일]`, Edge `[--new-window, URL]`(K4). 인자 없는 실행도 받는다 |
| 인자 검사(서비스·어댑터 둘 다) | 폴더·파일은 존재하는 절대 경로, URL은 http·https 절대 URL, 사용자 정보(`user:pass@`) 거부. `-`로 시작하거나 줄바꿈·NUL이 있으면 `bad_arg` |
| 새 창 대응 | 실행 직전 후보 집합 S0 기록 → T = 15 s 동안 250 ms마다 재열거 → S0에 없는 창이면 `launched{req, win, ms}`. 500 ms 안 2개 이상이면 `ambiguous`, 없으면 `no_new_window` |
| 동시 실행 | 앱마다 하나씩. 같은 폴더·파일로 이은 창이 살아 있으면 실행하지 않고 그 창을 돌려준다 |
| 메모장 | 시연 PC를 "새 창에서 열기"·"세션 복원 끔"으로 둔다. 새 창이 안 생기면 재실행에서만 뺀다 [권장안 U-104] |
| Edge | 창들이 한 프로세스를 공유한다. 시작 설정 "새 탭 페이지 열기" 전제. CDP·확장·창 제목 해석 금지(REQ-038) |

- 실행 확인 시간 T는 W-T10 뒤 max(5 s, 2 × 최대 실행→새 창)로 고정 [실측 필요].

## 9. 동반 앱 창과 기록 경계

- 동반 앱 본창과 선택 팝업 창은 배치 대상 밖이다. 창 제어 중에도 최소화하지 않는다(`exclude_pids`) [권장안 U-25].
- 어댑터 stderr에는 hwnd·pid·app_id·사각형·상태·판정값·시각·사유 코드만 남긴다. 창 제목·경로·URL은 남기지 않는다. 서비스도 제목을 로그·기록에 저장하지 않는다.

## 10. 범위

| 범위 | 기능 |
|---|---|
| M(먼저) | 좌표 규약, 열거·필터·Z·`onTop`·`home`, `place`·`minimize`·`restore`, 판정, 창별 대기열, 늦은 적용, 식별 키, 관리자 창 제외, 닫힘·상태 보고, 작업 영역 폴링, 등록 앱 실행(팝업 때문에 M으로 당김) |

| 범위 밖 | 다중 모니터, 가상 데스크톱, 실행 중 배율 변경, F11 전체 화면, 창 올리기, WinEvent 훅 |

- 시연 조건: Windows 11, 모니터 1대, 해상도·배율 한 쌍 고정(1080p면 100 %), 주 모니터 창만 [권장안 U-26].

## 11. 상수

판정 허용 8 px, 틱 10 ms, N_STABLE 2, 기한 D 1,000 ms, 늦은 적용 감시 10 s, 보정 1회, 창별 대기 1, 상태 폴링 250 ms, 작업 영역 폴링 1 s, 실행 대응 15 s(재열거 250 ms, 동시 새 창 500 ms), Z 순회 2,000, ping 1 s·무응답 3 s, 재시작 1·2·4 s·60 s에 3회. 틱·N_STABLE·실행 대응은 [실측 필요] W-T4·W-T10. 내부 지연 목표 `t_issue − t_recv` p95 ≤ 2 ms [실측 필요].
