# 표시 렌더러

이 문서로 답하는 것: 패드 LED 프레임에 무엇을 어떤 순서로 그리고, 큐브 둘레에 언제 어떤 문제 표시를 켜며, 큐브 8×8에 어떤 아이콘을 보내나. 밝기와 전류는 누가 막나.

관련: [03 상태기계](03-상태기계.md) · [04 배치 엔진](04-배치-엔진.md) · [07 AI 실행](07-AI-실행.md) · [USB 2 메시지 목록](../03-인터페이스/02-USB.md)

## 1. 위치와 입출력

- main 안 서비스 모듈이다(동반 앱 화면을 그리는 Electron 렌더러와 다르다). 담당 팀원 2.
- PC가 프레임을 통째로 만든다. 패드 펌웨어는 출력·감광·대기 패턴만 한다.

| 입력 출처 | 입력 |
|---|---|
| engine | 분할 트리, 움직이는 선, 한계 상태, 패드 지도 칸 `{rgb, alpha}` |
| cube-events | `presence`, `reject`, `protect`, `batt_level`, `edge_warn`, `icon`, `flow`, `popup`, `window_off`, 현재 모드 |
| AI 조정 | `ai_problem{cube, kind: error\|wait\|fail\|none, run_id}` |
| 설정 | 패드·큐브 LED 밝기 배율(100 % 이하) |

| 출력 | 규칙 |
|---|---|
| LED 프레임 | 384 × RGB(줄 1→16, 줄 안 열 1→24), 감광 전 값. 그림이 바뀔 때만, 광학 프레임 `frame_us`(기본 50 ms)에 1번 이하(기본 ≤ 20 fps)(REQ-017 ⑦) |
| ICON | 슬롯마다 8×8 RGB(행 우선, 밝기 반영 최종값). LINK `up=1`마다, 아이콘이 바뀔 때 |
| LED_OFF | 서비스 정상 종료 때 |

형식은 [USB 2](../03-인터페이스/02-USB.md).

## 2. 패드 LED 층과 우선순위

위가 이긴다(REQ-017 ③). 한 칸에는 이긴 층 하나만 그린다.

| 단 | 층 | 모양·밝기(코드값/255) |
|---|---|---|
| 1 | 한계 빨강, 가장자리 경고 | 이음매 양옆 열 빨강 점멸 / 그 변 바깥 테두리 빨강 점멸 |
| 2 | 큐브 둘레 문제 표시(3절) | 큐브 몸체 바로 바깥 LED 한 줄 |
| 3 | 움직이는 경계, 사건 1회 흐름 | 밀리는 선 30 %(77). 이관 흐름 30 %·1.0 s·사건당 1번. 확정 번쩍(배정 순간 테두리만 흰색 1번) |
| 4 | 창 테두리 단 | 영역 테두리 1줄(면 채움 아님), 창마다 다른 색. 창 1~2개 55 %(140), 3개 45 %(115), 4개 40 %(102). AI 모드는 대신 패드 전체 보라 테두리 1개. 들림 대기 영역은 테두리가 서서히 어두워짐 |
| 5 | 패드 지도 단 | 안 묶인 창 칠하기. 떠 있음 알파 0.25, 최소화 `home` 0.10([04](04-배치-엔진.md) 10절) |

- 단 2 안 순서: 존재·거부(노랑 점멸, 흰 점멸, 회색 점멸, 보호 부재) > 10 %·보호 빨강 > AI 표시 > 충전 필요.
- 같은 큐브에 존재 표시와 AI 표시가 겹치면 존재 표시만 그리고, 존재 표시가 끝나면 AI 표시를 다시 그린다.
- 지도 단과 패드 알림 항목(REQ-065 ④, 켰을 때 맨 아래 단에 한 번)의 순서는 정해지지 않았다 [미정 C7]. 이 문서 안: 알림이 지도 위.
- 감광 때 상태 구분은 색과 움직임(정지·점멸)으로 하고 전체를 같은 비율로 낮춘다.
- 사건 1회 흐름 가운데 AI 순서 확정·단계 결과 전달 흐름은 결정 전이라 구현하지 않는다 [권장안 U-46]. 이관 흐름만 그린다.
- 점멸·호흡 주기, 번쩍 길이, 앱 대표색은 요구 원문에 값이 없다. 잠정: 점멸 0.6 s 주기 50 %, 호흡 1.2 s, 번쩍 0.3 s [실측 필요]. 표시끼리 구분되는지는 표시 구분 시험 T11b([10 재생·시험](10-재생-시험.md) 6절)로 보고, 미달인 표시는 색·점멸을 바꾼다.

## 3. 큐브 둘레 문제 표시

정상 상태(연결됨, 묶임, 미배정, AI 실행 중·완료)는 둘레를 켜지 않는다(REQ-017 ②). 둘레 점등 0은 큐브 둘레에만 해당하고 지도는 켠다.

| 상태 | 색·점멸 | 켜기 | 끄기 | 밝기(잠정) |
|---|---|---|---|---|
| 재인식 대기 | 노랑 점멸, 마지막 위치 | 재인식 대기에 들고 0.3 s 뒤 | 상태를 벗어남 | 100 % |
| 끊김 보류 | 노랑 점멸, 마지막 위치 | 보호 아님 ∧ link DOWN, T_drop 동안 | 복귀·T_drop 만료 | 100 % |
| 충전 필요(30 % 이하) | 어두운 노랑, 정지 | `batt_level = low30` | `ok` | 50 % |
| 10 % 이하·보호 | 빨강, 정지 | `low10` 또는 수동 보호 | 이력 조건, 보호 끝 | 100 % |
| 들림 대기·보호 | 마지막 위치 빨강 유지 | 보호 큐브를 듦 | 놓임·보호 부재 | 100 % |
| 보호 부재 | 마지막 위치 약한 빨강 | PABS | 이관·복귀·보호 해제 | 40 % |
| 막은 큐브(밀기 한계) | 빨강 점멸 | 경계가 이 큐브 앞에서 멈춤 | 한계 해제 | 100 % |
| 거부 | 흰 점멸 1.5 s, 판정당 1번 | `reject`(경계 띠, 활성 4개, AI 역할 없음, 안 되는 버튼 동작, 실행 실패) | 1.5 s 뒤 | 40 % |
| 끊김으로 풀린 자리 | 회색 점멸, 마지막 위치 | T_drop 만료로 미배정 | 그 창이 새 담당을 얻거나 닫힘 | 80 % |
| AI 명세 큐브 빠짐 | 회색 점멸, 빈 자리 | 실행 중 고정 큐브 제거·방전(실행은 계속) | 실행 끝 | 80 % |
| AI 확인 대기 | 노랑 점멸 | `ai_problem wait` | 대기 이탈 | 100 % |
| AI 실패·구성 오류 | 빨강 점멸 | `ai_problem fail·error` | 실패: 결과 확인·다음 실행·AI 모드 이탈. 오류: 다음 검증에서 사라짐 | 100 % |

- 큐브 밑(후광)은 켜지 않는다. 대상 큐브가 패드 밖이면 패드에 표시하지 않고 동반 앱만.
- 화면 제어 모드에서 온 AI 표시 사건은 그리지 않는다. AI 표시는 큐브를 들어도 끄지 않는다.
- 큐브와 무관한 알림(패드 세션 끊김, 서비스·어댑터 오류)은 패드에 그리지 않는다. 동반 앱 화면과 작업 표시줄 깜박임(`win.flashFrame(true)`)만 [권장안 U-25].
- 재인식 대기가 10 s를 넘으면 동반 앱에 안내만 띄운다.

### 잔량 단계(REQ-045)

| 단계 | 켜기 | 끄기 |
|---|---|---|
| 충전 필요 | 마지막 BATT 3개(30 s)가 모두 V30(3.80 V) 이하 | 3개 모두 V30 + 150 mV 이상 |
| 10 % 이하 | 같은 필터로 V10(3.70 V) [권장안 U-96] | V10 + 150 mV 3회 |

- 충전으로 잔량이 올라도 보호·창 상태는 바꾸지 않고 표시만 바꾼다. 설정의 경고 기준(REQ-065 ⑤)은 V30만 바꾼다. V10은 바꾸지 않는다.

## 4. 큐브 8×8 아이콘

PC가 `icon(모드, 큐브)`를 계산해 ICON으로 보낸다. 8×8에는 아이콘 외 상태를 그리지 않는다(REQ-044).

| 모드·상태 | 아이콘 |
|---|---|
| 화면 제어, 묶임 | 그 창의 앱 아이콘 |
| 화면 제어, 묶임 + 창 끔 | ✕ |
| 화면 제어, 미배정 `?` | `?` |
| 화면 제어, 고르는 중 | `?` 깜빡: PC가 `?`와 빈 틀을 0.5 s마다 번갈아 보냄(10/11 확정) |
| 화면 제어, 트레이 | 등록 아이콘 |
| AI, 역할 있음 | 역할 아이콘: 에이전트 = 공급자별(Claude Code·Codex), 프롬프트·스킬 = 작업 종류 4종(`code`·`doc`·`search`·`prompt`), 프로젝트 = 프로젝트 도안 |
| AI, 역할 없음 / MCP·묶음 | 등록 아이콘. 프리셋이 지정된 큐브는 프리셋 아이콘 |
| ICON 받기 전 | 큐브 기본: 가운데 2 × 2 흰색, 어두운 밝기 |
| 링크 끊김 | 마지막 ICON 유지 |

- 등록 아이콘 = 등록 때 고른 도안. 기본값은 그 큐브의 AI 역할 아이콘, 없으면 빈 틀(가장자리 한 줄).
- 보내는 때: LINK `up=1`, 배정·미배정·이관, 모드 전환, 팝업 열림·닫힘, 창 켜기·끄기, 프리셋 바뀜. 새 boot면 새 LINK에서 다시 보낸다.
- 도안 파일 [시안/LED아이콘_8x8_RGB.json](시안/LED아이콘_8x8_RGB.json)(키 `patterns`·`rgb8`·`palette`·`icon_names`, 원점 왼쪽 위, 행 우선): 지금 8종(`chrome`, `youtube`, `kakao`, `vscode`, `code`, `doc`, `search`, `prompt`). 더할 것: Edge, 메모장, Claude Code, Codex, 프로젝트, 빈 틀 [권장안 U-92], `?`, ✕.
- 큐브 펌웨어가 아이콘 위에 덮는 예외 셋(도크 잔량 막대 3 s, 저전력 맨 아래 빨강 줄, 전원 켜기·끄기 순간 ≤ 2 s)은 PC가 그리지 않는다 [권장안 U-21].

## 5. 밝기와 전류

| 항목 | 규칙 |
|---|---|
| ICON 밝기 전환 | 움직임(CONTACT 변화, 들림 동안, ON_PAD 위치 변화, link_up) 뒤 보통 밝기, 10 s 조용하면 어두운 밝기로 ICON 1번 다시 보냄. PC가 판단하고 큐브 IMU는 안 씀 [권장안 U-57]. 어두운 ICON은 보통 ICON과 켜진 칸이 같아야 한다(0이 아닌 채널을 0으로 내리지 않고 최소 1). 그래야 큐브가 0.5 s에 걸쳐 어두워진다([펌웨어 02 10.1](../02-펌웨어/02-큐브.md)) |
| 큐브 점등분 상한 | 보통 ≤ 40 mA, 어두움 ≤ 15 mA(REQ-053 ⑤). 렌더러가 ICON을 만들 때 큐브와 같은 식으로 재서(식과 `I_CH`는 [펌웨어 02 10.2](../02-펌웨어/02-큐브.md)) 넘으면 모든 값에 같은 비율을 곱한다. 큐브는 어두운 상태를 모르므로 40 mA만 다시 강제한다. BRIGHT_ACTIVE·IDLE 값 [실측 필요] |
| 설정 밝기 | 패드·큐브 배율 %, 낮추기만(100 % 이하) |
| 패드 감광 | 패드 펌웨어가 한다. `I = 384 × Iq + Σ(r·Ir + g·Ig + b·Ib)/255`가 4.0 A를 넘으면 동적 항에 같은 비율을 곱함, 하한 5 %. 렌더러는 감광 전 값을 보낸다 |
| 감광 보고 | `STATUS.led_scale`(255 = 감광 없음)을 동반 앱에 표시 |
| 지도 전류 | 지도가 늘 켜진 장면이 4.0 A 감광 안에 드는지, 감광 뒤 0.25·0.10 두 밝기가 구분되는지 다시 계산·시험 [미정 C5] |
| PC 무통신 | 패드가 5 s 뒤 대기 패턴(동적 ≤ 0.3 A), 10분 뒤 검정. 렌더러 몫 아님 |
