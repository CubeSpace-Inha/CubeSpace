# 구성

이 문서로 답하는 것: PC 쪽은 어떤 프로세스와 저장소·폴더로 나뉘고 데이터가 어떻게 흐르나, 서버는 무엇을 맡나, 개발 환경은 무엇이고 무엇부터 만드나.

## 1. 프로세스

| 프로세스 | 하는 일 | 통신 |
|---|---|---|
| Electron main | 단일 인스턴스, 트레이 상주. 서비스 모듈을 안에 둔다 [권장안 U-22] | 함수 호출 |
| 렌더러(React) | 동반 앱 본창, 선택 팝업 창. `sandbox: true` | `cube:req`·`cube:state`([PC 내부 3](../03-인터페이스/03-PC-내부.md)) |
| preload | `window.cube.invoke`·`window.cube.onState` 두 함수만 노출 | 같음 |
| 서비스 모듈(main 안) | 게이트웨이, 좌표 추정, cube-events, 배치 엔진, 표시 렌더러, AI 조정, 저장소, 어댑터 클라이언트, 서버 연결. 패드 USB는 `serialport` | 함수 호출 |
| `cube-adapter.exe`(C#) | 상주 자식. 창 열거·적용·판정·감시·앱 실행. 코드는 CubeSpace-Program-Win32 저장소 | stdio NDJSON([PC 내부 2](../03-인터페이스/03-PC-내부.md)) |
| `claude.exe`·`codex.exe`·판정 테스트 | 단계마다 띄우는 자식 | 인자·stdin([PC 내부 4](../03-인터페이스/03-PC-내부.md)) |

- 포트를 열지 않는다. TCP·UDP LISTEN 0, `ws`·`express`·HTTP 서버 의존성 금지(REQ-052) [권장안 U-22]. CubeSpace-Server와는 main이 밖으로만 연결한다(2.1절).
- main 이벤트 루프 p99가 50 ms를 넘으면(S-E2) 서비스를 `utilityProcess.fork()`로 뺀다. 렌더러 쪽 IPC는 그대로다 [실측 필요].
- 창을 닫으면 트레이로 간다(창 제어 계속). 트레이 "종료"만 앱을 끝낸다.
- 종료 순서: 활성 AI 실행이면 확인 창 → CLI·판정 `taskkill /PID <pid> /T /F` → LED_OFF → 어댑터 stdin 닫기 → SQLite 닫기 → `app.quit()`. 상한 3 s(활성 실행이면 +15 s), 넘으면 `app.exit(0)`.
- 모든 자식: `spawn(file, args, { shell: false, windowsHide: true, detached: false })`. 부모 환경을 물려주지 않는다([07 AI 실행](07-AI-실행.md) 4절, [PC 내부 4](../03-인터페이스/03-PC-내부.md) R5).
- 어댑터가 관리자 권한으로 떠서 종료 코드 3이면 창 제어와 AI 시작을 모두 막는다.

## 2. 저장소와 폴더

PC 쪽 코드는 저장소 셋이다. 동반 앱과 PC 서비스는 `CubeSpace-Client`(npm 패키지 하나, 모노레포 아님, pnpm), C# 창 어댑터는 `CubeSpace-Program-Win32`, 서버는 `CubeSpace-Server`(2.1절)다. 저장소 전체 구성과 저장소 사이 약속은 [아키텍처 8](../00-공통/01-아키텍처.md).

CubeSpace-Client:

| 폴더 | 책임 | 기댈 수 있는 곳 |
|---|---|---|
| `src/core/engine/` | 배치 엔진: 분할 트리, 템플릿, 접힘, 밀기, 최소 크기, 점 판정, 패드 지도 | 없음 |
| `src/core/estimate/` | 광학 원시 창 + 보정 → 패드 mm 좌표 | 없음 |
| `src/core/gateway/` | USB 프레임 검증, 순번, 재부팅·세션, 시각 변환 | `estimate` |
| `src/core/cube-events/` | 상태기계 `step(state, event)` | `engine` |
| `src/core/cube-replay/` | 기록 재생·시뮬레이터 | 위 넷 |
| `src/main/` | 창 생성, 보안 골격, IPC 검사, 서비스 셸, 저장소, 표시 렌더러, AI 조정 | `src/core` 전부, `src/shared` |
| `src/main/win32/` | 창 어댑터 클라이언트: 띄우기, 명령 보내기·결과 받기, ping, 재시작([06](06-창-어댑터.md) 1절) | 같음 |
| `src/main/device/` | 패드 USB(`serialport`) | 같음 |
| `src/main/remote/` | CubeSpace-Server 연결. 밖으로만, main에서만 | 같음 |
| `src/shared/` | main ↔ renderer 공용 타입(IPC 계약) | 없음 |
| `src/preload/` | `invoke`·`onState` 두 함수 | `src/shared`만 |
| `src/renderer/` | 동반 앱 화면(React). `index.html`·`main.tsx`·`App.tsx`와 `styles/`·`layout/`·`components/`·`hooks/`·`model/`·`screens/`·`template/` | `src/shared`만 |
| `test/` | `rules.test.ts` 등, `vectors/`(공용 시험 벡터 복사본, [시험 벡터](../03-인터페이스/04-시험-벡터.md)) | |

CubeSpace-Program-Win32: C# `cube-adapter.exe`(창 열거·적용·판정·감시·앱 실행, [06](06-창-어댑터.md)).

빈 폴더를 먼저 만들지 않는다. 파일이 생길 때 폴더도 생긴다.

### 2.1 서버(CubeSpace-Server)

창 제어와 AI 실행은 서버 없이 PC 안에서 끝난다. 서버는 PC 하나로는 할 수 없는 세 가지를 맡는다. 언어·프레임워크·DB·호스팅·계정 방식·착수 시점은 정하지 않았다 [미정 S12].

| 역할 | 하는 일 |
|---|---|
| AI 확장 목록 | AI 모드가 쓰는 skill·plugin·MCP를 모아 두고 판을 올린다. Client는 앱을 새로 내지 않고 목록과 갱신을 받는다 |
| 사용자별 설정·정보 | 계정마다 동반 앱 설정, AI 프리셋, 고른 확장을 보관한다. 다른 PC에서도 이어 쓴다 |
| 세팅 공유·추천 | 사용자가 세팅 묶음을 공개하면 다른 사용자가 별(GitHub star처럼)을 준다. 별 순으로 추천받아 가져다 쓴다 |

```text
CubeSpace-Server/
  src/auth/       계정·로그인
  src/catalog/    AI 확장 항목, 판, 내려받기 정보(SHA-256 포함)
  src/settings/   사용자별 설정·정보
  src/presets/    세팅 묶음 공개·별·추천·가져오기
  src/api/        Client가 부르는 HTTPS API
  db/             스키마·마이그레이션
  test/
  .github/workflows/
```

자료(잠정):

| 표 | 필드 |
|---|---|
| `users` | 계정 |
| `extensions` | `id, kind: skill\|plugin\|mcp, name, version, sha256, source, updated_at` |
| `user_settings` | `user_id, body, ver, updated_at` |
| `presets` | `id, owner, title, body(설정 + 확장 참조), public, stars, updated_at` |
| `stars` | `user_id, preset_id` |

API(잠정 [미정 S12]):

| 역할 | 요청 |
|---|---|
| AI 확장 목록 | `GET /extensions?since=<판>` |
| 사용자 설정 | `GET /me/settings`, `PUT /me/settings` |
| 세팅 공유·추천 | `GET /presets?sort=stars`, `GET /presets/{id}`, `POST /presets`, `POST /presets/{id}/star` |

지킬 것:
- 앱은 포트를 열지 않는다(REQ-052). 서버와는 main이 `src/main/remote/`로 밖으로만 연결하고, 렌더러는 직접 연결하지 않는다(CSP `connect-src 'none'`, [08](08-동반-앱.md) 9절). 화면에 필요한 값은 `cube:state`와 IPC로 받는다([PC 내부 3](../03-인터페이스/03-PC-내부.md)).
- 서버에서 받은 skill·plugin·MCP도 지금 등록 규칙을 그대로 거친다: 로컬 stdio 절대 경로 실행 파일만, 허용 도구 목록, 특권 등록(OS 확인 창)([07](07-AI-실행.md)). 내려받은 파일의 SHA-256이 목록 값과 다르면 버린다.
- 기록에 남기지 않는 것(창 제목·파일 경로·URL·프롬프트·대화·인증 정보, REQ-018)은 서버에도 올리지 않는다. 올리는 항목은 사용자가 보고 고른다.
- 서버가 없거나 끊겨도 창 제어와 AI 실행은 이미 받아 둔 값으로 돈다.
- 공개 세팅이 가리키는 확장 중 악성인 것을 걸러 내는 방법이 필요하다 [미정 S12].

## 3. 순수 모듈 규칙(`src/core`)

`test/rules.test.ts`가 강제한다.

| # | 규칙 |
|---|---|
| ① | import 금지: `electron`, `fs`, `net`, `http`, `https`, `child_process`, `worker_threads`, `serialport`, `node:sqlite`(`node:` 접두 포함) |
| ② | `Date.now()`, `Math.random()`, 인자 없는 `new Date()` 금지. 시각은 입력으로 받고 난수는 씨앗 PRNG(mulberry32 등) |
| ③ | `src/core` 모듈끼리는 2절 표의 허용 모듈만 |
| ④ | `src/core`에서 `src/main`·`src/preload`·`src/renderer` import 금지 |

같은 입력 열이면 같은 출력이어야 한다(REQ-055). 부수 효과는 결과 값(명령 목록)으로 내고 셸이 실행한다.

## 4. 데이터 흐름

```text
패드 USB ─serialport─▶ gateway.onFrame(buf, t_pc_us)
  gateway ─(estimate로 x·y·conf 채움)─▶ 내부 사건: pad.session · obs · cube.evt · cube.link · cube.rebooted
                                          │
어댑터 stdout ─▶ window 사건 ─────────────┤
렌더러 cube:req ─▶ ipc-check ─▶ app 사건 ─┤
                                          ▼
                      셸: JSONL 기록 → cube-events.step(state, event)
                            (step 안에서 engine 순수 함수 호출)
                                          │ {state', commands}
          ┌───────────────┬───────────────┼────────────────┬──────────────┐
          ▼               ▼               ▼                ▼              ▼
   db → SQLite 커밋   apply 묶음 →     표시 명령 →        notice·상태 →   ai_member →
   (실패면 아래 0)    어댑터 stdin     표시 렌더러 →      cube:state     AI 조정 →
                                       LED·ICON → USB     (50 ms 모음)   CLI 자식
```

- 쓰는 쪽은 cube-events 한 곳, 한 루프다. 사건은 들어온 순서대로 하나씩 처리한다.
- 커밋이 실패하면 창·표시·알림 명령을 하나도 내지 않는다(REQ-036). 세부는 [03 상태기계](03-상태기계.md) 3절.
- AI 조정은 `ai_problem`을 표시 렌더러에 보내고, 실행 상태를 `cube:state`에 싣는다.

## 5. 개발 환경과 시작점

코드는 이 문서들을 기준으로 각 저장소에서 처음부터 만든다.

| 항목 | 값 |
|---|---|
| 앱 틀 | Electron 44 + React 19 + TypeScript 6.0, Node 24 |
| 빌드 | electron-vite 5(Vite 7). main·preload·renderer를 한 설정으로, 렌더러 HMR |
| 라우팅 | react-router 8 `BrowserRouter`. `/` 앱, `/template` 부품 카탈로그 |
| 검사·시험 | ESLint 10 + typescript-eslint, `tsc --noEmit`, Vitest 5 + Testing Library(jsdom). `pnpm check` = lint · typecheck · test |
| 패키지 관리자 | pnpm. 의존성은 정확한 판으로 넣는다. Electron은 특히 `^`·`~`를 쓰지 않는다 |
| 실행 환경 | Electron·esbuild는 OS별 바이너리를 받으므로 Windows에서는 `pnpm install`·`pnpm dev`를 Windows PowerShell에서 한다. WSL에서 설치한 `node_modules`는 Windows에서 쓸 수 없다. Mac에서도 순수 모듈·화면 개발은 된다. 창 어댑터·실제 창은 Windows |
| 포장 | 다음 단계. 포장판은 `file://`로 열면 `BrowserRouter` 경로가 동작하지 않으므로 `app://` 프로토콜로 연다([08](08-동반-앱.md) 9절). 포장 도구와 어댑터 exe를 함께 넣는 방법 [미정 S11] |
| 창 어댑터 | CubeSpace-Program-Win32의 `cube-adapter.exe`를 앱이 띄운다. 포장판은 정해 둔 판의 GitHub Release exe를 넣는다. 개발 중 exe 경로를 앱에 알려 주는 방법 [미정 S11] |

`/template`은 개발 전용이다. `import.meta.env.DEV`일 때만 경로를 등록하고 배포 빌드에서는 빠진다. 개발 서버(`http://localhost:5173/template`)라 Electron 없이 브라우저로도 본다.

첫 커밋 완료 조건: `pnpm dev`로 창이 뜨고 "CUBE SPACE"가 보인다, `/template`에 빈 카탈로그 페이지가 있다, `pnpm check` 통과(렌더 시험 1개 포함), `.gitignore`·`README.md`(실행 방법).

알아 둘 제약:
- 개발판 HMR이 CSP의 인라인 스크립트 금지([08](08-동반-앱.md) 9절)에 막히는지 확인한다 [실측 필요].
- SQLite는 내장 `node:sqlite` `DatabaseSync`. Electron 44 main에서 안 되면 `better-sqlite3` + `@electron/rebuild` [실측 필요].

## 6. 구현 순서

앞 단계의 출력이 뒤 단계의 시험 입력이 되는 순서다.

| # | 만들 것 | 끝난 기준 |
|---|---|---|
| 1 | 규격 타입: 내부 사건·어댑터 메시지·IPC 스키마([PC 내부](../03-인터페이스/03-PC-내부.md)) | 타입·ajv 스키마가 시험 벡터를 통과 |
| 2 | `estimate`, `gateway` 코어 | [04 시험 벡터](../03-인터페이스/04-시험-벡터.md) 통과, 시험 벡터 부록의 기준 구현과 좌표 차 ≤ 0.01 mm |
| 3 | `cube-replay` 시뮬레이터(`obs.window` 합성)와 장면 시나리오 파일 | 같은 시나리오 두 번 → 사건 열 바이트 동일 |
| 4 | `engine`: 트리·좌표·템플릿·접힘·밀기·점 판정·패드 지도·최소 크기 | X8-S 불변식 위반 0, X8-G 기대값 일치 |
| 5 | `cube-events`: 존재 사건, 전이, 착지, 내림, 버튼, 끊김·보호, 재평가, AI 후보 | X3-S 시나리오 기대값 일치 |
| 6 | main 서비스 셸: SQLite, 트랜잭션 루프, JSONL 기록, `cube:state` 송신 | 07-T2(재생 결정론, 커밋 실패 주입) |
| 7 | C# 어댑터 M 범위(CubeSpace-Program-Win32) + main 클라이언트(`src/main/win32/`, spawn·ping·재시작) | W-T1·2·4·9·11 |
| 8 | 표시 렌더러(LED 프레임·ICON) | 렌더러 단위 시험 |
| 9 | 화면(시안 기준): 앱 틀·토큰, 홈(패드·세 갈래·6칸·확대·서랍), 창, 선택 팝업, 설정(장치 추가·규칙·프로그램), AI 모드 | UI 상태 함수 시험, UI-S1~S4 |
| 10 | AI 조정(모의 실행기 먼저, 실물 CLI 다음) | AI-M1·M2, AI-T1·T2 |
| 11 | 후순위: 외부 변경(K3), 모양 모드·설정·AI 프리셋(K8), 이력(K7) | 해당 시험 |

- 화면 쪽은 기본 세팅(5절 첫 커밋) → 템플릿(토큰·레이아웃·부품)과 `/template` 카탈로그 → 9번 화면 순서로 간다.
- 서버(2.1절)는 착수 시점이 정해지면 이 표에 단계를 더한다 [미정 S12].
