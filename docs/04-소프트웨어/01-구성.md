## 1. 프로세스

| 프로세스 | 하는 일 | 통신 |
|---|---|---|
| Electron main | 단일 인스턴스, 트레이 상주. 서비스 모듈을 안에 둔다 [권장안 U-22] | 함수 호출 |
| 렌더러(React) | 동반 앱 본창, 선택 팝업 창. `sandbox: true` | `cube:req`·`cube:state`([PC 내부 3](../03-인터페이스/03-PC-내부.md)) |
| preload | `window.cube.invoke`·`window.cube.onState` 두 함수만 노출 | 같음 |
| 서비스 모듈(main 안) | 게이트웨이, 좌표 추정, cube-events, 배치 엔진, 표시 렌더러, AI 조정, 저장소, 어댑터 클라이언트. 패드 USB는 `serialport` | 함수 호출 |
| `cube-adapter.exe`(C#) | 상주 자식. 창 열거·적용·판정·감시·앱 실행 | stdio NDJSON([PC 내부 2](../03-인터페이스/03-PC-내부.md)) |
| `claude.exe`·`codex.exe`·판정 테스트 | 단계마다 띄우는 자식 | 인자·stdin([PC 내부 4](../03-인터페이스/03-PC-내부.md)) |

- 포트를 열지 않는다. TCP·UDP LISTEN 0, `ws`·`express`·HTTP 서버 의존성 금지(REQ-052) [권장안 U-22].
- main 이벤트 루프 p99가 50 ms를 넘으면(S-E2) 서비스를 `utilityProcess.fork()`로 뺀다. 렌더러 쪽 IPC는 그대로다 [실측 필요].
- 창을 닫으면 트레이로 간다(창 제어 계속). 트레이 "종료"만 앱을 끝낸다.
- 종료 순서: 활성 AI 실행이면 확인 창 → CLI·판정 `taskkill /PID <pid> /T /F` → LED_OFF → 어댑터 stdin 닫기 → SQLite 닫기 → `app.quit()`. 상한 3 s(활성 실행이면 +15 s), 넘으면 `app.exit(0)`.
- 모든 자식: `spawn(file, args, { shell: false, windowsHide: true, detached: false })`. 부모 환경을 물려주지 않는다([07 AI 실행](07-AI-실행.md) 4절, [PC 내부 4](../03-인터페이스/03-PC-내부.md) R5).
- 어댑터가 관리자 권한으로 떠서 종료 코드 3이면 창 제어와 AI 시작을 모두 막는다.

## 2. `pc/` 패키지

npm workspaces 루트가 `pc/`다. 순수 패키지는 `private: true`, 이름 `@cube-space/<폴더>`, `exports: "./src/index.ts"`, 빌드 단계 없음(Vite·Vitest가 TS를 직접 읽음).

| 폴더 | 책임 | 기댈 수 있는 패키지 | 담당 |
|---|---|---|---|
| `engine/` | 배치 엔진: 분할 트리, 템플릿, 접힘, 밀기, 최소 크기, 점 판정, 패드 지도 | 없음 | 팀원 2 |
| `estimate/` | 광학 원시 창 + 보정 → 패드 mm 좌표 | 없음 | 팀원 1 |
| `gateway/` | USB 프레임 검증, 순번, 재부팅·세션, 시각 변환 | `estimate` | 팀장 |
| `cube-events/` | 상태기계 `step(state, event)` | `engine` | 팀장 |
| `cube-replay/` | 기록 재생·시뮬레이터 | 위 넷 | 미정 |
| `src/main/` | 보안 골격, IPC 검사, 서비스 셸, 저장소, 표시 렌더러, AI 조정, 어댑터 클라이언트 | 패키지 전부 | 팀장·팀원 2 |
| `src/preload/`, `src/renderer/` | preload, 동반 앱 화면 | 없음(main 타입만) | 팀원 2 |
| `win-adapter/` | C# 어댑터 | 없음 | 팀원 2 |

main 쪽 모듈(표시 렌더러, AI 조정, 저장소, 어댑터 클라이언트)은 착수할 때 `src/main/` 아래나 새 패키지로 둔다. 빈 폴더를 먼저 만들지 않는다.

## 3. 순수 패키지 규칙

`test/rules.test.ts`가 강제한다.

| # | 규칙 |
|---|---|
| ① | import 금지: `electron`, `fs`, `net`, `http`, `https`, `child_process`, `worker_threads`, `serialport`, `node:sqlite`(`node:` 접두 포함) |
| ② | `Date.now()`, `Math.random()`, 인자 없는 `new Date()` 금지. 시각은 입력으로 받고 난수는 씨앗 PRNG(mulberry32 등) |
| ③ | `@cube-space/*`는 2절 표의 허용 패키지만 |
| ④ | 패키지에서 앱(`pc/src/**`) import 금지 |

같은 입력 열이면 같은 출력이어야 한다(REQ-055). 부수 효과는 결과 값(명령 목록)으로 내고 셸이 실행한다.

## 4. 데이터 흐름

```text
패드 USB ─serialport─▶ gateway.onFrame(buf, t_pc_us)
  gateway ─(estimate로 x·y·conf 채움)─▶ 내부 사건: pad.session · obs · cube.evt · cube.link · cube.rebooted
                                          │
어댑터 stdout ─▶ window 사건 ─────────────┤
렌더러 cube:req ─▶ ipc-check ─▶ app 사건 ─┤
                                          ▼
                      셸: JSONL 기록 → cube-events.step(state, event)
                            (step 안에서 engine 순수 함수 호출)
                                          │ {state', commands}
          ┌───────────────┬───────────────┼────────────────┬──────────────┐
          ▼               ▼               ▼                ▼              ▼
   db → SQLite 커밋   apply 묶음 →     표시 명령 →        notice·상태 →   ai_member →
   (실패면 아래 0)    어댑터 stdin     표시 렌더러 →      cube:state     AI 조정 →
                                       LED·ICON → USB     (50 ms 모음)   CLI 자식
```

- 쓰는 쪽은 cube-events 한 곳, 한 루프다. 사건은 들어온 순서대로 하나씩 처리한다.
- 커밋이 실패하면 창·표시·알림 명령을 하나도 내지 않는다(REQ-036). 세부는 [03 상태기계](03-상태기계.md) 3절.
- AI 조정은 `ai_problem`을 표시 렌더러에 보내고, 실행 상태를 `cube:state`에 싣는다.

알아 둘 제약:

- `@vitejs/plugin-react`를 쓰지 않는다(인라인 스크립트가 CSP에 막힘). 렌더러를 고치면 Cmd+R(Ctrl+R)로 새로 고친다.
- Vite 7이 `npm start`·`npm run package`에서 실패하면 Vite 5.4.21 + Vitest 3.2.7로 내린다 [실측 필요].
- SQLite는 내장 `node:sqlite` `DatabaseSync`. Electron 44 main에서 안 되면 `better-sqlite3` + `@electron/rebuild` [실측 필요].

## 6. 구현 순서

앞 단계의 출력이 뒤 단계의 시험 입력이 되는 순서다.

| # | 만들 것 | 끝난 기준 |
|---|---|---|
| 1 | 규격 타입: 내부 사건·어댑터 메시지·IPC 스키마([PC 내부](../03-인터페이스/03-PC-내부.md)) | 타입·ajv 스키마가 시험 벡터를 통과 |
| 2 | `estimate`, `gateway` 코어 | [04 시험 벡터](../03-인터페이스/04-시험-벡터.md) 통과, 시험 벡터 부록의 기준 구현과 좌표 차 ≤ 0.01 mm |
| 3 | `cube-replay` 시뮬레이터(`obs.window` 합성)와 장면 시나리오 파일 | 같은 시나리오 두 번 → 사건 열 바이트 동일 |
| 4 | `engine`: 트리·좌표·템플릿·접힘·밀기·점 판정·패드 지도·최소 크기 | X8-S 불변식 위반 0, X8-G 기대값 일치 |
| 5 | `cube-events`: 존재 사건, 전이, 착지, 내림, 버튼, 끊김·보호, 재평가, AI 후보 | X3-S 시나리오 기대값 일치 |
| 6 | main 서비스 셸: SQLite, 트랜잭션 루프, JSONL 기록, `cube:state` 송신 | 07-T2(재생 결정론, 커밋 실패 주입) |

| 8 | 표시 렌더러(LED 프레임·ICON) | 렌더러 단위 시험 |
| 9 | 화면(시안 기준): 앱 틀·토큰, 홈(패드·세 갈래·6칸·확대·서랍), 창, 선택 팝업, 설정(장치 추가·규칙·프로그램), AI 모드 | UI 상태 함수 시험, UI-S1~S4 |
