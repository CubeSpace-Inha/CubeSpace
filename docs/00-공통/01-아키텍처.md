# 아키텍처

이 문서로 답하는 것: 시스템이 어떤 장치·프로세스로 이뤄지고, 값이 어디서 어디로 흐르며, 판단은 어디서 하나.

관련: [02-용어](02-용어.md) · [03-미정-결정](03-미정-결정.md) · [하드웨어](../01-하드웨어/) · [펌웨어](../02-펌웨어/) · [인터페이스](../03-인터페이스/) · [소프트웨어](../04-소프트웨어/)

상태 표시: `[권장안 U-nn]` 확정 전이지만 이 값으로 구현 · `[미정 …]` 값 없음(잠정이 있으면 그 값으로 구현) · `[실측 필요]` 하드웨어로 정할 값. 목록은 [03-미정-결정](03-미정-결정.md).

## 1. 한 장 그림

```text
[큐브 × 최대 6]  ESP32-S3-Matrix(A1) + 만능기판(A2) + 셀 300 mAh
  S1 접촉 · 버튼 · 배터리 · 도크 감지  →  BLE EVT
  바닥 IR LED: 자기 슬롯(= 등록 번호 0~5)에서만 발광
  8×8 LED: 받은 아이콘만 표시
        │  BLE  패드→큐브 SYNC·CFG·ICON / 큐브→패드 EVT
        ▼
[패드 × 1]  ESP32-S3-Zero
  광센서 7 × 11 = 77(먹스 → ADC) → 슬롯별 차분 → 광학 원시 창(OBS)
  LED 24 × 16 = 384(4체인), 전류 상한 감광
        │  USB CDC  SLIP + CRC-32, 패드→PC 8종 / PC→패드 7종
        ▼
[PC  Windows 11, Electron 동반 앱 한 프로세스]
  gateway ─▶ estimate(좌표 mm) ─▶ cube-events 상태기계 step(state, event) → commands
      ├─▶ engine 배치 ─▶ win-adapter(C#, stdio) ─▶ VS Code·Edge·메모장
      ├─▶ 표시 렌더러 ─▶ LED 프레임·ICON ─▶ 패드 ─▶ 큐브 8×8
      └─▶ AI 조정 ─▶ Claude Code·Codex CLI(단계마다 자식 프로세스)
  동반 앱 화면(renderer) ⇄ main 허용 목록 IPC · SQLite 저장소 · JSONL 기록

[도크 6칸]  충전 전용(포고 2핀, 칸별 PTC, 5 V). 통신 없음. 도크에 넣으면 큐브가 BYE 1을 보내고 꺼짐
```

## 3. PC 프로세스

```text
CUBE SPACE.exe   Electron main(단일 인스턴스, 트레이 상주) + 서비스 모듈(gateway·cube-events·engine·AI 조정·저장소)
 ├─ renderer(sandbox)          main과 IPC만(cube:req, cube:state). 네트워크 포트 없음
 ├─ cube-adapter.exe(C#)       상주 자식, stdio NDJSON
 └─ claude.exe · codex.exe     단계마다 자식, 셸 없음
```

모두 일반 사용자 권한. 서비스는 main 안 모듈이 기본이고, main 이벤트 루프 지연 p99 > 50 ms면 `utilityProcess`로 뺀다.

## 4. 값의 흐름 (큐브를 놓아 창을 묶기까지)

| # | 어디서 | 무엇을 | 규격 |
|---|---|---|---|
| 1 | 패드 → 큐브 | SYNC로 패드 시각을 보내고, 큐브는 그 시각에 맞춰 자기 슬롯에 IR을 켬 | [BLE 2·4절](../03-인터페이스/01-BLE.md) |
| 2 | 큐브 → 패드 | S1 접촉 확정 → EVT CONTACT | [BLE 3절](../03-인터페이스/01-BLE.md) |
| 3 | 패드 | 슬롯마다 센서 차분 → ON_PAD면 3 × 4 창 | [펌웨어 03](../02-펌웨어/03-패드-프레임-광학.md) |
| 4 | 패드 → PC | OBS(프레임마다), EVT 중계, LINK | [USB 2절](../03-인터페이스/02-USB.md) |
| 5 | gateway | 검사·순번·시각 복원 → 내부 사건 | [PC 내부 1절](../03-인터페이스/03-PC-내부.md) |
| 6 | estimate | OBS 창 → 좌표 mm | [소프트웨어 02](../04-소프트웨어/02-게이트웨이-좌표.md) |
| 7 | cube-events | 놓임 에지 + 0.5 s·4 mm 안정 → 놓은 점의 맨 위 안 묶인 창 / 최소화 창 옛 자리 / 없으면 선택 팝업 | [소프트웨어 03](../04-소프트웨어/03-상태기계.md) |
| 8 | engine → 어댑터 | 묶이고 켜진 창만 템플릿 배치, 나머지 등록 창 최소화 | [소프트웨어 04](../04-소프트웨어/04-배치-엔진.md), [06](../04-소프트웨어/06-창-어댑터.md) |
| 9 | 표시 → 패드·큐브 | 창 테두리 + 패드 지도(안 묶인 창) + 문제 표시 → LED 프레임, 앱 아이콘 → ICON | [소프트웨어 05](../04-소프트웨어/05-표시.md), [USB 4절](../03-인터페이스/02-USB.md) |

들면: CONTACT 들림 → T_lift 0.5 s → 창 최소화·배정 풂·지난번 프로그램 기억. 버튼: EVT BTN → `?` 큐브면 팝업.

## 5. 구현 원칙

1. **판단은 PC에만.** 패드·큐브는 원시 값과 사건만 보낸다. 규칙이 바뀌어도 펌웨어는 그대로다.
2. **판정 시각은 패드 시각.** "지금" = 마지막 패드 프레임 머리 `t_us`. PC 시계는 표시·지연 측정에만 쓴다.
3. **순수 모듈.** `gateway`·`estimate`·`cube-events`·`engine`·`cube-replay`는 입출력·`Date.now()`·`Math.random()` 금지, 시각은 입력으로 받는다. 같은 입력이면 같은 결과다. 기록 재생과 시뮬레이터가 같은 코드를 쓴다. 펌웨어도 순수 로직을 하드웨어 층과 나눠 PC에서 시험한다.
4. **만든 쪽이 순번·시각을 붙인다.** 패드 `pad_boot_id·pad_seq·t_us`, 큐브 `cube_boot_id·seq·t_pad32`, PC `pc_boot·pc_seq`.
5. **규격 상수는 한 곳.** 펌웨어 `proto.h`, PC `proto.ts`, 둘은 공용 시험 벡터로 맞춘다([04-시험-벡터](../03-인터페이스/04-시험-벡터.md)).
6. **배정·보호·창 연결을 바꾸는 사건 하나 = SQLite 트랜잭션 하나.**
7. **네트워크 포트 없음.** renderer는 main 허용 목록 IPC만. 특권 동작은 OS 확인 창을 거친다 [권장안 U-22].
8. **창을 활성화하지 않는다.** 예외는 전경 창 최소화와 앱 실행으로 생긴 새 창 [권장안 U-24].
9. **실행 중인 AI는 물리 사건에 닿지 않는다.** 물리 사건은 다음 실행 후보만 바꾼다 [권장안 U-35].
10. **기록에 개인 내용을 남기지 않는다.** 창 제목·경로·URL·프롬프트·인증 정보는 기록하지 않는다.

## 6. 모드

| 모드 | 하는 일 |
|---|---|
| 화면 제어 | 큐브를 창 위에 놓아 묶음, 빈 곳이면 선택 팝업, 밀어서 경계 이동, 들면 최소화, 교체 보호·예비 이관. 모양 모드(저장한 큐브 모양으로 구성 실행) [미정 C2] |
| AI | 큐브 조합으로 에이전트·프로젝트·프롬프트 구성, 동반 앱에서만 시작, 순차 실행 |
| 전환 | 동반 앱 버튼. 떠나는 모드의 배정·AI 실행은 유지, 돌아올 때 한 번 재평가. 패드 테두리 = 화면 제어는 창 테두리, AI는 보라 |

## 7. 실행 환경

| 항목 | 값 |
|---|---|
| OS | Windows 11, 일반 사용자 권한(관리자 실행 금지), 관리자 권한 창은 대상에서 빼고 사유 표시 |
| 모니터 | 주 모니터 1대, 해상도·배율 고정(1080p면 100 %) [권장안 U-26] |
| PC 개발 | 저장소 CubeSpace-Client, npm 패키지 하나, pnpm. Node 24, Electron 44(정확 고정) + React 19 + TypeScript 6.0, electron-vite 5. Windows는 PowerShell에서 설치·실행. Mac에서도 순수 모듈·화면 개발 가능, 창 어댑터·실제 창은 Windows([소프트웨어 01](../04-소프트웨어/01-구성.md) 5절) |
| 창 어댑터 | C#, .NET 10 LTS 자체 포함 단일 파일 [권장안 U-78]. 저장소 CubeSpace-Program-Win32 |
| DB | `node:sqlite`(main), 안 되면 `better-sqlite3` |
| 펌웨어 | Arduino-ESP32 3.3.12 고정 + 라이브러리 재빌드 [권장안 U-06] |

## 8. 저장소

GitHub `CubeSpace-Inha`에 따로 배포되는 것마다 저장소 하나를 둔다. 규격과 공용 시험 벡터는 CubeSpace에서만 만들고, 다른 저장소는 복사해 쓴다(손으로 고치지 않고, CubeSpace에서 다시 만들면 다시 복사하며, 복사할 때 원본 CubeSpace 커밋을 커밋 메시지에 남긴다). 규격을 바꿀 때는 CubeSpace PR이 먼저다.

| 저장소 | 내용 | 배포 |
|---|---|---|
| CubeSpace(이 저장소) | 문서, 규격·공용 시험 벡터, 하드웨어 제작 파일, 광학·측정 도구 | 없음(기준) |
| CubeSpace-Firmware | 큐브·패드 펌웨어, 공용 규격 라이브러리, 호스트 시험([펌웨어 01](../02-펌웨어/01-구조-빌드.md) 2절) | 펌웨어 바이너리 |
| CubeSpace-Client | 동반 앱 + PC 서비스(Electron, npm 패키지 하나). 폴더는 [소프트웨어 01](../04-소프트웨어/01-구성.md) 2절 | 앱 설치본 |
| CubeSpace-Program-Win32 | 창 어댑터 `cube-adapter.exe`(C#, [소프트웨어 06](../04-소프트웨어/06-창-어댑터.md)) | exe(GitHub Release) |
| CubeSpace-Server | AI 확장(skill·plugin·MCP) 목록과 갱신, 사용자별 설정·정보 보관, 세팅 공유·별 추천과 가져오기. 구조는 [소프트웨어 01](../04-소프트웨어/01-구성.md) 2.1절. 착수 시점 [미정 S12] | 서버 |

이 저장소(CubeSpace) 폴더:

| 폴더 | 내용 |
|---|---|
| `docs/` | 이 문서들 |
| `spec/vectors/` | 공용 시험 벡터 생성기 `make_vectors.py`와 결과 `proto_vectors.hex`. 벡터는 여기서만 만든다([시험 벡터](../03-인터페이스/04-시험-벡터.md)) |
| `hardware/` | 큐브·패드 제작 파일과 생성 스크립트 |
| `optics/`, `measure/` | 광학 상수 생성, 측정·교정(Python). 절차는 [02-펌웨어/06-광학-보정](../02-펌웨어/06-광학-보정.md) |

공통 규칙: `main`은 보호하고 PR로만 병합하며 CI 통과가 필수다. 브랜치 이름은 `feat/`·`fix/`·`docs/`. 담당은 팀에서 정하고, 정해지면 저장소마다 `.github/CODEOWNERS`에 넣는다. 배포하는 저장소는 `v0.x.y` 태그와 GitHub Release로 내보낸다. CubeSpace-Client는 포장할 때 정해 둔 판의 CubeSpace-Program-Win32 Release exe를 넣는다.
